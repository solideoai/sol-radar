# /add-review-profile — 커스텀 리뷰 프로필 만들기

프로젝트에 필요한 전문가 리뷰 프로필을 만든다. 검토자 설명과 체크리스트를 인자로 한 번에 넘겨도 되고,
빈손으로 불러 인터뷰로 만들어도 된다. 만들어진 프로필은 `/predeploy-review <이름>`으로 바로 사용할 수 있고,
`.claude/skills/predeploy-review/profiles/<이름>.md` 에 저장된다.

## 전제

- `.claude/skills/predeploy-review/profiles/` 폴더가 있어야 한다 (없으면 생성)

## 인자를 받았을 때 (한 번에 만들기)

인자가 있으면 **거기서 읽어낼 수 있는 항목은 인터뷰로 다시 묻지 않는다.** 아래 절차의 각 단계를
인자로 채우고, **못 채운 것만** 질문한다.

인자 형태 (한 줄 설명 + 체크리스트):

```
/add-review-profile 요금·날짜 표기 검토자.
체크리스트: 통화 기호와 환산 표기 일관성 / 월·연 주기 표기 혼동 /
결제일·D-day 계산 표시 / 조언·추천으로 읽히는 문구 유입 (미션 위반)
```

읽어내는 방법:

| 단계 | 인자에서 | 못 읽으면 |
|---|---|---|
| 1. 어떤 전문가인가 | 첫 문장(`체크리스트:` 앞) | 질문한다 |
| 2. 뭘 보나 | 체크리스트 항목들 | 질문한다 |
| 3. 어떤 파일을 보나 | 체크리스트에서 유추해 **제안**한다 | 제안 후 확인 |
| 4. 핵심 질문 | 체크리스트에서 유추해 **제안**한다 | 제안 후 확인 |
| 5. 체크리스트 | `체크리스트:` 뒤를 `/` 로 나눠 항목화 | 2단계에서 생성 |
| 6. 프로필 이름 | 첫 문장에서 kebab-case로 **제안**한다 | 제안 후 확인 |

제안한 3·4·6은 파일을 만들기 전에 **한 번에 모아** 보여주고 확인을 받는다. 항목마다 따로 묻지 않는다.

> "이렇게 만들겠습니다 — 이름: `pricing-format` / 파일: `web/app/**`, `web/components/**`,
> `web/server/subscription/**` / 핵심 질문: "요금과 날짜가 사용자에게 오해 없이 보이는가?"
> 체크리스트 4항목. 이대로 만들까요?"

체크리스트 항목이 3개 미만이면 인자만으로는 얕다. 2단계 질문을 한 번 더 던져 보완한다.

## 절차 (인자가 없으면 전부 질문한다)

사용자에게 차례로 질문한다:

### 1단계: 어떤 전문가인가?
> "어떤 전문가의 관점으로 리뷰하고 싶나요?"
> 예시: "보안 전문가", "접근성 전문가", "SEO 전문가", "데이터 분석가"

### 2단계: 이 전문가는 뭘 보나?
> "이 전문가가 코드를 볼 때 가장 먼저 확인하는 것은 뭔가요?"
> (3~5개 핵심 관심사를 뽑는다)

### 3단계: 어떤 파일을 봐야 하나?
> "주로 어떤 종류의 파일을 검토해야 할까요?"
> 예시: "서버 코드만", "모든 코드", "프론트엔드만", "설정 파일"
> (파일 패턴으로 변환: `web/server/**`, `web/app/**`, `**/*.tsx` 등)

### 4단계: 핵심 질문
> "이 전문가가 리뷰할 때 머릿속에 두는 한 가지 질문이 있다면?"
> 예시: "이 코드가 공격자에게 악용될 수 있는가?"

### 5단계: 체크리스트
2단계에서 뽑은 관심사를 기반으로 체크리스트를 생성한다.
사용자에게 확인:
> "이런 체크리스트로 리뷰하면 될까요? 추가하거나 빼고 싶은 항목이 있나요?"

### 6단계: 프로필 이름
> "이 프로필의 이름을 정해주세요. (영문 kebab-case, 예: security, seo, data-analyst)"

### 7단계: 파일 생성

`.claude/skills/predeploy-review/profiles/{이름}.md`에 다음 구조로 저장:

```markdown
# {전문가 이름} Review Profile

{한 줄 설명}

## 페르소나

- {전문가 역할 설명}
- {리뷰 접근 방식}

**핵심 질문**: "{4단계에서 정한 질문}"

## 파일 필터

- {3단계에서 정한 패턴들}

## 참조 기준

1. {관련 스킬 문서 또는 spec 파일}

## 체크리스트

{5단계에서 확정된 체크리스트}

## 출력 포맷

`SKILL.md` 의 "프로필 판단 표" — 체크리스트 절마다 한 행.

## 심각도 기준

| 심각도 | 기준 | 예시 |
|---|---|---|
| Critical | ... | ... |
| Warning | ... | ... |
| Suggestion | ... | ... |
```

### 8단계: 안내

> "✅ `{이름}` 리뷰 프로필이 만들어졌습니다!"
> "사용법: `/predeploy-review {이름}`"
> "자동 감지에 추가하려면 `.claude/skills/predeploy-review/SKILL.md` 의 파일 패턴 매핑 표에 추가하세요."

## 주의사항

- 기존 프로필과 이름이 겹치면 덮어쓰기 전에 확인을 묻는다
- 체크리스트는 3~7개 섹션, 각 섹션에 3~5개 항목이 적절하다
- 너무 넓은 범위(모든 것을 다 보는)는 피하고, 특정 관점에 집중하도록 유도한다
