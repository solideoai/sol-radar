# 3분 시연 영상 스토리보드

백업 영상이다([[18-HACKATHON|18 해커톤]] §10). 장면 번호·fixture·기대 수치는 [[19-DEMO-SCENARIO|19 데모 시나리오]] §2 · §4를 그대로 따른다(S-LIVE는 19 §2 표와 §4 S-LIVE). 합계 180초. 화면은 1440px, 줌 100%. 상단바에는 실행 모드·AI 표시가 없다(2026-10-26 제거). 데이터 출처는 상단바 `DEMO` 배지(보는 출처가 demo일 때만)·행 `DEMO` 배지·"(가상)" 제목으로, 분석의 실행 모드·AI는 공고 상세 분석 요약 띠("분석 실행 모드: …"·"AI: …")로 보인다. 분석 컷은 이 띠가, 공고 컷은 `DEMO` 배지가 보여야 하고, 녹화 컷은 자막으로 "녹화"라고 적는다. 공식 발표 시간 제한이 다르면 그 기준에 맞춰 컷 길이를 줄인다.

촬영 환경은 둘 중 하나다. 어느 쪽으로 찍을지는 사용자 확인 전이다.

- 운영(D1, [[16-DECISIONS|ADR-054]]): `https://www.solideos-radar.com`에서 `?origin=demo`로 운영 DB의 DEMO 데이터를 연다. `pnpm demo:reset`은 하지 않는다. 회사 런타임이 실모델이라 FX-02 즉석 분석은 실모델 결과다(운영 기록 2026-10-24 1건: 66점 WATCH). 컷 5·8의 숫자는 찍은 화면 값으로 적는다.
- 격리 로컬 Compose `mock`: mock 골든(FX-01 94·FX-02 72·FX-03 68)이 그대로 나온다.

컷 10(장애 대체 `PARTIAL`)·컷 11(`org-02` 404)은 터미널에서 `ai-gateway` 를 멈추고 토큰으로 `curl` 하므로 격리 로컬에서 찍는다.

상태 값: **촬영 가능**(해당 화면 구현 뒤 촬영) / **녹화 대체**(실시간 대신 같은 입력의 실행 로그 기반 녹화) / **슬라이드**(화면 아님).

## 촬영 규칙

- 일정(제안, 사용자 확인 전): 11-01 리허설 1 뒤 촬영, 11-02 영상 완성([[12-ROADMAP|12 로드맵]] 제안 표). 컷 9(S-LIVE)와 카카오 컷은 첨부 처리 구현·회사 반영(10-30~10-31 제안) 뒤다.
- 격리 로컬 `mock`으로 찍으면 19 §3 S0 사전 준비(seed 재적용, FX-02를 뺀 18건 사전 분석, `org-02` 토큰 발급) 뒤 컷 3 → 11 순서로 한 번에 찍는다. 운영(D1)으로 찍으면 `pnpm demo:reset`을 하지 않고 `?origin=demo`로 연다. 컷 9(S-LIVE)는 따로 찍어 편집한다.
- 분석 컷(5~10)은 분석 요약 띠의 "분석 실행 모드"·"AI"가, 공고 컷(3·4)은 `DEMO` 배지가 프레임 안에 있어야 한다. 없으면 다시 찍는다. 상단바의 실행 모드·AI 표시는 2026-10-26에 없어졌으니 찾지 않는다.
- 녹화 대체 컷은 자막 "녹화(실행 로그 기반)"를 넣고, 발표에서도 실시간이라 말하지 않는다.
- 비밀값·토큰·서비스키가 터미널에 보이면 그 컷은 쓰지 않는다(컷 11의 `curl`은 `$ORG02_TOKEN` 변수로).
- 카카오 실수신 10초 컷은 이 표에 없다. 덱 클립 3 의 카카오 10초(`slides-spec.md` 부록 A)다. 카카오 연결이 0건이라(2026-10-27) 아직 녹화하지 않았다. 첨부 처리 구현 뒤 실공고 S-LIVE와 함께 찍는다(ADR-054). 녹화하지 못하면 이 영상에도 넣지 않는다.
- 원본 영상·편집본은 `docs/evidence/demo-day/`가 아니라 저장소 밖에 두고 경로만 `README.md`에 적는다(용량).
