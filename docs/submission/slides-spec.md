# 발표 덱 제작 명세 (pptx 스킬용)

이 문서 하나로 pptx 스킬을 가진 AI 가 발표 덱을 만든다. 사람이 읽는 대본이 아니라 **슬라이드 제작 명세**다. 2026-10-21 사용자와 합의한 구성(18장 · 20분 · 영상 클립 5개)에 S5 변경 감지 클립 6 과 자격 갭 레이더 클립 7(30초, 슬라이드 6, [[16-DECISIONS|ADR-060]])을 더했다. 2026-10-29 클립 2 에 FX-01 의 저장된 추천 분석 20초를 더했다(30초 → 50초, [[16-DECISIONS|ADR-066]]). 촬영 계획과 3분 백업 영상은 부록 A, 캡처 매핑은 부록 D 다. 수치는 정본([[18-HACKATHON|18 해커톤]] · [[19-DEMO-SCENARIO|19 데모 시나리오]] · [[08-SCORING|08 점수]] · `limitations.md`)과 이 문서 부록 C 출처표에 있는 것만 쓴다.

**일정([[16-DECISIONS|ADR-054]])**: 공식 제출 **2026-11-03(화)**, 발표 **2026-11-04(수)**. 촬영 · 리허설 날짜는 [[12-ROADMAP|12 로드맵]] "남은 일정 제안" 표(사용자 확인 전)다.

**발표 형식과 촬영 경로(ADR-054)**: 본편은 "덱 20분 + 녹화 클립"이다. D1 운영 사이트 `https://www.solideos-radar.com`(시작 URL 에 `?origin=demo`)가 클립 촬영 경로이자 질의응답 때의 라이브다. S5 · S6 은 로컬 Compose 에서 녹화한다. 장면별 촬영 경로는 [[19-DEMO-SCENARIO|19]] §4 표다. 운영에 `pnpm demo:reset` 은 하지 않는다. 운영 회사 프로필은 공개 자료 프로필 revision 5 라 D1 의 DEMO 분석은 모두 보류(`WATCH`)이고 추천(`BID`)은 없다. 사용자는 프로필 · 데이터를 그대로 두고 대본을 바꿨다([[16-DECISIONS|ADR-059]], 2026-10-28). 추천은 슬라이드 6 의 계산 예시(가상 프로필 FX-01 94)로 설명한다. D1 값은 [[19-DEMO-SCENARIO|19]] §2.2 다. FX-02(클립 3)는 [재분석] 뒤 화면 점수로 캡션을 적는다. 예상은 11-03 전에 재분석하면 43 보류, 11-03 이후면 37 보류이고, 두 자격 "보유 가정"을 켜면 비추천(`NO_BID`)이다([미리 계산](../evidence/company-public-profile/20261028/fx-forecast.md)). 이 예상은 fixture 추출로 계산한 값이다. 회사 gateway 가 `req-extract/v0.2` 로 바뀌어([[16-DECISIONS|ADR-064]]) [재분석] 때 Qwen 추출이 새로 돌므로 화면 값으로 다시 확인한다. 운영의 이전 run 66 보류는 가상 프로필 revision 2 기준 분석이다. 골든 **72**는 `mock` 시험 기준이다. 상단바에는 실행 모드 · AI 표시가 없다. 분석의 실행 모드 · AI는 공고 상세 분석 요약 띠("분석 실행 모드: …" · "AI: …")에 보인다.

**발표 조건(2026-10-21 사용자 입력)**: 사내 해커톤. 심사위원은 사장 · 부사장 · CFO 와 AI 심사위원(Claude Fable 5.1). 30분 중 발표 20분, Q&A 10분. 시연은 라이브가 아니라 **녹화 영상을 덱 안에 삽입**한다. AI 심사위원은 덱(또는 서비스)을 **마크다운으로 변환한 파일**로 채점한다. 평가 배점은 실용성 30 · 사업적 창의성 25 · 완성도 25 · 확장 가능성 20([[18-HACKATHON|18]] §4).

> [!warning] 18 §1 과 다른 점
> [[18-HACKATHON|18]] §1 은 심사자를 "사람 5인 + Fable 5.1" 로 적었다. 이 문서는 사용자 입력(사장 · 부사장 · CFO + AI)을 따른다.

### 0.2 AI 심사위원(md 변환) 대응 규칙

md 변환본에는 글만 남는다. 그림 · 영상 · 도형 안 글자는 사라질 수 있다. 그래서:

1. **모든 그림 · 영상 자리에 캡션 글 상자**를 둔다. 캡션은 `[그림]` 또는 `[영상 클립 n · 길이 · 실행 모드]` 로 시작하고, 화면에 보이는 핵심 값(공고 ID · 점수 · 판정 · 배지 문구)을 글로 적는다. 아래 장별 명세의 "캡션" 문구를 그대로 쓴다.
2. 표는 **실제 표 개체**로 만든다. 표를 그림으로 넣지 않는다.
3. 숫자 · 판정 · 모델명은 도형 안이 아니라 **글 상자**에 넣는다. 흐름 띠(도형)에도 같은 내용을 글 한 줄로 아래에 반복한다.
4. 모든 장에 **발표자 노트**를 넣는다. 노트에는 말할 내용 전문, 근거 문서 경로, 출처 URL 을 적는다. md 변환에 노트가 포함되는지는 변환 도구에 따라 다르므로, 채점에 꼭 필요한 근거는 슬라이드 본문의 출처 줄에도 적는다.
5. 금지 표현(0.4)은 노트에도 쓰지 않는다.

### 0.3 상태 값

장별 명세의 "상태" 열은 다음 중 하나다.

- **확정**: 정본에 있고 바뀌지 않는다. 그대로 만든다.
- **재확인**: 발표 전 정본 · 증거에서 값을 다시 확인한다. 값이 바뀌면 바꾼다.
- **측정 뒤 채움**: 실험 · 조사 결과를 기다린다. 값이 없으면 "측정 전" 글자를 남기고 추정값을 넣지 않는다.
- **green 조건**: 촬영 전까지 해당 기능이 main · 운영에서 green 이면 넣고, 아니면 명세에 적힌 **대체 문장**으로 바꾼다.
