# 실험 결과 표 (빈 틀)

세 표 모두 **측정 전. 값 없음.** X1(E0~E3)·X6(E1'·E4)·X2는 발표(2026-11-05) 뒤 진행 예정이라 세 표는 발표 뒤 측정이다([[16-DECISIONS|ADR-067]]). 발표 뒤 날짜는 정하지 않았다. 회사 서버에서 학습·채점을 돌린 기록과 평가 리포트는 없다. 빈 칸에 추정값을 넣지 않는다. 지표 정의는 [[21-MODEL-TRAINING|21 모델 학습]] §4.3, 비교 대상은 §4.2, 임팩트 지표는 [[01-PRD|01 PRD]] 성공 측정이다. 표본이 작으므로 모든 값에 표본 수와 부트스트랩 95% 신뢰구간을 함께 적고, "예비 검증이며 일반화된 성능을 입증하지 않는다"를 표 아래에 남긴다. 결정 모델은 Bosun v3.1 0.6B(`Hanno-Labs/bosun-v3.1-0.6b@5e78a37c`)이고, 추출·설명 모델은 회사 vLLM API(`https://acropolissg.com/vllm/v1`)의 Qwen3.8-Flash-Next(served id `Qwen3.8-Flash-Next-AWQ-INT4`)다([[16-DECISIONS|ADR-034]]). 그래서 기준선은 E1(퇴역한 옛 결정 모델, 미측정)이 아니라 E1'(공개 Bosun zero-shot)이다(21 §4.2).

## (a) E0 · E1' · E2 · E3 비교 (X1)

**측정 전. 값 없음. 발표 뒤 측정(ADR-067).**

사유: E0(규칙만)·E1'·E2·E3 는 측정 전이다. E3 에 필요한 회사 vLLM `prompt_logprobs` 지원도 미확인이다. X1 은 발표 뒤 진행 예정이다([[16-DECISIONS|ADR-067]]).

입력: fixture 20건(`recommendation` · `mandatoryRisk` · `needsHumanReview`, 사람 기대값) + 실제 공고 5건(사람 라벨, 결정 모델 담당 항목). 해커톤 축소판이며 21 §3.5의 test 20 · dev 10 사업 평가셋이 아니다. 골든 94/72/68과 SOL Score 가중치, 결정 모델 미반영 구조는 이 실험으로 바꾸지 않는다.

|---|---|---|---|---|---|---|
| Accuracy (3값) | | | | | | 부트스트랩 |

| 미충족 → 정보부족 혼동률 | | | | | | 부트스트랩 |
| Brier | — | | | | | 부트스트랩 |
| ECE (보정 전) | — | | | | | 부트스트랩 |

| 규칙 결과와 상충(`MODEL_RULE_DISAGREEMENT`) 건수 | — | | | | | — |

채운 뒤 적을 것:
- 데이터셋 버전 · git commit · 질문 세트(`kev-qs/v0.1`·`v0.2`) · state 템플릿 버전 · 모델 식별자(`Hanno-Labs/bosun-v3.1-0.6b@5e78a37c`, Qwen 은 회사 운영이라 `/v1/models`의 `id` 그대로 `Qwen3.8-Flash-Next-AWQ-INT4`) · 온도 · 실행 일시 · 실행 위치(E1'·E4는 회사 서버 안 오프라인 채점 `sol_eval.bosun_score`(B1 구현, 실모델 경로 미검증), 그 밖은 노트북 `sol_eval` → 회사 추론 엔드포인트 HTTPS, [[16-DECISIONS|ADR-025]]·[[21-MODEL-TRAINING|21]] §4.1).
- E3는 회사 vLLM이 `prompt_logprobs`를 주는지 미검증이다. 발표 뒤 실험에서 먼저 확인한다(ADR-067). 판정 규칙과 유지·축소·제외 3안은 [E3 실험 설계](../plans/2026-10-19-e3-experiment-design.md)를 따른다.
- 채우지 못한 칸의 이유.
- E1' 오류 분석 요약(원인 코드 `PARSE` · `EXTRACTION` · `TRANSLATION` · `STATE` · `RULE` · `LABEL` · `MODEL` 건수).
- 결론 후보 셋 중 하나: 결정 모델을 보조 위험 신호 탐지기로 유지 / 역할 축소 / 규칙 + Qwen을 기본 경로로. 근거는 위 표만.

## (c) E1' · E4 비교 (B5, ADR-034)

**측정 전. 값 없음. 발표 뒤 측정(ADR-067).**

사유: E1'·E4 는 측정 전이다. X6(회사 GPU 학습)은 발표 뒤 진행 예정이고(ADR-067), 회사 서버에서 학습·채점을 돌린 기록은 없다. 실행되면 B5(서버 안 오프라인 채점) 결과로 채운다. 실행되지 않으면 아래 "회사가 실행하지 않았으면" 규칙대로 그 사실만 적는다.

입력: 평가셋 v0.1 test 20 사업(21 §3.5, X6a). E1' = 공개 Bosun v3.1 0.6B zero-shot, E4 = Bosun + LoRA(`en`, 공개 LoRA 이어 학습, dev 온도 보정). 데이터셋 버전·commit·질문 세트·state 템플릿·seed 0~5가 같다. 둘 다 회사 서버 안 오프라인 채점(`sol_eval.bosun_score`, 실모델 경로는 미검증)이고 물리 GPU 1에서 순차로 돈다. 학습 절차는 [[22-FINETUNE-RUNBOOK|22 파인튜닝 실행서]] §4.

| 지표 | E1' | E4 | Δ(E4−E1') | 95% CI(짝 부트스트랩) | n |
|---|---|---|---|---|---|
| Macro-F1 (3값) | | | | | |
| 정보부족 → 미충족 혼동률 | | | | | |
| Brier | | | | | |
| ECE (보정 후) | | | | | |
| 지연 p95 (ms, 요청당) | | | | — | |

채운 뒤 적을 것: 체크포인트 id, `training_config.json` 요약, train 레코드 수, 번들 sha256, 학습 GPU(회사가 준 값), 학습 시간, 망각 확인(내부 dev 세트 정확도 변화. dev만으로 Bosun의 일반 Decision 능력이 망각되지 않았다고 주장하지 않는다. DecisionBench 공개 평가 분할은 조건 확인·별도 승인 뒤 보조로만, ADR-034 9번). CI가 0을 포함하면 "차이 없음"으로 적는다. 회사가 실행하지 않았으면 표 대신 그 사실을 적는다.

> 예비 검증이며 일반화된 성능을 입증하지 않는다. 표본이 작아 신뢰구간이 넓다.

## (b) 임팩트 예비 실험 n=3 (X2)

**측정 전. 값 없음. 발표 뒤 측정(ADR-067).**

사유: X2(실제 공고 3건, n=3)는 측정 전이다. "30분 → 10분"은 측정 전 가설로 남는다. X2 는 발표 뒤 진행 예정이다(ADR-067).

절차: 실제 공고 3건 → 사람이 기존 방식으로 분석(참가자격 · 기술 적합도 · 인력 적합성 · 위험 요소 기록, 시간 측정) → 같은 공고를 SOL RADAR로 분석(사람 최종 확인 시간 포함 총 소요 시간) → 누락 · 수정 · 일치율 · 유용성 비교. 검증자가 외부 실무자가 아니면 "개발자 자체 검증"으로 적고 실무자 검증이라 쓰지 않는다.

| 공고 | 검증자 구분(실무자 / 개발자 자체) | 수작업 검토 시간(분) | SOL RADAR 시간(분, 사람 확인 포함) | 필수 항목 누락 수(수작업) | 필수 항목 누락 수(SOL RADAR) | 검토 후 수정 필요 판단 수 | 참가자격 판정 일치율 | 유용성(1~5) |
|---|---|---|---|---|---|---|---|---|
| 1 | | | | | | | | |
| 2 | | | | | | | | |
| 3 | | | | | | | | |
| 평균 | | | | | | | | |
| 중앙값 | | | | | | | | |

채운 뒤 적을 것:
- 공고 3건의 출처(나라장터 공고번호), 실행 모드, 분석 일시.
- 검증자 수와 구분, 검토 경험 유무.
- "30분 → 10분"은 측정 전 가설이었고, 이 표의 값으로 바꾼다. 3건은 예비 검증이며 일반화하지 않는다.

> 예비 검증이며 일반화된 성능을 입증하지 않는다. n=3.
