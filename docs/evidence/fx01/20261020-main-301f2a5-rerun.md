### 실행에서 드러난 시험 결함 2건 — 둘 다 시험 쪽, 고쳤다

1. **S3 strict mode violation**([full-1.txt](main-301f2a5/full-1.txt)): 10열 목록 표의 FX-01 행에 `cell "BID"` 가 둘이다 — "권고"(분석)와 "최종 결정". seed 가 FX-01 에 BID 결정을 미리 넣기 때문이다(`scripts/demo/plan.mjs` `DEMO_REVIEWS`). 머리 글자로 열을 찾는 `cellOf(table, row, header)` 로 바꾸고, `SOL Score`=94·`권고`=BID 에 더해 seed 사전 결정 `최종 결정`=BID 를 S4 의 출발점으로 고정했다.
2. **S4 `response.json()` 30초 timeout**([full-2.txt](main-301f2a5/full-2.txt)): POST 201 은 받았고 화면에는 새 사유와 `마지막 결정: WATCH · 이영업` 이 이미 보였다. 화면(`submit-review.ts`)이 201 본문을 읽지 않아 페이지가 소비하지 않은 fetch 본문을 Playwright 가 끝까지 받지 못한 것이다. 요청 본문(`postDataJSON()`)으로 `{decision:"WATCH", reason}` 을 보고, 저장 값은 GET 목록에서 "before 에 없던 id 정확히 1건" 을 골라 `bidId·decision·reason·systemRecommendationAtDecision:"BID"·disagreementFlag:true` 를 그대로 단언한다. 단언 강도는 같다.
