### 최종 실패 두 건

1. `fx01-flow.spec.ts:87`: SALES 로그인→`/dashboard` 도착→h1 `대시보드`까지 통과. `BID 권고` table의 FX-01 row에 대한 `toHaveCount(1)`은 **실제0**으로 실패했다. 이 실패 뒤의 목록 클릭·상세·자격/점수 화면·서랍·WATCH 저장·이력+1은 실행되지 않았다.
2. `fx01-flow.spec.ts:220`: SALES의 실제 Supabase 로그인 토큰 발급은 성공했다. `GET /api/v1/bids?origin=demo&q=…`의 기대200이 **실제404**여서 실패했다. 같은 조직 자격200 대조군도 아직 도달하지 못했으므로, 뒤의 `viewer@other.invalid` 자격404를 격리 성공으로 보고할 수 없다.

현재 main에 C6의 공고 화면·Route Handler가 없다는 상태와 일치한다. DB에94가 존재한다는 사실과 화면/API에94가 표시된다는 사실을 구분한다.

최종67건의 `did not run`은 `chromium` 실패에 의해 의존 프로젝트 `chromium-write`가 실행되지 않은 결과다. `test.skip`·`.only`·`--no-deps`를 사용하거나 단언을 약화한 결과가 아니다. 이67건과 기존 인증 쓰기/조직·인력 쓰기 시험을 통과로 집계하지 않는다.

## 발견한 앱 계약 불일치 — 수정하지 않음

**Kev 공식 mock 응답과 C4 wire 입력 계약이 어긋나, Gateway가 살아 있어도15건이 AI_UNAVAILABLE/PARTIAL로 저장된다.**

- `fixtures/kev/`에 wire 파일이 있는 FX-01·03·16은 이번 사전 분석에서 COMPLETED다. FX-02는 정본대로 사전 분석에서 제외했다.
- 나머지15건은 Gateway의 공식 mock 경로를 사용한다. `services/ai/src/sol_ai/adapters/mock.py:176`의 fit `ScoreAnswer`는 score·legend만 채우며, `kev_wire.py:168`~172는 없는 probabilities/confidence를 wire에서 생략한다.
- `web/server/scoring/analysis-input.model.ts:293`~297의 `kevMockResponseSchema`는 `responses.fit.probabilities`와 `responses.fit.confidence`를 필수로 요구한다.
- `web/server/analysis/analysis.model.ts:348`~356의 변환이 실패하면 null이고, `analysis.service.ts:155`는 이를 `GATEWAY_DOWN`으로 분류한다. 이후 AI_UNAVAILABLE/PARTIAL이 된다.
- 대표 FX-04의 저장 snapshot·번역으로 실제 `/kev`를 다시 호출했다. **HTTP200·C5 응답 봉투 유효**, wire.fit 키는 score/legend뿐이며 C4 스키마 오류 경로는 위 두 필드였다. FX-01 대조군은 두 필드가 있고 변환에 성공했다([probe](main-c2b12d3/contract-probe.json)). DB 결과를 변경하지 않은 진단이다.

Gateway/C5-B 담당자가 계약을 대조해야 할 항목으로 남긴다. 이 작업에서는 Gateway·분석 코드·fixture·스키마를 수정하거나15건을 완료로 덮어쓰지 않았다.
