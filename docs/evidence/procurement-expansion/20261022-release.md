## 통합 기준

- 최초 구현 baseline `7133636`, 통합 main `3fded9990f56fb311be37ee39a558f5f7cb466f0`.
- main의 private Supabase Storage, Redis HTTPS Gateway, Qwen 실제 served model ID, Vercel 비밀 파일 제외 설정을 보존한다. Storage·조달 전체 migration에서 DB 타입을 다시 생성했다.
- 이전 baseline의 커밋 훅 시험이 Git 환경을 임시 저장소에 상속해 feature HEAD/index를 변경했다. 125개 구현 manifest hash가 그대로임을 확인하고 feature 메타데이터만 원래 기준으로 복구했다. 안전 stash `7e82229106813f3c23e5c0c59b648410e7c2992e`를 보존한 뒤, main에 이미 있는 시험 격리 수정과 통합했다. 훅을 우회하지 않는다.
- Gateway 응답의 신규 출처 계약·정형 서비스 준비 오류를 통합한다. 회사 Docker 빌드는 저장소 문맥에서 registry를 포함하고 실제 standalone의 `web/server.js` 배치를 사용한다.

## 남은 회사 운영 적용

공개 `/health/live`는200, `/health/ready`는503, 회사 `https://acropolissg.com/redis/health`는502다. 회사 SSH 접속 대상/서버 저장소 경로가 없어 **회사 Gateway·Worker는 미적용**이다. 사용자에게 필요한 접속 정보만 요청했으며 운영 승인을 다시 요구하지 않았다. 접근 경로가 제공되면 기존 Redis network/env/Worker를 확인하고 이 릴리스의 준비된 이미지/Worker를 적용·검증한다. Nginx·Redis 재생성·모델 교체·운영 재수집은 수행하지 않았다.

신규6 API는 disabled/NOT_VERIFIED를 유지한다. KEPCO 실제 인증과 나머지5키의 발급/승인·응답 완전성 검증, raw bytes/문서 소비자·파서는 별도 잔여 범위다. 전체 수집 정상이나 신규6 실제 수신 성공으로 보고하지 않는다.

## 복구

DB는 source/revision/분석/결정을 보존하는 추가 구조다. 실패한 파일은 정식 적용기의 트랜잭션으로 롤백하며 이미 성공한 파일 이력은 유지한다. 운영 문제 시 이전 Vercel 배포로 웹을 복귀하고 새 수집은 켜지 않는다. 테이블·기존 데이터·Storage/Redis 볼륨을 삭제하는 복구를 하지 않는다.
