# 공공조달 확장 운영 적용

사용자 추가 지시 “운영 DB 적용, 배포, main 병합, 커밋해”에 따라 진행한다. [10-21 구현 보고](20261021-implementation.md)는 격리 구현 당시 기록이다. 신규 API 활성화·실수집·전수 재수집·모델 교체·Nginx 변경은 이번 운영 적용에 포함하지 않는다.

## 통합 기준

- 최초 구현 baseline `7133636`, 통합 main `3fded9990f56fb311be37ee39a558f5f7cb466f0`.
- main의 private Supabase Storage, Redis HTTPS Gateway, Qwen 실제 served model ID, Vercel 비밀 파일 제외 설정을 보존한다. Storage·조달 전체 migration에서 DB 타입을 다시 생성했다.
- 이전 baseline의 커밋 훅 시험이 Git 환경을 임시 저장소에 상속해 feature HEAD/index를 변경했다. 125개 구현 manifest hash가 그대로임을 확인하고 feature 메타데이터만 원래 기준으로 복구했다. 안전 stash `7e82229106813f3c23e5c0c59b648410e7c2992e`를 보존한 뒤, main에 이미 있는 시험 격리 수정과 통합했다. 훅을 우회하지 않는다.
- Gateway 응답의 신규 출처 계약·정형 서비스 준비 오류를 통합한다. 회사 Docker 빌드는 저장소 문맥에서 registry를 포함하고 실제 standalone의 `web/server.js` 배치를 사용한다.
- 원래 main의 다른 세션 미커밋 인증·데모·문서는 별도 보존한다.

Vercel 대상은 `gwanghui97s-projects/sol-radar` (`prj_i1QhzEUmo98jdaNx829YIVEVTVug`), 도메인 `www.solideos-radar.com`이다. 사전 `/health/live` 200, `/health/ready` 503이고 회사 `acropolissg.com/redis/health`는 502다. - 최신 main의 운영 기록 `2ce06a7`·`3deddff`도 fast-forward로 포함했다.

- 회사 Gateway Docker 이미지 빌드 exit0, 실제 이미지에서 `/app/web/server.js`와 `/app/infra/sources/registry.yaml` 존재 확인. 첫 빌드는 기존 `@test-harness` 파일 누락을 발견해 build stage에 정본 scripts를 포함한 후 통과했다. Docker runtime에는 traced 서버/registry만 복사한다. [빌드 로그](20261022-docker-build.txt).
- 새 standalone 배치로 로컬 실제 Redis/BullMQ 왕복·멱등1건·호출 제한30/5·health200/미인증401·비허용 경로10개 거절을 통과했다. 회사 컨테이너·Redis는 변경하지 않았다. [로컬 smoke](20261022-gateway-smoke.txt).
- Gateway 신규 출처202와 정형 source-readiness503의 안전 전달, G2B 입찰/조달요청 watermark 격리 회귀를 통과했다. 새 G2B 입찰 run에 서비스 태그를 넣고 과거 NULL 서비스 이력도 이어 읽는다.

커밋 SHA, DB 적용, 배포 URL과 후속 관찰은 실행 후 기록한다. 신규6 API는 disabled/NOT_VERIFIED를 유지한다.

## 복구

DB는 source/revision/분석/결정을 보존하는 추가 구조다. 실패한 파일은 정식 적용기의 트랜잭션으로 롤백하며 이미 성공한 파일 이력은 유지한다. 운영 문제 시 이전 Vercel 배포로 웹을 복귀하고 새 수집은 켜지 않는다. 테이블·기존 데이터·Storage/Redis 볼륨을 삭제하는 복구를 하지 않는다.
