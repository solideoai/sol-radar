## 2. 신규 API 6개 공식 명세 확인

2026-10-21 공공데이터포털 공식 서비스 페이지 6개를 열고, HTML에 포함된 `swaggerJson`의 host/path/definitions와 `swaggerOprtinVOs`를 확인했다. 이 공개 문서 조회는 공고 수집 API 실호출이 아니다. 요약 metadata·문서 hash·확인 범위는 [JSON](20261021-api-metadata.json)에 있다. 공개 metadata만 보관했으며 키 값/실제 공고 응답은 없다.

포털은 모든 operation의 경로/응답 정의를 제공하지만 요청 상세 배열은 선택된 operation 하나만 포함했다. 따라서 같은 서비스의 다른 operation까지 필수 파라미터가 같다고 확정하지 않는다. Swagger `host`에 path가 포함된 비표준 구조도 있어 URL은 문서의 host+operation으로 판독했다. HTTPS는 문서상 지원이며 실제 인증/TLS 성공은 별도다.

K-water 입찰/계획의 개발 10,000 표기는 각 공식 페이지에서 확인했다. 문서의 quota는 계약/계정별 실제 승인 한도를 대신하지 않는다. KEPCO 상세 명세는 사용자 제공 입력을 사용했으며 독립적으로 열람하지 못했다. 공개 사이트 열람의 timeout을 API 장애나 인증 실패로 판정하지 않았다.

중요 응답 차이: LH 공고 `bidNum/bidDegree/bidnmKor/tndrdocAcptEndDtm`과 `presmtPrc/fdmtlAmt`, LH 사전규격 `inadvcStddztNm/assignBudgetAmt/opinionRegEndDtm`, K-water 계획 `cntrwkam`의 **백만원** 표기를 확인했다. 금액/마감 의미는 operation·실응답 확인 없이 통일하지 않는다. LH 사전규격 공개 정의에는 안정적인 공고번호가 보이지 않으므로 identity 검증을 활성화 조건으로 둔다.

## 6. 이번 검증의 범위

이번 작업은 문서만 변경하므로 [[17-CLAUDE-IMPLEMENTATION|17]] ADR-046의 문서 전용 정책을 적용했다. `pnpm verify:changed`는 exit0, 당시 변경25개를 문서/증거로 분류해 **코드 검사0개**로 종료했다. 전체 `pnpm verify`·빌드·기능/E2E·신규 API 인증/수집·Storage/GPU·브라우저 시각 검증은 실행하지 않았다. API metadata JSON은 저장소 Prettier로 서식을 맞췄다. Markdown은 저장소 서식 제외 정책을 유지한다.

문서 링크·frontmatter·실재 코드 근거47경로·Phase0~8의6개 필수항목·JSON파싱·문서diff whitespace·기존3파일hash를 [최종 문서 점검](20261021-document-check.json)으로 확인한다. 최초 검사기의3개 지적은 표의 escaped wiki pipe와 “승인 대기” 라벨을 인식하지 못한 검사기 문제였고, 검사기를 고쳐 다시 확인했다. 이후 별도 `web/components/landing/hero.tsx` 변경과 `docs/evidence/database/`가 나타나 전체 작업트리 변경과 이번 작업 소유 파일을 분리했다. 해당 병행 변경은 수정/스테이징/취소하지 않았다. 이 관찰과 최초 점검 결과도 JSON에 남긴다.

마지막 일반 Git 재점검은 `this operation must be run in a work tree`로 실패했다. 읽기 전용 조사에서 `.git/config`의 `core.bare=true`를 확인했으며 이번 작업에서는 Git 설정을 변경하지 않았다. 최종 문서 diff는 명시적 `--work-tree` 경로를 준 읽기 명령으로 검사했다. 일반 Git 명령 실패와 이 대체 읽기 범위를 최종 JSON에 구분해 남겼다.
