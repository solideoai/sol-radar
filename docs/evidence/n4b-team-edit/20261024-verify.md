## 변경

- 마이그레이션 `20261024000400_team_member_edit.sql`
  - `team_members.employment_status`(`ACTIVE`·`LEFT`, 기본 `ACTIVE`)를 더했다.
  - ADMIN 전용 DB 함수 `create_team_member`·`update_team_member`(security definer)를 만들었다. 함수가 조직·역할·팀 부서·직급을 확인하고, `TEAM_MEMBER_CREATE`·`TEAM_MEMBER_UPDATE` 감사를 같은 트랜잭션에 쓴다.
  - 표 직접 쓰기 권한은 열지 않았다.
  - `LEFT` 는 restrictive SELECT 정책으로 숨긴다. 대상은 `team_members`·`team_member_scoring` 이다.
  - `LEFT` 직원의 계정 연결(`user_id`)은 트리거가 `member_left` 로 막는다(81 요청 b).

- API: `POST /api/v1/team-members`, `PATCH /api/v1/team-members/:id`
  - 업무 경로 입구(`businessRoute`)를 거친다. CSRF 를 확인하고 조직은 세션에서 정한다.
  - 본문은 엄격한 zod 스키마로 검사한다. 점수 속성은 받지 않는다.
- 화면 `/people`
  - ADMIN 에게만 "직원 추가" 버튼과 행마다 "… 관리" 메뉴(부서·직급 이동, 퇴사 처리)를 보인다.
  - 진입점은 `web/components/people/team-member-edit-dialog.tsx` 다.
- 분석 입력
  - worker(service role)는 `LEFT` 직원을 가용 인력에서 뺀다(`web/server/analysis/analysis.repo.ts`, M16 ⑤).
