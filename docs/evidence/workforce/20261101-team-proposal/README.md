# 인력 배치 추천 팀 구성 화면 확인 (2026-11-01)

사용자 요청(2026-11-01): 시뮬레이션 조회에서 팀별 후보 0명이 나오는 공고가 없게 어떻게든 팀을 짤 것, 한 팀(예: AX사업본부 AI플랫폼운영팀)만 나오지 않게 PM·개발자·디자이너처럼 여러 팀에서 고를 것, FTE 를 다른 말로 바꿀 것.

> [!warning] 운영 화면이 아니다
> 화면 부품(`WorkforceResults`)을 Vitest 브라우저 모드에서 그린 사진이다. 공고 3건의 추출값(요구 기술·인력 요구조건·제목)은 운영 DB 를 읽기 전용 SELECT 로 확인한 값을 옮겼고, 사람은 저장소 fixture 가상 직원 200명(`fixtures/people/solideo.people.json`)이다. 운영 DB 쓰기·배포·유료 모델 호출은 하지 않았다. 운영 화면은 배포 뒤 따로 본다.

## 원인 (운영 읽기 확인)

| 공고 | 고치기 전 화면 | 원인 |
|---|---|---|
| 2027년~2029년 과천시 지능형교통시스템(ITS) 통합운영 및 유지관리 용역 | 후보 0명 | 요구 기술 ITS·신호제어를 가진 직원이 없고, 인력 요구 역할 "센터운영"·"현장 및 상황근무"가 직무 코드에 대응하지 않는다 |
| 실행형 AI 플랫폼 구축 용역 | AX사업본부 AI플랫폼운영팀 한 팀만 | 역할·기술 요구가 없어 200명 전원이 후보가 되고, 가장 큰 팀의 앞 6명만 보였다 |
| 27년 AI 규제정보시스템 운영 및 유지관리 사업 | 후보 0명 | 요구 기술 문구와 맞는 직원이 없다 |

## 바꾼 것

- 공고마다 **추천 팀 구성**을 만든다(`web/server/workforce/team-proposal.ts::proposeTeam`). 인력 요구조건이 있으면 그 역할대로, 없으면 필요 인력(3~12자리)에 맞춰 PM → 요구 기술·제목이 말하는 직무 → 개발자·디자이너·PL·QA… 순으로 자리를 나눈다.
- 자리마다 같은 직무 직원을 먼저 찾고, 없으면 다른 직무에서 대체해 팀이 비지 않게 한다. 고르는 순서는 투입 가능 → 요구 기술 일치 → 기간이 겹치는 앞 공고에 안 낸 사람 → 아직 없는 팀 → 요구 등급 → PM·PL 은 높은 등급 → 투입 가능 많은 순이다.
- "팀별 지원 요청" 표는 추천 팀 구성원을 소속 팀별로 묶는다(`team-plan.ts::teamPlanOf`).
- 화면에서 FTE 를 "N명분"·"투입 가능 N%"로 바꾸고 "1명분은 한 사람이 그 기간 업무 시간을 전부 쓰는 양" 설명을 붙였다. 다른 화면(인물 서랍·회사 역량)의 FTE 표기는 이번에 바꾸지 않았다.
- 확정 배정이 아닌 후보라고 적고, 저장하지 않는다(ADR-021).

## 남은 것

- 직무 대응이 없는 역할(ITS 센터운영 등)의 대체 인원은 직무가 임의라 사람이 확인해야 한다. 화면에 "직무 대응 없음 · 다른 직무에서 대체"로 적는다.
- 유효한 분석이 없는 공고는 지금처럼 "분석 필요"로 두고 팀을 짜지 않는다(현재 명부로 분석 당시 인력을 대신하지 않는다).
