# 발표 화면 다듬기 (2026-11-03)

사용자 요청: 기존 로직·API·DB·인증·라우팅을 바꾸지 않고 발표에 중요한 화면부터 읽기 쉽게 다듬는다. 판정(추천·보류·비추천)이 먼저 읽히게, 색·간격·표를 일관되게. 브랜치 `feat/ui-polish`(origin/main `b1bc414c`에서 시작), 운영 반영 전. 화면 계약은 [[06-UI-UX|06 화면]] §3.2·§3.5·대시보드·§5.4·§5.5에 반영했다.

## 바꾼 것

| 화면 | 문제(수정 전) | 수정 |
|---|---|---|
| `/bids` 표 | 판정 열(SOL Score·권고)이 마감 뒤에 있어 1280px 첫 화면에서 권고 열이 잘림. 권고가 12px 글자라 행마다 훑어 읽기 어려움 | 열 순서를 출처·기관·단계·제목·**SOL Score·권고**·분야·예산·마감·분석 상태·최종 결정으로. 점수는 `type-heading` 오른쪽 정렬, 권고는 강조 배지(상태 색 1px 테두리·글자·아이콘, 바탕 없음). 열 폭 합 1,184px 그대로 |
| `/bids` 표 둘레 | "DEMO · 예시 공고 기준"·건수 줄이 따로 떨어져 빈 줄이 많음. 미확인 출처 칸이 진한 글자 빈 상자라 버튼처럼 보임 | 건수 줄과 데모 안내를 한 줄 양 끝으로. 미확인 출처는 회색 글자 |
| `/bids` 768px | 표 칸의 스크린리더 글자(absolute)가 스크롤 칸 밖 조상 기준이라 페이지가 441px 가로로 넘침(열 순서 변경 전에도 같은 구조) | 스크롤 칸에 `relative` |
| `/bids` 모바일 카드 | 예산·마감이 판정보다 먼저 | SOL Score·권고 줄을 먼저 |
| `/bids/[id]` | 오른쪽 레일 맨 위가 입찰 프로젝트 칸이라 판정이 아래로 밀림. 권고가 색 글자뿐 | 결정 패널(권고·SOL Score)을 레일 맨 위로, 권고를 큰 강조 배지로. 긴 공고명 제목은 `text-balance` |
| `/dashboard` | "우선 검토할 입찰"의 권고가 작은 글자. 390px에서 출처 칸이 제목 폭을 잡아먹음 | 권고 강조 배지(같은 부품). 640px 미만에서 출처를 제목 위 한 줄로 |

새 토큰·새 부품은 없다. 기존 `StatusBadge`에 권고 전용 `emphasis` 모양 하나를 더했다. 데이터·문구·링크·`aria-*`·필터 구성(10-30 사용자 결정으로 모두 노출)은 그대로다.

## 검증

- `pnpm verify:changed`: 통과(서식·타입·린트·웹 147파일 1,222시험·lodestar·토큰·색).
- 관련 Chromium 브라우저 시험 8파일 94개: 첫 실행에서 `procurement.browser.test.tsx` 1개가 표 칸 번호(`td[7]` = SOL Score)로 단언해 열 순서 변경 뒤 실패했다. 단언 값·개수는 그대로 두고 칸 번호만 새 순서로 고친 뒤 그 파일 6개 통과, 나머지 7파일 88개는 첫 실행에서 통과.
- 로그인 E2E(`web/e2e-auth`)는 실행하지 않았다. 표 칸을 머리 글자로 찾고(`cellOf`·`tableRows`) 레일을 역할 이름으로 찾아 순서 변경에 기대지 않는 것만 코드로 확인했다.
- 전체 `pnpm verify`: exit 0. 루트 324시험, 웹 147파일 1,222시험, `next build`, AI 290시험, 결정 서버 57시험([로그](verify-full.log)).

## 하지 않은 것

- 운영 반영(main push = Vercel 배포)은 하지 않았다. 오늘은 화면 동결일이고 촬영 화면이 바뀌므로 반영 여부는 사람이 정한다.
- 공고 상세 모바일에서 결정 패널은 여전히 본문 아래다(한 열 배치 순서는 그대로).
- `bid-detail-view.tsx`는 수정 전부터 800줄을 넘는다. 이번에 나누지 않았다.
