# GitHub E2E·필수 검사 실패 수정

## 원인

- [Storage 전환 PR 실행 39612684098](https://github.com/gwanghui97/sol-radar/actions/runs/39612684098): 프로덕션 서버의 instrumentation이 `SOL_DEPLOYMENT_ROLE 설정이 필요합니다`로 실패했다. Playwright가 시작한 서버에 역할이 없어 준비 대기가 60초 뒤 종료됐다.
- [main 실행 39610798790](https://github.com/gwanghui97/sol-radar/actions/runs/39610798790): `7133636`에서 승인된 솔리데오 제목으로 변경했지만 `landing.spec.ts`는 이전의 `우리 회사가 검토할 사업부터.`를 기대했다. 실제 제목은 `수많은 공고 속,솔리데오가 검토할 사업부터`다.
- `required`의 `project: failure`는 위 `verify-web` 실패를 집계한 결과다. 다른 원인의 독립 실패가 아니다.

## 변경

Playwright의 공개·인증·업무·수집 설정에서 `webServer.env.SOL_DEPLOYMENT_ROLE`을 `standalone`으로 명시했다. 테스트가 띄우는 로컬 서버가 화면과 API를 함께 제공하도록 한다. 실제 배포는 기존 런타임 역할 검증을 따른다.

제목 E2E는 솔리데오 고정 요구와 현재 승인된 문구에 맞추고, 시작과 끝을 고정한 정규식으로 전체 제목을 검사한다.

## 검증

기준은 `feat/supabase-storage`의 `55e7e9b`와 이번 수정이다.

1. 수정 전 제목 E2E를 `SOL_DEPLOYMENT_ROLE=standalone`으로 실행해 GitHub와 동일한 기대값 불일치 재현: 1 failed.
2. 수정 후 외부 `SOL_DEPLOYMENT_ROLE`을 제거하고 `CI=1`, CI와 같은 공개 Supabase placeholder, `E2E_PORT=3317`로 `pnpm -C web test:e2e` 실행: **Playwright 45 passed + 브라우저 48 passed**, exit 0. 프로덕션 빌드는 기준 커밋의 전체 verify에서 만든 빌드를 재사용했다.
3. `pnpm verify:changed`: 웹 서식·타입·린트·가드·단위 323개·구조·토큰·색 검사 **PASS**, exit 0.

인증·업무·수집 전용 E2E 실행과 DB seed/reset은 이번 검증 범위에 포함하지 않는다. CI에서 새 빌드를 포함한 결과는 이 변경의 GitHub Actions 실행으로 확인한다.
