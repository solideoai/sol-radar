# P1 문서 큐 복구·마지막 업무 ADMIN 보호

2026-10-19, `fix/p1-docs-reconcile-last-admin`. 시작점 `cfe8f0a`에서 작업을 격리한 뒤 사용자가 지정한 main `4895010`을 fast-forward로 반영했다. 수집 담당의 `closeAll`과 worker 등록·실패 정리 구조를 보존했다. main에는 커밋·병합하지 않았다.

## 변경

- 수집 run 완료와 별개로 DB의 `bid_documents.download_status=PENDING`을 시작 시 및 60초마다 조회한다. 회차당 100행을 UUID 커서로 순회하며 기존 `documents-<revisionId>` job ID로 큐에 넣는다. Redis 등록 실패·worker 재시작 뒤에도 DB에 남은 작업을 다시 등록한다. 중복 회차 실행을 막고 종료 시 진행 중인 복구를 기다린 뒤 ingest·documents 큐를 닫는다.
- 조정 세션(e8)이 배정한 `20261019000014_protect_last_sol_admin.sql`에서 마지막 업무 ADMIN의 강등·멤버 삭제를 거절한다. 조직 행 잠금으로 동시 변경을 직렬화하고 계정 탈퇴도 JWT를 비우기 전에 검사한다. 기존 owner·정지 계정 보호를 유지하며, 혼자인 조직 삭제와 JWT 없는 관리 작업·service_role의 관리 경로를 보존한다.
- 계정 탈퇴는 `auth.users → profiles → organizations` 순서로 잠근다. 검사 도중 새 조직의 ADMIN 초대를 수락하거나 검사 이후 멤버십을 삽입하는 동시성 경로도 보호한다. API `DELETE /api/users/me`는 마지막 ADMIN 탈퇴에 409 `sole_admin`을 반환하고 기존 설정 화면에 인계 안내를 표시한다.
- `pnpm db:types`로 다시 생성했다. 공개 함수 서명·표 모양이 같아 생성물의 바이트 변경은 없다.

## 재현 및 검증

새 회귀 테스트는 수정 전 실패를 확인한 뒤 구현했다. [ADMIN 보호 RED](20261019-p1-admin-red.txt), [문서 복구 RED](20261019-p1-documents-red.txt), [오류 전달 RED](20261019-p1-errors-red.txt), [실제 PostgreSQL 동시성 RED](20261019-p1-concurrency-red.txt).

[통합 초점 검증](20261019-p1-targeted-green.txt)은 실제 PostgreSQL 동시성 2건, 웹 6파일 111건, 새 PGlite ADMIN 보호 8건을 통과했다. PostgreSQL 검증은 캐시된 `postgres:17.11-alpine` 이미지의 고유 임시 컨테이너와 임의 loopback 포트만 사용하고 종료 시 제거했다. 재실행 명령은 `node scripts/p1-last-admin-concurrency.mjs`이며 Docker와 해당 캐시 이미지가 필요하다. 공유 DB·환경 파일은 사용하지 않는다.

첫 전체 검증에서 기존 owner 테스트 2개의 ADMIN 인계 없는 fixture가 새 보호에 걸렸다. 다른 owner에게 ADMIN도 부여하도록 입력을 수정했고, 기존 owner 오류·계정 삭제 결과에 대한 단언은 유지했다. 독립 코드 리뷰에서 발견한 계정 삭제·초대 수락 경쟁도 실제 PostgreSQL로 재현하고 잠금 수정 후 통과했다. 최종 리뷰에 남은 Important/Critical 제품 코드 지적은 없다.

최종 `pnpm verify`는 exit 0: 루트 647건·웹 139파일 4,884건·AI 894건과 프로덕션 빌드, 서식·타입·린트·구조·토큰·색·DB 타입 검사를 모두 통과했다. AI 의존성의 기존 Starlette 사용 중단 예정 경고 1건은 남는다. [전체 로그](20261019-p1-verify.txt)는 수정한 기존 owner 테스트 2건의 사전 확인과 이어진 전체 검증을 담는다. [첫 전체 검증 실패 원본](20261019-p1-verify-fixture-red.txt)은 루트 645 PASS / 2 FAIL이며 두 fixture의 ADMIN 인계 조건만 보완했다.

무거운 검증은 사용자가 지정한 `verify-slot.sh`로 감쌌다. 정상 커밋 게이트는 공용 스크립트의 “커밋 게이트(.husky)는 감싸지 않는다” 안내에 따라 일반 `git commit`으로 실행한다.

커밋에 보존한 텍스트 로그는 줄바꿈·줄 끝 공백·파일 끝 빈 줄만 정규화했다. 실행 결과와 오류 내용은 유지했다.
