# live 카카오 발송 수단·가입 약관 동의 저장 수정 검증

2026-10-27 전체 점검의 중간 등급 두 건. 브랜치 `fix/live-guards`(기준 main `43e4e024`), 미커밋 상태에서 검증했다.

## 1. live 에서 카카오 발송이 조용히 mock 이 되던 문제

- `NOTIFY_KAKAO_PROVIDER` 가 비고 `SOL_RUN_MODE=live` 이면 `readKakaoSettings` 가 `disabled` 를 고른다. 던지지 않으므로 worker 기동은 그대로다.
- `createKakaoChannel(disabled)` 는 `undefined` 다. 알림 회차(`processOutboxBatch`)의 기존 `KAKAO_CHANNEL_NOT_CONFIGURED` 경로로 카카오 이벤트가 재시도(5·10·20·40초)되고 다섯 번째에 DEAD 가 된다. 저장소·발송 수단을 부르지 않으므로 `kakao_send_claims`·KAKAO `notifications` 행·`kakao_notify_links.last_result` 가 생기지 않는다. 인앱 알림은 영향이 없다.
- 기동 때 1단계에서 경고 한 줄(`notify.kakao.disabled`)을 남긴다. live 에서 `mock` 을 직접 적으면 받고 `notify.kakao.mock_in_live` 경고를 남긴다. 키 이름만 싣고 값은 싣지 않는다.
- mock·fixture 실행 모드(빈 값 포함)는 바뀌지 않는다.

## 2. 가입 약관 동의를 저장하지 않던 문제

- 새 마이그레이션 `20261027000600_signup_consents.sql`: `public.user_consents`(사람 하나에 한 행, 필수 셋 시각 not null, 마케팅 시각 nullable). RLS 켬, authenticated 는 본인 행 select 만, service_role 은 select 만. 넣기는 가입 트리거(security definer)만 한다.
- `handle_new_user` 를 다시 만들었다. 부서·직급 키가 있는 가입(이메일 가입)은 `consents.terms`·`privacy`·`age_over_14` 가 모두 JSON true 가 아니면 `consent_required`(22023)로 거절한다. 시각은 트리거의 `now()` 다.
- 가입 화면은 `options.data.consents` 로 네 항목을 보낸다. 운영자·시험 스크립트(`scripts/demo/plan.mjs`·`scripts/db-seed.mjs`·`web/e2e-auth/support/seed.ts`·`people-fixtures.ts`)도 같은 키를 싣는다.
