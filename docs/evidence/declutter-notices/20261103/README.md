# 업무 화면 겹친 고지·내부 숫자·운영 정보·DEMO 중복 빼기 (2026-11-03)

사용자 지시: "4·5·6번도 이어서 해". 같은 날 전 화면 검토 보고(6묶음)의 남은 묶음이다. 4번은 반복 고지·내부 숫자, 5번은 일반 화면의 운영자 정보, 6번은 DEMO 중복이다. 1·2·3번은 [[16-DECISIONS|ADR-080]]([검증 기록](../../plain-screen-text/20261103/README.md))이다. 결정은 [[16-DECISIONS|ADR-081]], 화면 계약은 [[06-UI-UX|06 화면]] "화면에서 뺀 겹친 고지·운영 정보"다. 브랜치 `feat/declutter-notices`(origin/main `e43a62f2`에서 시작), 커밋 `b32a0728`·`215e2dc7`, 운영 반영 전.

## 바꾼 것

| 묶음 | 화면 | 수정 |
|---|---|---|
| 반복 고지 | 공고 상세 결정 모델 구역 | 아래 고지 줄(`kev-qs/v0.1` 블록 3줄·`kev-qs/v0.2` "결정 모델 확률은 …")을 지웠다. 확률 고지는 분포 제목 "모델 선택지 신뢰 분포 (충족·수주 확률 아님)" 한 곳이다 |
| | 공고 상세 추천 분석 구역 | 제목 아래 "판정은 규칙 엔진이 하고, 최종 참여 결정은 사람이 합니다."를 지웠다. 팝업 머리에는 남겼다 |
| | 공고 상세 점수 분해 | 저장 설명 끝의 "최종 참여 결정은 사람이 합니다."를 화면에서만 뗀다. 사람 결정 고지는 결정 패널 한 줄이다 |
| 내부 숫자 | 결정 모델 구역 | 신호 값과 기준값("0.05 · 기준 0.70 이상" 두 줄), 적합도 의견·기술 적합·실적 연관 의견(n/5), 보정 상태를 지웠다. 신호가 기준 이상이면 "필수자격 위험 신호가 기준 이상입니다"·"사람 검토가 필요하다는 신호가 기준 이상입니다"만 보인다 |
| | 결정 패널·점수 분해·근거 서랍·단계 이력 | "규칙 + 결정 모델 참고"·"규칙만" 줄, "합계 94.0 → SOL Score 94 (반올림)" 줄, "원문 대조 검증 통과", 거치지 않은 단계의 "—"를 지웠다 |
| Mock 고지 | 공고 상세 | 분석 요약 띠가 "Mock 응답(데모 데이터)"를 보이면 결정 모델 구역과 추천 분석 구역 작성 줄은 되풀이하지 않는다(상세 한 화면에 3번 → 1번). 결정 모델만 mock이면 결정 모델 구역이 밝힌다. 팝업은 늘 밝힌다 |
| 운영자 정보 | 대시보드 | 숫자 띠·수집 지표 설명을 쉬운 말로("진행 중인 입찰공고"·"아직 분석하지 않은 공고"·"IT 입찰공고"·"프로젝트 보기"), "별도 집계" 삭제. "수집 소스 상태"는 ADMIN에게만 |
| | 자격 갭 레이더·발주 현황 | 범위 문구 "공고에 적힌 면허 제한·참가 가능 지역만으로 먼저 골랐습니다. 제안요청서 첨부의 자격 요건은 반영하지 않았습니다.", 출처 문구 "나라장터 입찰공고 기준 · 낙찰·계약·발주계획·사전규격 미포함". "취소 0건 제외"·"예산 미확인 0건 제외"는 두지 않는다 |
| | 조직·인력 | 명부 표의 "점수 계산 대상" 열을 뺐다. 거르기·머리 요약·인물 서랍은 그대로 |
| DEMO 중복 | 공고 목록·관심 공고·대시보드 우선 검토 줄 | 출처를 모르는 데모 행은 출처 칸에 DEMO 하나("미확인" 칩 없음). 출처가 있는 데모 행은 출처 배지 + 제목 쪽 DEMO. 같은 부품 `web/components/work/opportunity-source-cell.tsx` |
| | 공고 목록·관심 공고 | 건수 줄의 "DEMO · 예시 공고 기준"을 지웠다. 대시보드의 같은 줄은 남겼다 |

남긴 것: 영역 이름 "모델 참고 지표 (점수 미반영)", 분포 제목, 결정 패널 SOL Score 고지, 팝업 고지, DEMO 배지, Mock 고지 한 번([[09-SECURITY|09 보안]] 원칙 2~5·7). 저장 설명 문장 안의 "결정 모델 분포는 모델 참고 지표이며 점수에 반영하지 않습니다.", 수행 리스크 막대 옆 0.xx 값, 사업기회 연결 후보 안내, 데이터 수집 관리 화면. 데이터·API·DB·권한·라우팅은 그대로다.
