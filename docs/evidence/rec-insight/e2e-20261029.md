브라우저: `web/node_modules/@playwright/test` 의 chromium 으로 일회용 스크립트를 돌렸다(scratchpad). 로그인 → 공고 상세(`/bids/<id>?origin=demo`) 순서다. DB 확인은 격리 DB 컨테이너의 `psql` 로 읽었다. e 의 행 넣기만 SQL 쓰기다.

## 참고

1. gateway mock 의 `/insight` 응답은 `refs: []` 이고 항목의 `refIds` 도 비어 있다. 그래서 근거 칩과 인용 펼침은 실제 앱에서 보이지 않았다. 이 부분은 부품 브라우저 시험(`recommendation-insight.browser.test.tsx`)만 본다. 실모델 연결 뒤 확인이 남는다.
2. mock 응답 본문은 규칙 결과 문장이다("SOL Score 94점. 규칙 엔진이 판정하고 Bosun 참고 지표를 함께 봤습니다.", "유사 수행 실적: 25점 중 25점." 등). source 는 MODEL 이다.
3. `/health/ready` 는 `storage·ai unavailable` 로 503 을 낸다. 이 두 값은 전체 Worker(`worker/main.ts`)가 Redis 에 올리는 의존성 보고에서 오는데, `analysis-only-main.ts` 는 그 보고를 올리지 않는다. 추천 분석 흐름과는 상관없다.
4. 이 확인의 mock 모델 이름은 `fixture` 다. 45 가 gateway mock 값을 `mock` 으로 바꾸는 중이고(09), 패널 상수는 그 뒤 후속 커밋에서 맞춘다.
