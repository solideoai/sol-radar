1. 같은 파일에 같은 크기 차이(−25바이트)의 변형을 같은 1초 안에 연달아 넣으면(M33 → M34, citation.py) Python 이 앞 변형의 .pyc 를 그대로 써서 M34 가 한 번 초록불로 보였다. 시험 빈틈이 아니라 변형 도구의 캐시 문제라 PYTHONPYCACHEPREFIX 를 변형마다 따로 두고 40건 전부 다시 돌렸다. 위 표가 그 결과다.
2. M40(/explain 숫자 검사 끔)은 처음 실행(보강 전)에 초록불이었다(pytest 통과, test_explain.py 18 passed) — 빈틈. 정상 공개 요청으로는 템플릿이 입력 밖 숫자를 만들 수 없어서다. 보강 시험 `test_sentence_with_number_outside_input_is_replaced` 를 test_explain.py 에 더했다(내부 이름 sol_ai.explain.template_sentences 를 바꿔치기해 입력 밖 숫자 문장을 넣고 HTTP 응답을 본다). 보강 뒤 M40 은 pytest-FAIL. 이 보강 시험은 아직 커밋되지 않았다.
3. M01~M29 는 시험 작성 단계에서 scratchpad 참조 구현으로 뒤집었던 조건을 실제 코드의 해당 위치에서 다시 뒤집은 것이다. M30·M31 은 이번 보완(KNOWN 이 아닌 필드 value=null, 출력 탐지는 지우기 전 값), M17·M18 은 KEV_ENABLED=false 경로(kevEnabled 판정), M32~M40 은 추가 변형이다.

## 4. 다루지 못한 것
- Kev state 문자열: 응답에 나오지 않는다(stateHash 만). 한글 0자·규칙 결과 0개는 "한글 값·규칙 결과 키만 바꿔도 stateHash 가 같다"와 대조군 "영어·숫자 값을 바꾸면 달라진다"로 간접 확인했다. 영어 템플릿 줄의 정확한 표기, (unknown)·(conflicted) 표기, 6,000 토큰 자르기, translations 사용(fieldPath 형식 미정)은 시험으로 고정하지 않았다.
- /explain 숫자 검사: 공개 요청으로는 유발할 수 없어 내부 함수 이름에 기대는 시험 1개로 보강했다(위 비고 2). 이름이 바뀌면 그 시험은 AttributeError 로 실패한다.
- Kev wire 요청 본문(state·model·questions)은 mock 이 보내지 않아 관찰할 수 없다.
- 로그에 원문·키·PII 가 없는지, 모드 분기가 어댑터 팩토리 한 곳에만 있는지(구조), 프로세스 사이의 결정성은 시험하지 않았다.
- local·hosted 실모델 경로: 이번 단계 범위 밖이고 사용자 승인이 필요하다. hosted 미승인 기동 거부는 기존 tests/test_startup.py 가 본다.
- /parse 실제 파서: 어댑터가 아직 없어 UNSUPPORTED·PARSER_NOT_CONFIGURED 경로만 본다.
- G6 의 worker 쪽 결과(PARTIAL·RULES_ONLY 저장, 배너)는 web/server 시험(test-server) 몫이다. 여기서는 gateway 응답만 본다.
