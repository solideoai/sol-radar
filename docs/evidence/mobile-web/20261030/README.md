# 모바일 웹 기본 대응

2026-10-30 사용자가 승인한 구성안과 [[16-DECISIONS|ADR-072]]에 따라 반응형 웹을 반영했다. 네이티브 앱과 결제 제외는 유지한다. 데스크톱 1280px 이상은 기존 배치를 유지하고, 작은 폭은 메뉴 서랍·한 열 본문·2열 지표·공고 요약 목록으로 재배치한다.

## 반영 범위

- 랜딩: 간소한 헤더와 메뉴 서랍, 세로 설명과 읽을 수 있는 분석 예시, 비교표 내부 스크롤. 모바일 미지원 안내 제거.
- 공통 틀: 모바일 현재 화면 표시, 주요 터치 영역 44px, 좁은 화면의 표·팝업·쪽 이동 넘침 방지.
- 공고·관심 목록: 요약 목록에서 출처·DEMO·정정·기관·금액·마감·0점·상충·초기 단계·분석 상태·최종 결정·관심 동작을 보존. 상세 링크의 기존 목록 쿼리 유지.
- 필터: 검색은 본문, 세부 조건은 서랍. 적용 전 임시 선택과 취소·적용, 적용 조건 해제. 상태 조건은 한 묶음으로 해제하며 긴 기관명은 줄바꿈.
- 업무 화면: 상세·변경 이력·프로젝트 보조 패널을 본문으로 이동. 대시보드·갭·시장 지표 2열, 인력 배치 카드와 조직도 재배치, 회사·분석·인력 표의 내부 스크롤. 로딩 화면에도 같은 열 규칙 적용.
- 일정·서랍: 모바일은 선택 월 전체 일정 목록을 사용한다. 14일 범위 밖 월말 일정도 누락하지 않는다. 근거·인력·수집 상세 서랍은 모바일 전체 폭.

## 검증

| 검사 | 결과 |
|---|---|
| `pnpm verify:changed` | 통과: 웹 서식·타입·린트·가드·단위시험·계층·토큰·색 |
| `pnpm verify` | 최종 순차 실행 통과(종료 코드 0): 루트 311개·웹 1085개·AI 264개·결정 서버 57개, 웹 빌드 포함 |
| `pnpm -C web test:browser` | 19개 파일, 129개 통과. 360px 상세·대시보드, 390px 공고·인력 서랍·월말 일정, 필터 취소/적용/긴 기관명/상태 묶음, 기존 데스크톱 회귀 포함 |
| `pnpm -C web exec playwright test e2e/landing.spec.ts` | 프로덕션 앱 23개 통과. 360·390·768·1280·1440·1920px 넘침, 모바일 메뉴 닫기 클릭과 링크 이동, 데스크톱 예시 조작 포함 |
| 모바일 로그인 후 변경 흐름 | 로컬 owner 세션에서 `mobile-web.spec.ts` 1개 통과. 메뉴→공고→필터 취소/적용→일정 목록 표시·가로 넘침을 확인 |
| 독립 리뷰 | 1회. 인력 서랍 고정 폭, 상태 조건 일부 해제의 불일치, 긴 조건 칩, 일정 링크 터치 높이, 데스크톱 바닥글 높이 5건 수정 후 재확인 |

로그인 후 모바일 시험은 성공한 owner 로그인 세션을 재사용해 `playwright test -c playwright.auth.config.ts mobile-web.spec.ts --project chromium --no-deps`로 실행했다. 기존 설정의 owner/member 로그인 준비는 2개 통과했다. 전체 로그인 준비 중 outsider/invitee/admin 3개는 기존 기대 제목 `조직 초대가 필요합니다`와 현재 제목 `가입 신청`의 차이로 실패했고, 의존하는 기존 9개는 실행되지 않았다. 이 기대값은 모바일 작업 범위에서 변경하지 않았다.

로그인 검증 전 로컬 DB에서 누락된 저장소 마이그레이션만 `supabase migration up --local`로 적용했다. 데이터 초기화·운영 DB 변경은 하지 않았다. 로컬 status의 주소·anon 키를 시험 빌드와 서버의 자식 프로세스 환경에만 전달했으며 환경 파일은 수정하지 않았다. 최종 전체 검증은 기존 환경으로 다시 빌드한다.

초기 전체 검증에서는 다른 브라우저 검증과 실행이 겹쳤을 때 기존 결정 서버의 20ms 마감 시험이 질문 시작 전에 만료되어 1건 실패했다. 최종 순차 실행에서는 결정 서버 57개가 모두 통과했고 전체 명령도 종료 코드 0으로 끝났다.

## 푸시 전 검토 (2026-10-30)

`predeploy-review`의 code·design·product·developer·marketer·customer-support·qa 기준과 최신 Vercel Web Interface Guidelines를 모바일 변경 범위에 적용했다. 기존 독립 리뷰 5건의 수정과 모바일/데스크톱 검증 증거를 다시 확인했고 추가 배포 차단 지적은 없다. 디자인 프로필의 옛 모바일 금지 체크는 정본 ADR-072를 우선했다. 기존 전체 로그인 준비 3건의 문구 불일치는 위 제한으로 유지한다.

커밋에는 모바일 웹 구현·시험·설계·증거만 포함하며, 동시 작업 중인 구글 캘린더 API·토큰·마이그레이션·참조 이미지는 포함하지 않는다. 원격 main의 자격 판정·가입·운영 문서 변경은 별도 병합 커밋으로 유지했다. 커밋과 푸시 훅은 끄지 않고 실행한다.
