# 문서 최신 기준 정합화 수정과 검증 기록

2026-10-21 사용자가 [[2026-10-21-docs-current-baseline-sync-plan|수정 계획]]을 승인해 Task 1~7을 순서대로 수행했다. 시작 HEAD는 `7133636`이다. 기존 ADR-047 설계와 다른 작업의 미커밋 변경을 보존하면서 `docs/` 문서만 정정했다. 코드·시험·DB·운영 설정·Git 설정은 이 작업에서 변경하지 않았다.

## 검증 범위

- 단계별로 기준 문서와 실제 파일을 읽고 해당 문구·구현 상태를 대조했다. C1 shell 예시는 `bash -n`으로 구문만 확인했고 실행하지 않았다.
- 수정한 문서의 frontmatter, 새로 바뀐 줄의 Markdown 링크·위키링크, 표 열 수·파이프 이스케이프, 뒤 공백을 확인했다. 과거부터 있던 예시·미래 파일 경로와 실제 파일 참조를 구분했다.
- 현재 안내의 옛 모델·배포처·착수 게이트·리허설 날짜를 `rg`로 찾고 현행·이력·제안을 분류했다. 문자열 0건을 목표로 퇴역 모델·과거 날짜를 삭제하지 않았다.
- 시작 시 저장한 문서와 비교해 기존 ADR-047 제안 절과 날짜가 있는 과거 작업 로그를 보존했는지 확인했다. 중복 Vercel 요약은 동일한 두 블록 가운데 하나만 제거했다.
- 저장소는 시작부터 `core.bare=true`였다. 설정을 바꾸지 않고 `git --work-tree=/Users/leegwanghui/dev/hackathon/sol-radar diff --check`로 검사했다.
- 코드 시험·전체 verify·빌드·E2E·Compose·외부 API·모델 호출·DB 적용·배포는 실행하지 않았다. ADR-046의 문서 전용 검증 기준을 적용했다. 다른 작업의 코드 검증 결과를 이 작업의 결과로 합산하지 않았다.

## 독립 검토와 수정

전체 문서 변경에 독립 검토 1회를 수행했다. 판정은 문서 P2 네 건 수정 조건부였고 판단을 유보한 항목은 없었다. 네 건 모두 기존 코드·문서와 대조한 뒤 수정했다.

1. 11 테스트 S-LIVE 수용 기준과 19 S0의 실제 첨부 파싱·보정 배지 요구를 현재 구현에 맞췄다.
2. 18 차별점·경쟁 비교표의 Qwen 설명 생성·보정 배지 주장을 현재 템플릿·UI 미구현으로 정정했다.
3. 15 데이터 계약의 삭제된 connector·registry 시험을 당시 이력으로 구분했다.
4. C1 G6을 실패 대상별로 나눴다. 추출 정상·Bosun만 불가하면 `COMPLETED`·`RULES_ONLY`, 캐시 없는 Qwen 추출 실패는 `PARTIAL`·`RULES_ONLY`, gateway 연결 실패는 `AI_UNAVAILABLE`·`PARTIAL`이다. 근거는 `web/server/analysis/fallback.model.ts`와 [[03-AI-PIPELINE]] §8이다. 같은 원칙을 제출 아키텍처에도 반영했다.

수정 뒤 해당 문구·참조·실패 분류를 다시 대조했다. 문서만 수정했으므로 새 회귀 시험을 만들거나 삭제 시험을 복구하지 않았다.

## 현재 증거의 경계

- 회사 모델의 실제 served id·실추론 품질·GPU 학습·수신 결과는 기존 증거 확보 상태를 유지한다. 이 문서 정정으로 성공·완료가 되지 않는다.
- 작업 중 별도 운영 도메인 로그인 조회 증거가 작업 폴더에 추가됐다(이번 문서 정정 커밋에는 포함하지 않은 별도 작업). 이는 운영 사이트 관찰이며, 승인된 Vercel 다중 서비스 구성이 배포됐다는 증거로 대신 쓰지 않았다. 배포 상태 문구는 해당 Vercel 구성 검증 기록의 범위로 한정했다. 잘못 구분했다면 배포 증거를 추가 대조해야 하며 런타임 변경은 없다.
- EMAIL 채널·개인 설정·새 API는 승인 설계와 main 구현을 구분한다. 기존 DB 값·DTO를 이미 바꿨다고 쓰지 않는다.
- 문서 정정·검증 단계 이후 사용자가 커밋·push를 요청했다. 다른 작업의 변경은 원래 작업 폴더에 보존하고, 별도 작업 공간에서 문서 정정분만 분리해 정상 커밋 게이트를 거쳐 반영한다. 최종 문서 검사 결과는 아래에 기록한다.

## 커밋 직전 원격 반영

커밋 분리 중 원격 main에 Storage 전환 PR #7(`76eea2a`)이 추가됐다. 이를 먼저 반영하고 ADR-048의 private Supabase Storage 결정·관련 문서를 보존했다. 문서 정정과 겹친 배포·보안·용어 절을 병합하고 제출 그림·첫 배포 안내의 파일 저장소도 같은 기준으로 맞췄다. 전환의 클라우드 적용·배포 성공은 별도 검증 대상이며 이번 작업에서 실행하지 않았다. 원래 작업 폴더의 병행 병합·미커밋 변경은 건드리지 않는다.

## 최종 검사 결과

PASS. 정정 대상 37개 문서의 변경 줄을 확인했고 새 링크·위키링크·표 열·frontmatter·뒤 공백 오류는 0건이다. 기존 제안 절 11개와 ADR-047 본문·과거 날짜별 작업 로그를 보존했다. C1 shell 예시 `bash -n`과 명시적 work-tree의 `git diff --check`를 통과했다. 독립 검토 P2 네 건은 모두 정정·근거 재대조했고 보류 항목은 없다. 코드 시험·빌드·실제 배포 성공을 주장하는 결과가 아니다.
