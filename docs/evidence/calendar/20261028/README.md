# 입찰 일정 `/calendar` (2026-10-28, 파트 C)

스펙: `polaris/specs/done/2026-10-28-gaps-market-calendar.md` §4·§7. 브랜치 `feat/bid-calendar`(기준 `5fa888db`). 사이드바 등록은 통합 때 메인 세션이 한다(그 전에는 주소로 연다).

## 무엇이 보이나

- 월간 달력(KST, 월요일 시작), 이전 달·오늘·다음 달 링크(`?month=YYYY-MM`), 오늘 칸 표시(`aria-current="date"`).
- 일정 종류는 아이콘 + 글자로 구분한다: 폴더 아이콘 = 제출 마감(입찰 프로젝트, 바꾼 값이면 "(변경)"), 문서 아이콘 = 공고 마감, 별 = 내 관심, 보라 글자 "DEMO" = 데모용 가상 공고. 칩의 접근 이름에 종류·시각·관심·DEMO 를 글자로 싣는다.
- 칩은 두 줄이다: 윗줄 종류 아이콘·시각(KST)·별·"DEMO" 글자, 아랫줄 제목(칩 폭 전부). 1440px 에서 제목이 7~8글자 보인다(전에는 아이콘 옆에서 3~4글자). 전체 제목은 마우스를 올리면(title) 보인다.
- 같은 날 2건 이상이면 칸 머리에 겹침 아이콘 + "n건". 칩은 칸마다 2개까지(칸 높이 그대로), 나머지는 "+n건 더" 메뉴. 메뉴는 머리에만 날짜를 두고 항목은 종류 아이콘·시각(HH:mm)·제목(2줄까지)·별·"DEMO" 글자다(접근 이름은 칩과 같다).
- "다가오는 14일" 목록(D-Day·D-n, 오늘 이미 지난 시각은 뺌). 단이 넓으면(사이드바를 편 1440px) 오른쪽, 좁으면(1280px) 달력 아래.
- 보기: 조직 전체(기본, 내 관심 + 조직의 진행 중 프로젝트) / 내 일정(`?view=mine`, 내 관심 + 내가 담당인 프로젝트). 남의 관심은 어느 보기에도 없다(RLS·N3 D6).
- 일정이 하나도 없으면 빈 상태와 "입찰 공고 보기" 링크.
- 마감 알림 안내 문구는 두지 않는다. 운영 알림 Worker 가 기동 전이라 사실이 아니다(`docs/PROGRESS.md` "알림 처리" 행). 회사 Worker 를 켜면 되살린다.

## 일정 모으기 규칙 (`web/server/calendar/calendar.model.ts`)

- 원천: 본인 `bid_watches` + 조직의 `bid_projects`(CLOSED 제외). 새 표·마이그레이션 없음, 사용자 세션 + RLS.
- 프로젝트 제출 마감은 `effectiveDueAt`(변경 값 우선). 변경 값이 없거나 공고 마감과 같은 시각이면 한 건(제출 마감)으로 합치고, 다르면 제출 마감과 공고 마감 두 건이다.
- 같은 공고가 관심이면서 프로젝트이면 프로젝트 일정에 관심 표시만 얹는다(중복 칩 없음).
- 칩 링크: 제출 마감 → `/projects/[id]`, 공고 마감 → `/bids/[id]?origin=demo|live`(공고의 출처).

## 후속: 관련 업종 공고와 원본 일정 (2026-10-28, `feat/calendar-schedule`)

운영 `/calendar` 가 비어 있었다. 관심 공고와 입찰 프로젝트만 읽었기 때문이다. 이 후속은 수집이 이미 저장한 나라장터 입찰공고 원본(`raw_payload`)의 일정을 관련 업종 공고와 함께 싣는다. API 호출·Worker·마이그레이션은 더하지 않았다. 사용자 세션(anon 키) + RLS 로만 읽고 service role 은 쓰지 않는다. 기준은 main `4091f625` 이다.

- 근거: [prod-raw-check.md](prod-raw-check.md) — 운영 DB 읽기 SELECT 3회차. 마감 전 대표 공고는 1,148건이고 모두 `g2b-bid-notice` 다. 키 채움은 bidBeginDt 1,148, opengDt 1,148, bidQlfctRgstDt 1,147, cmmnSpldmdAgrmntClseDt 379, dcmtgOprtnDt 13 이다.
- 새 일정 종류는 다섯 가지다: 입찰서 제출 시작(`bidBeginDt`), 입찰참가자격 등록 마감(`bidQlfctRgstDt`), 공동수급협정서 마감(`cmmnSpldmdAgrmntClseDt`), 현장설명회(`dcmtgOprtnDt`, 장소 `dcmtgOprtnPlce`), 개찰(`opengDt`). 입찰 마감(`bidClseDt`)은 기존 "공고 마감"(`deadline_at`)을 그대로 쓴다. 종류는 아이콘 + 글자로 구분하고, 개찰은 일정만 보이며 결과는 다루지 않는다.
- 대상: 조직 전체 보기는 관심·프로젝트에 관련 업종 공고를 더한다. 관련 업종 공고의 조건은 `/gaps`(`web/server/gaps/gaps.repo.ts`)와 같다. live(`is_demo=false`, `source<>fixture`) 입찰공고(`stage=NOTICE`)이고, OPEN·AMENDED 이며(취소 제외), 대표 공고(`superseded_by` 없음)다. 마감 하한만 `/gaps`(지금 이후)와 다르다: 오늘 0시(KST) − 14일 이후라 마감이 지난 공고의 개찰 같은 일정이 14일 동안 남는다. 여기에 최신 revision 의 최신 관련성 평가가 RELEVANT·CANDIDATE 여야 한다. 내 일정 보기는 관련 공고를 읽지 않는다. 대신 관심·내 프로젝트 공고의 원본 일정을 싣는다.
- 읽기: `raw_payload` 는 통째로 받지 않는다. `종류:raw_payload->>키` 경로로 키 여섯 개만 고르고 `latest_revision` 행만 쓴다. 1,000행 제한은 id keyset(500건씩)으로 넘는다. 공고 마감 범위는 [오늘 0시(KST) − 14일, 보일 끝날 + 45일)이다. 보일 끝날은 달력 격자 끝날과 다가오는 14일 끝 가운데 늦은 날이다. 이 범위로 오늘부터 보일 칸의 원본 일정이 빠지지 않는다고 가정한다(개찰은 마감 뒤 14일 안, 제출 시작 등은 마감 전 45일 안). 하한이 오늘 기준이라 마감이 14일 넘게 지난 관련 공고는 지난 달 칸에 보이지 않는다(출처 줄 "관련 업종의 마감 전·최근 14일 마감 공고"가 설명한다). 관련 공고 읽기가 실패해도 관심·프로젝트 일정은 그리고, 출처 줄 아래에 안내 한 줄(role=status)을 보인다. 이 가정은 주석(`SCHEDULE_*_DAYS`)과 시험에 남겼다.
- 시각: 원문은 KST 이고 오프셋이 없다. 수집의 `parseKstDateTime`(`@/server/ingestion`)을 다시 쓴다. 빈 값·형식 오류·없는 날짜·날짜만·상대 날짜는 그 일정만 버린다. 취소 공고는 원본 일정을 싣지 않는다.
- 겹침: 같은 공고가 관심·프로젝트·관련에 함께 걸려도 (공고 id, 종류, 시각)마다 한 번만 그린다. 관심 별과 프로젝트 표시는 남는다.
- 종류 거르기(`?kinds=`): 모르는 값은 무시한다. 걸러 낸 결과가 비면 전부로 되돌리지 않고 "0건 + 전체 보기"를 보인다. 전부 끄면 `?kinds=`(빈 값)로 적는다.
- 화면 상한(0f): 다가오는 14일은 화면에 40건까지 넘기고 처음 8건 + "나머지 32건 더 보기"로 그린다. 넘는 건수는 "그 밖에 n건은 일정 종류를 거르거나 달력에서 봅니다." 한 줄로만 보인다. 밀집 날 "+n건 더" 메뉴는 항목을 하루 15건까지 그리고, 넘으면 구분선 아래에 "그 밖에 n건 · 일정 종류를 거르면 줄어듭니다" 한 줄을 둔다. 관련 공고가 많을 때 문서 크기를 줄이려는 상한이다(아래 측정).

- 결함(하) 2건. QA 뒤 45 가 고쳤다: 1은 안내 문구를 "이 달에는 고른 종류의 일정이 없습니다."로 바꿨고, 2는 날짜·시각을 줄바꿈하지 않게 했다. 브라우저 시험으로 확인했고 스크린샷은 다시 찍지 않았다(kinds-none 두 장은 옛 문구):

  2. 1440px(사이드바 폄)에서 다가오는 목록의 종류 줄이 긴 종류 이름일 때 날짜와 시각 사이에서 줄이 바뀐다. 예: "입찰참가자격 등록 마감 · 2026-10-31 / 10:30". 시각 부분을 줄바꿈하지 않게 하면 된다.

### 응답 크기와 첫 화면 시간
