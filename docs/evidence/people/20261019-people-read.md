# 조직·인력 조회와 독립 조직도 구현·검증

요청한 조회 기능과 `/people`·`/org-chart` 분리를 구현했다. 최종 제품 코드 `cd4a91c673fcd411a31e8f86086a5bb429918fde`에서 전체 검증과 관련 실연동 재검증을 통과했다. 다만 기존 가입 E2E의 최신 보존 결과에는 **4건의 실패가 남아 있어 전체 회귀·수용 완료나 병합 준비 완료를 선언하지 않는다.** main 병합·공유 DB 적용·push·배포는 수행하지 않았다.

작업 위치는 `5b0c`, 브랜치는 `feat/people-read`, 기준은 main `89b2b5e`다. 구현·시험·스펙 변경은 14커밋·66파일이다. [커밋 목록](20261019-people-read/implementation-commits.txt), [전체 변경 파일](20261019-people-read/implementation-files.txt), [독립 QA](20261019-people-read/qa-report.md), [독립 검토](20261019-people-read/live-ui-fix-review.md), [최종 증거 감사](20261019-people-read/final-evidence-audit.md), [안전한 원본 증거 묶음](20261019-people-read/evidence.zip), [파일 해시·출처](20261019-people-read/manifest.json)를 함께 보존한다. 이 문서를 추가한 문서 커밋은 위 제품 14커밋과 별도다.

## 구현 결과

- `/people`은 명부 전용이다. 이름 검색, 부서·직급·점수 계산 대상 필터,20명 페이지, URL/뒤로 가기, 로딩·빈 상태·오류/재시도를 제공한다. `view` 값은 무시하며 조직도 탭이나 리다이렉트가 없다.
- `/org-chart`는 서버 서비스가 현재 조직의 전체 자료를 읽는 별도 화면이다. 약300px 부서 탐색기, 실제 부모 연결, 직접 본부→팀, 본부 인원순/동률 코드순, 중립적인 상위 미지정 묶음, 직급 카탈로그순/같은 직급 이름순 카드가 있다. 본부·그룹·묶음은 중첩ul/li 펼침 버튼, 팀은 선택 버튼이다.
- 기본 선택은 AX사업본부 AI플랫폼운영팀14명이다. `?team=`·새로고침·뒤로 가기를 지원하며 없는 값과 다른 조직의 값은 기본 팀으로 돌아간다. 이름 combobox는 최대8후보를 표시하고 해당 팀·카드에 초점을 옮긴다. 서랍은 자동으로 열지 않는다.
- 사이드바 사용자 메뉴 위에 구분선과 NetworkIcon의 “조직도” 링크를 추가했다. 기존 “조직·인력” 링크를 유지하며 전체 N1 메뉴 개편은 하지 않았다.
- 공통 `PersonDrawer`는 사진·이름·부서·직급·대상 여부와 대상자의 직무·등급·스킬·가용성을 표시한다. 일반173명은 `scoring:null`이다. Escape·초점 복귀, 실패 재시도, 오래된 응답 차단을 지원한다. 카드 사진은44px이며 사진 없음·오류 시 이름 첫 글자로 대체한다. 연락처·성별·내부 ID는 화면에 노출하지 않는다.

서버 도메인은 `web/server/people/`의 model·repo·service·index로 구성했다. 서버가 세션과 실제 멤버십으로 조직을 결정하며 anon-session RLS를 사용한다. VIEWER·ANALYST·SALES·ADMIN 모두 조회할 수 있고 업무 역할은 owner/member 및 플랫폼 운영자와 별개다. 조직0/1/복수, 정지·미완료 계정, Bearer 우선순위를 검사한다. 다른 조직 상세/필터 자원은404, 직접 RLS 조회는0행이다.

새 append-only 마이그레이션은 `20261018000001_people_business_roles.sql` 하나다. `memberships.sol_role` 기본VIEWER·4값 CHECK와 클라이언트 임의 INSERT/UPDATE 차단을 추가했다. 기존 owner/member 권한·12개 SQL·가입 개인 조직 미생성 정책을 보존했고 타입은 생성기로 갱신했다. 적용은 전용 로컬 QA DB에서만 했다. 독립 조직도 분리 단계에서는 API·마이그레이션·패키지를 더하지 않았다.

가입의 공개 직급 코드와 조회의 UUID를 구분한다. 사진은 직원 UUID 대신 `personCode`로 `/demo/people/SOL-P0001.png`~`SOL-P0200.png`에 연결한다. 페이지 커서는 서버 전용 `API_CURSOR_SECRET`(32자 이상)으로 서명해 조직·필터·페이지 크기·24시간에 묶는다. 키 미설정은503이며 HMAC 서명은 암호화가 아니다.

## 데이터와 조직 표시

직원200·평가27·비대상173, 승인 사진200·SHA-256, 기존 직원 UUID/personCode·이름·부서·직급을 유지했다. 본부6·그룹4·팀38, 팀별 targetCount 합200이며 본부·그룹의 목표 인원은NULL이다. 상위 인원 집계를 DB에 저장하지 않는다.

확정된13팀의81명과 상위 미지정25팀의119명을 구분한다. 미지정 그룹4개에는 연결된 직원이 없다. 부모 미확정29개는 `parentId:null`로 유지하고 자연적인 본부 root와 구분해 표시한다. P&AX컨설팅본부는 “연결된 팀 없음”이며 화살표가 없다. 실제38팀을 차례로 선택한 검증에서 고유 직원200명이 각각 한 번 포함됐다. 부모 추정이나 직원 이동은 하지 않았다.

최종 무결성 검사에서 승인 기준과 같은219개 파일(사진200·핵심 fixture4·기존 SQL12·점수 입력/시험3)을 확인했다. 골든94/72/68의 기존 입력을 보존했다. 이 결과를 전체 G1~G10 또는 운영 정보 변경 뒤 기존 score_runs 불변의 통합 증거로 올리지 않는다.

## 남은 실패·미검증

기존 가입 E2E 네 건은 이메일 가입·확인 후 재로그인, 미완료 계정 보완1440/1280, 신고 정보 삭제 후 업무 차단 시나리오다(`signup-employment.write.spec.ts:52,115,168`). 로그인 뒤 화면 이동의 원래5초 단언 등에서 실패해 후속 시나리오 전체를 통과했다고 할 수 없다. 실제 DB57014/Auth504 및 느린 응답을 관측했지만 모든 실패의 원인을 부하로 확정하지 않았다. 제품 인증 코드는 바꾸지 않았다.

조직·인력 실연동 준비는 실제 로그인 폼·Auth200·세션 쿠키를 확인한 뒤 대상 화면으로 문서 이동한다. 이 방식은 자동 로그인 후 이동 회귀의 성공 증거를 대신하지 않는다. 잘못된 업무 역할의 SSR은 기존 방식의 inline HTTP200 권한 안내이며 API403과 구분한다. 외부 OAuth, 최신 main과 결합한 실행, 전체 N1/N2/P1, 전체 G1~G10·score_runs 파이프라인은 이번 수용 범위가 아니다. 부모29건의 사실 관계 확인도 남아 있으나 null과 미지정 표시 자체는 정상 지원한다.

## 보존·정리와 병합 전 준비
