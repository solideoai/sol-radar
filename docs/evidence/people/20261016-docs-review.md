# 솔리데오 인력·가입 설계 문서 검증

## 이번 검증 범위

ADR-019와 `polaris/specs/planned/2026-10-16-solideo-people-signup.md`, README 및 정본 문서의 반영 여부를 확인했다. 명부 JSON·사진 200장·DB migration·가입 폼 구현은 후속 작업이며 PPL-01~07을 통과한 상태로 보고하지 않는다.

## 문서 검사

결과는 `20261016-docs-check.json`이다. 인력 원본은 로컬 읽기만 수행했고 증거에 원본 실명을 기록하지 않았다.

- 문서 23개, 위키링크 763개, 로컬 Markdown 링크 30개, 표 128개 검사.
- frontmatter·링크 대상·표 열·관련 문서 H2·잘못 삽입된 제목 검사 오류 0.
- 원본에서 인력 행 250개 인식. 이는 가중치용 행 수이며 실제 고유 임직원 수로 주장하지 않는다.
- 이번에 추가한 문서와 스펙의 원본 이름 일치 0건. 이 결과는 아직 만들지 않은 가상 이름 200개의 검사 결과가 아니다.
- 원본 SHA-256은 JSON에 저장해 어느 입력으로 검사했는지 추적한다. 이름 제외 집합·원본과 가상 인물 대응표는 저장하지 않는다.
- 별도 에이전트의 읽기 전용 교차 리뷰 후 이름 보완 저장·카탈로그 FK 초기화·인력 입력 스냅샷·직급 배분 동률 규칙을 보완했다. 재검토에서 추가 지적 없음.

## 저장소 검증

실행 명령: `pnpm verify`. 저장 로그는 줄끝 공백·개행만 정규화했으며 결과·오류 내용은 유지했다.

- 첫 실행: 샌드박스에서 임시 서버의 `127.0.0.1` listen이 EPERM으로 거절되어 pre-push 시험 5건 실패. 원본 로그 `20261016-docs-verify-sandbox.txt`.
- 동일 명령을 제한 밖에서 다시 실행: 종료 코드 0. 로그 `20261016-docs-verify.txt`.
- 루트 173/173, 웹 Vitest 628/628 통과. 서식·타입·린트·린트 가드·계층·토큰·색·DB 생성 타입·Next 빌드 통과.
- `git diff --check` 통과.

이번에는 제품 코드 변경이 없어 브라우저/E2E와 실제 가입·DB 적용·이미지 생성을 실행하지 않았다. 이 요구의 구현 검증은 정본 [[11-TESTING]]의 PPL-01~07을 따른다.
