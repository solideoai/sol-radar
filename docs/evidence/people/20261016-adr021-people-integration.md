# ADR-021 인력·가입 정합화 검증

2026-10-17 독립 코드 QA 통과. 최종 코드 `21c8b9785cc04fcd1d99eddd92e75cbe157bcedb`에서 확인된 세 결함은 수정·독립 리뷰·실제 재검증으로 닫혔다. 사진 사람 검수·READY·통합과 전체 ADR-021 구현·배포 완료는 포함하지 않는다. [전체 QA 보고서](20261017-adr021-qa-report.md), [증거 해시 목록](20261017-adr021/index.json).

## 구현과 데이터 보존

- `team_members` 운영 200행과 `team_member_scoring` 27행을 분리했다. 기존 ID·이름·사진 경로·계산 입력·20FTE 의미를 보존한다.
- 38개 TEAM을 보존하고 확인된 본부 6·그룹 4를 추가했다. 상위 10개 조직의 인원 수는 NULL이다. 미확정 부모 29건(팀25·그룹4)은 NULL과 사유를 유지한다. 가입 선택은 38개 TEAM·직급12개다.
- 신규 가입은 profile만 만들며 개인 조직·멤버십을 자동 생성하지 않는다. 기존 개인 조직·멤버십·작업은 보존한다.
- 서버가 실제 업무 멤버십으로 0개→초대 안내, 1개→해당 조직, 복수→지원 불가를 결정한다. 신고 부서·직급으로 권한이나 조직 합류를 부여하지 않는다. 계정·보완·받은 초대는 조직 없이 접근한다.

## 환경 격리와 정리

전용 프로젝트 `sol-radar-t9-20261017-b3ef-qa`(API55321/DB55322/웹localhost33272)를 사용했다. 모든 CLI는 정확한 전용 `--workdir`, fixture는 두 명시적 대상 선택자와 해당 API 검증 뒤 실행했다. 새 빌드의 공개 번들에서 전용 API는 확인됐고 공유54321은 없었다. QA는 기존 환경 파일을 직접 열람하거나 복사하지 않았으며, 앱 설정은 전용 private 환경으로 덮어썼다.

최종 인력200/평가27/부서48/직급12/테스트계정5와 ID·이름·성별·해시 보존을 확인했다. 임시 사용자·조직0, 전용 컨테이너9개·볼륨만 정리, 무관한 실행 컨테이너16개 동일, private 환경·생성 로그인 상태5개 제거를 확인했다. 공유 DB migration/seed 적용·소스 checkout 수정·main 병합·클라우드 push는 하지 않았다. 이전 작업과 원본 엑셀은 보존한다.

## 남은 범위와 검증 한계

- 사진은 별도9663 worktree에서 GENERATED200/READY0. 코드 worktree는 PLANNED manifest이며 실제 사진 통합 전이다. 사람의 200명 이름/얼굴 승인 없이 READY·release 통과를 기록하지 않는다.
- 실제 REST 중단 시험은30초 navigation timeout으로 끝나 초기 서버 조회 실패 안내의 live 동작은 확립하지 못했다. 오류 화면의 모의 브라우저 검사와 실제 PATCH503 오류/재시도 검사를 구분한다.
- RSC 응답을 계속 보류한 상태의 즉시 계정 이동은 미확립이다. 키보드 활성화 후 보류 응답을 해제했을 때 최종 계정 화면과 초점 유지 통과만 주장한다.
- 완전한 slug 없는 N1, `sol_role`/ADMIN 정책 전체 전환 N2, `/people`, `/ops`, sidebar/P1, 전체 Phase4 점수 파이프라인과 실제 외부 OAuth 공급자는 후속 범위다. 플랫폼 `/admin`의 기존 운영자 정책은 유지한다.
- 원본은 승인된 검증기만 읽었고 결과는 집계/코드/해시만 남긴다. 과거 Task5의 내부 연락처 단일 값 출력은 이미 고지한 이력이므로 과거까지 노출0이라고 주장하지 않으며 그 값은 재기록하지 않는다.
