# 관리자 프로필 사진 등록

사용자 요청: 운영 계정 `admin@solideos.com`에 기존 가상 직원 200명과 같은 정장 사진 스타일의 남성 관리자 이미지를 생성해 등록한다. 이번 요청이 대상 계정의 운영 사진 등록 승인이다.

- 생성 도구: 기본 내장 `image_gen` (`imagegen` 스킬). CLI·유료 hosted 추론 API를 따로 호출하지 않았다.
- [생성 원본](admin-portrait.png): 1254×1254 PNG, 2,080,679바이트. 밝은 회색 배경·네이비 정장·흰 셔츠·넥타이, 차분한 40대 중반 남성의 완전한 가상 얼굴. 실제 직원·유명인의 신원을 사용하지 않았다.
- [최종 생성 프롬프트](generation.json): 기존 사진의 스튜디오 조명·정장·정사각 구도를 맞추고 원형 아바타로 써도 얼굴이 잘리지 않도록 요청했다.
- 운영 전 확인: 이메일과 사용자 ID로 정확히 한 active 계정을 조회했다. 업무 역할 ADMIN, 사진 경로·기존 avatar URL 모두 null, 조직도 연결 직원 0명. 운영 사진 버킷은 private이며 2MiB 제한이다.
- 적용: 전용 `users/<계정 UUID>/<새 UUID>.png`에 덮어쓰기 없이 업로드하고 `profiles`의 ID·이메일·기존 `photo_path is null` 조건을 모두 걸어 사진 경로 한 열만 갱신했다. 계정·역할·조직·직원 명부·기존 200명 사진은 바꾸지 않았다.
- 검증: 갱신된 프로필 1행 재조회, 서명 URL 이미지 GET 200, 저장 이미지와 생성 원본의 SHA-256 일치. [작업 결과](operation.json). 비밀키·인증 토큰·서명 URL은 기록하지 않았다.
- 표시 경로: 조직도 연결이 없으므로 기존 `ownPhotoPathOf`가 `profiles.photo_path`를 사용하고, 기존 `photoRepo.signPaths`가 서명한 사진을 `toProfileView`가 아바타로 선택한다. 실제 로그인 브라우저 캡처는 하지 않았다.
- 코드·스키마 변경 없이 기존 Storage·사진 필드만 사용했으므로 전체 앱 검증은 반복하지 않았다. 운영 데이터 변경은 이미 완료됐으며 웹 배포가 필요하지 않다.
- 복구가 필요하면 이 계정의 현재 경로가 작업 기록과 같은지 확인한 뒤 사진 포인터만 이전 값 null로 되돌린다. 생성 파일과 업로드 객체는 이번 작업에서 삭제하지 않았다.
