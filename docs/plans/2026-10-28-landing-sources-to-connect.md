# 랜딩 데이터 출처 로고 — 아직 연결 안 된 기관

> [!todo] 한눈에 (기준 2026-10-28)
> 사용자 결정(2026-10-28): "SOL RADAR가 공고를 가져오는곳은 연결 예정 빼고 다 해커톤 전에 연결할 거니까 연결 안 된 것들만 문서로 남겨. 로고만 나오게 깔끔하게 수정해"
> 랜딩의 "SOL RADAR 가 공고를 가져오는 곳" 줄은 9곳 로고만 보이고 "연결 예정" 꼬리표가 없다. 그래서 공식 제출(2026-11-03) 전에 아래 7곳을 운영에서 실제로 수집해야 한다.

## 1. 연결된 곳 (이 문서의 대상 아님)

| 기관 | 근거 |
|---|---|
| 나라장터(조달청) 입찰공고 15129394 | 운영 수집 중([[2026-10-28-all-sources-activation\|10종 수집 계획]] §2) |
| 한국토지주택공사(LH) 입찰공고 15159012 | registry 켬 `c5c88510`, 회사 A단계 반영 기록 `c7844305` |

## 2. 아직 연결 안 된 곳

"코드"는 main 의 수집 코드·설정이 있는지, "운영"은 회사 ingest Worker 가 실제로 공고를 넣고 있는지다. 운영 칸은 2026-10-28 문서 기준이고 DB 로 확인하지 않았다.

| 기관 | 코드 | 운영 | 남은 일 |
|---|---|---|---|
| 한국수자원공사(K-water) 입찰공고 15101635 | registry 켬 `209d5515`, 정규화·재생 시험 있음 | 회사 반영 전 | push 된 main 을 회사에 ff → ingest Worker 재생성(사용자 승인) → 다음 정각 수집 확인 |
| 한국전력공사 전자입찰계약 15148223 | registry 켬(자체 상한 100/일), 정규화 71/71 | 회사 반영 전 | 위와 같음. 첨부 주소 `http://srm.kepco.net`는 해커톤 동안 막아 둔다(ADR-068) |
| 기업마당 지원사업 | `infra/sources/program-notices.yaml` `bizinfo` 켬([[../16-DECISIONS\|ADR-040]]) | 확인 안 됨 | 회사 Worker 에 `BIZINFO_API_KEY` 가 있는지(값은 보지 않는다), 부처 공고 수집 기록이 쌓이는지 확인 |
| 중소벤처기업부 사업공고 | 같은 파일 `mss` 켬(RSS, 키 없음) | 확인 안 됨 | 부처 공고 수집 기록 확인 |
| 한국도로공사 | 없음 | 없음 | 공개 입찰 API 찾기·활용신청 → 녹음 → 정규화 → registry → `bid_notices_source_check` 확장 마이그레이션(`db:push` 사용자 승인) → 회사 반영 |
| 국방전자조달(d2b) | 없음 | 없음 | 위와 같음 |
| 한국철도공사(코레일) | 없음 | 없음 | 위와 같음 |

- DB 의 `bid_notices_source_check`(`20261023000100_procurement_opportunities.sql`)는 나라장터·K-water·LH·KEPCO 출처만 받는다. 도로공사·국방전자조달·철도공사는 새 마이그레이션이 먼저다.
- 실호출·push·회사 반영·`db:push` 는 단계마다 사용자 승인 뒤에만 한다([[2026-10-28-all-sources-activation|10종 수집 계획]] §3·§5 규칙을 따른다).

## 3. 제출 전 확인

- 2026-11-02: 사용자 승인 뒤 운영 DB 읽기 SELECT(출처별 최근 7일 새 공고 수)로 9곳 모두 들어오는지 본다.
- 그때 연결되지 않은 기관이 있으면 사용자에게 알린다. 랜딩 줄 제목이 "가져오는 곳"이므로, 그 기관 로고를 뺄지 사용자가 정한다.
