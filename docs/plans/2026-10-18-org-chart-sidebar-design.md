# 설계 — 사이드바 트리·메뉴 아이콘과 조직도 화면 분리

> [!success] 병합 (2026-10-19)
> `/org-chart` 두 칸 탐색기(`13cf75f`), 사이드바 맨 아래 고정 칸의 "조직도", `/people` 명부만 남기기는 `feat/people-read`로 구현돼 main `7641ee4`(PR #6 `98101e8`)에 병합됐다([[06-UI-UX|06 UI]] §5.9·§5.9.1). 묶음 줄을 접는 사이드바 트리는 N1 앱 셸 몫이라 아직 없다([[PROGRESS|진행 상황]] ADR-021 N1). 본문의 "구현은 아직 전" 문장은 작성 당시 기록이다.

2026-10-18 사용자 대화에서 정했다. 이 문서는 설계 결정이며 구현은 아직 전이다(2026-10-19 현재 `/org-chart` 병합, [[PROGRESS|진행 상황]] 참조). [[16-DECISIONS|ADR-021]]의 사이드바 정보 구조와 [[06-UI-UX|06 UI]] §4·§5.9를 개정한다. 승인 설계 [사이드바 정보 구조와 입찰 업무 확장](2026-10-16-sidebar-ia-design.md)은 본문을 고치지 않고 그 문서 §8 "확정 이후 변경 기록"에 행을 더한다.

## 1. 의도

- 로그인 뒤 사이드바에서 가상 직원 200명의 조직도를 바로 열 수 있어야 한다.
- 조직도는 입찰 판단의 핵심 업무가 아니다. 그래서 업무 메뉴와 떼어 사이드바 맨 아래에 둔다(사용자 원문: "핵심 기능은 아니라서 사이드바 아래 부분에 배치").
- 사이드바는 묶음과 메뉴가 트리로 보여야 하고, 메뉴마다 아이콘이 있어야 한다.

## 2. 목표와 비목표

**목표**
- 사이드바를 트리로 바꾸고 메뉴마다 lucide 아이콘을 붙인다.
- 사이드바 맨 아래 고정 칸에 "조직도" 메뉴를 둔다.
- 조직도 전용 화면 `/org-chart`를 만든다. 왼쪽은 부서 트리, 오른쪽은 고른 팀의 사진 카드다.
- `/people`(조직·인력)에서 조직도 탭을 빼고 명부만 남긴다. 같은 조직도가 두 군데 있지 않게 한다.

**비목표**
- 조직·인력 편집(추가·이동·퇴사)은 여전히 P1이다([[12-ROADMAP|12 로드맵]]).
- 근거 없는 상위 부서를 추측해 붙이지 않는다. 원본 자료에서 확인되지 않은 부모는 "상위 미지정"으로 둔다([[16-DECISIONS|ADR-021]]).
- 새 API·마이그레이션·새 패키지를 만들지 않는다. 화면은 기존 `people` 서버 도메인을 쓴다.
- 1280px 미만 레이아웃은 만들지 않는다([[16-DECISIONS|ADR-007]]).

**실패로 볼 것**
- 조직도에 같은 직원이 두 번 나오거나 빠진다.
- 상위 미지정 부서를 본부 아래에 임의로 넣는다.
- 조직도가 핵심 업무 메뉴처럼 위쪽 묶음에 끼어든다.

## 3. 결정

### 3.1 사용자 결정 (2026-10-18)

| # | 결정 |
|---|---|
| U1 | 조직도는 사이드바 아래쪽에 **따로 둔 메뉴**다. `/people` 안의 탭으로 두지 않는다 |
| U2 | 위치는 **맨 아래 고정 칸**이다. 업무 메뉴와 선으로 떼고, 메뉴 수가 늘어도 자리가 바뀌지 않는다 |
| U3 | 사이드바는 **트리**로 보인다. 메뉴마다 아이콘을 붙인다 |
| U4 | 묶음 줄(업무·조직·시스템 등)은 **접기 화살표와 글자만** 둔다. 아이콘은 실제로 이동하는 메뉴에만 붙인다 |
| U5 | 조직도 화면은 **두 칸 탐색기**다. 왼쪽 부서 트리, 오른쪽 고른 팀의 사진 카드 |
| U6 | `/people`의 `명부`/`조직도` 전환을 없애고 명부만 남긴다. 구현 중인 세션에 전달한다(부록 A) |
| U7 | `/people`을 구현 중인 Codex 세션(`5b0c`)이 이미 만든 조직도 모델·부품을 `/org-chart`로 옮겨 이 화면까지 만든다. 지금 사이드바 바닥에 "조직도" 링크도 그 세션이 붙인다(M13 임시 배치). 트리·아이콘은 N1 앱 셸이 입힌다 |
| U8 | 정본 반영은 지금 다른 세션의 미커밋 수정이 없는 파일(06·20·사이드바 설계 §8)만 먼저 한다. 09·11·12·16·19·PROGRESS는 ADR-022 작업이 커밋된 뒤 사용자가 알려 주면 반영한다 |

## 4. 사이드바

### 4.1 구조

```text
┌──────────────────────────┐
│ SOL RADAR [DEMO]         │
│ ▾ 업무                   │   ← 묶음 줄: 화살표 + 회색 글자, 아이콘 없음
│ │ ▦ 대시보드             │   ← 메뉴: 세로선 안쪽 들여쓰기 + 아이콘 + 글자
│ ┃ ▤ 입찰 공고   (활성)   │   ← 활성: brand-soft 배경, brand 글자·아이콘, 세로선 자리에 3px brand 막대
│ │ ◔ 알림                 │
│ ▾ 조직                   │
│ │ ◎ 회사 역량            │
│ │ ◍ 조직·인력            │
│ ▾ 시스템                 │
│ │ ⚙ 설정                 │
│ │ ◫ 데이터 수집 관리     │
│                          │   ← 남는 공간
├──────────────────────────┤
│ ⌘ 조직도                 │   ← 맨 아래 고정 칸(묶음 없음)
└──────────────────────────┘
```

- 폭 240px, 접으면 64px는 그대로다([[06-UI-UX|06 UI]] §4).
- 묶음 순서는 ADR-021 그대로다: 업무 → AI 분석(P1) → 입찰 관리(P1) → 조직 → 시스템. 해커톤에는 노출 조건을 채운 업무·조직·시스템만 보인다.
- **묶음 줄**: 접기 버튼이다. 화살표(`chevron-down`/`chevron-right`, 16px)와 묶음 이름(작은 회색 굵은 글자)만 둔다. `aria-expanded`와 `aria-controls`를 단다. 누르면 그 묶음 메뉴가 접히고 펼쳐진다.
- **메뉴**: 묶음 화살표 아래 1px 세로선(`border`) 안쪽으로 들여 쓴다. 아이콘 16px + 글자 14px. 링크이며 현재 화면이면 `aria-current="page"`다.
- **활성 메뉴**: `brand-soft` 배경, `brand` 글자·아이콘, 세로선 자리에 3px `brand` 막대. 기존 "좌측 3px brand 바" 규칙을 트리 세로선 위에 그린다.
- **맨 아래 고정 칸**: 위쪽 1px 선으로 메뉴 영역과 나눈다. 묶음 없이 "조직도" 메뉴 하나다. 메뉴 영역이 길어지면 메뉴 영역만 스크롤되고 고정 칸은 움직이지 않는다. 사이드바 바닥에 사용자 메뉴가 있으면 그 바로 위다.
- **접은 상태(64px)**: 묶음 줄을 숨기고 메뉴 아이콘만 세로로 놓는다. 묶음 사이에 짧은 1px 선을 긋는다. 고정 칸의 조직도 아이콘은 맨 아래에 둔다. 마우스를 올리거나 키보드 초점이 오면 메뉴 이름 툴팁이 뜨고, 링크에는 `aria-label`로 이름을 준다.
- 색은 아이콘 + 글자 + 배경을 함께 써서 활성을 알린다. 색만으로 구분하지 않는다.

### 4.2 메뉴 아이콘 (lucide)

| 묶음 | 메뉴 | 경로 | 아이콘 | 해커톤 노출 |
|---|---|---|---|---|
| 업무 | 대시보드 | `/dashboard` | `layout-dashboard` | 예 |
| 업무 | 입찰 공고 | `/bids` | `file-text` | 예 |
| 업무 | 관심 공고 | `/watchlist` | `star` | P1 |
| 업무 | 알림 | `/notifications` | `bell` | 예 |
| AI 분석 | 분석 결과 비교 | `/analysis` | `git-compare-arrows` | P1 |
| AI 분석 | 인력 배치 시뮬레이션 | `/workforce` | `users-round` | P1 |
| 입찰 관리 | 입찰 프로젝트 | `/projects` | `folder-kanban` | P1 |
| 조직 | 회사 역량 | `/company` | `award` | 예 |
| 조직 | 조직·인력 | `/people` | `users` | 예 |
| 시스템 | 설정 | `/settings` | `settings` | 예 |
| 시스템 | 데이터 수집 관리 | `/admin/ingestion` | `database` | 예 (ADMIN만) |
| (고정 칸) | 조직도 | `/org-chart` | `network` | 예 |

- 이름은 설치된 `lucide-react` 1.54.0에서 확인했다. React에서는 `LayoutDashboardIcon`처럼 `Icon` 접미사 이름으로 부른다(현재 `web/components/app-shell.tsx`와 같다).
- 아이콘은 장식이다(`aria-hidden`). 이름은 항상 글자로 보이거나 `aria-label`로 읽힌다.

- 기존 `AppShell`·`AppPage`를 쓰고 `h1`은 "조직도"다. Topbar 제목도 "조직도"다.
- 설명 줄: `DEMO · 가상 인물` 표시와 `전체 N명 · 본부 N · 그룹 N · 팀 N`. 숫자는 읽은 자료에서 센다. 읽기 전이나 실패했을 때 고정 숫자를 보이지 않는다.

- 1440px·1280px 모두 사이드바를 연 상태에서 가로 스크롤이 없어야 한다. 카드는 `repeat(auto-fill, minmax(200px, 1fr))` 정도로 1440에서 4열, 1280에서 3열이 된다(구현자가 맞춘다).

### 5.2 왼쪽 부서 트리

- 실제 `parentId` 연결만 따라간다. 본부 → 그룹 → 팀은 허용되는 계층일 뿐 모든 단계가 있는 것이 아니다. 본부 바로 아래 팀(현재 13개)에 그룹을 끼우지 않는다.
- 두 구역으로 나눈다.
  1. **본부**: `kind=DIVISION`이고 `parentId=null`인 본부 6개. 구역 제목에 본부 아래 실제 인원 합(현재 81명)을 쓴다. 팀이 없는 본부(현재 P&AX컨설팅본부)는 "연결된 팀 없음"이고 펼치기 화살표가 없다.
  2. **상위 미지정**: 본부가 아니면서 `parentId=null`인 부서. 구역 제목에 부서 수와 인원(현재 29개 부서 · 119명), 그 아래 안내 "자료에서 상위 부서가 확인되지 않은 부서입니다."를 둔다. 안을 "그룹 N개"와 "팀 N개" 두 묶음으로 나눈다. 그룹 4개는 현재 연결된 팀이 없어 "연결된 팀 없음"이다.
- "본부"·"상위 미지정"·"그룹 N개"·"팀 N개"는 화면용 분류 이름이다. DB 부서로 저장하지 않는다.
- 상위 미지정은 정보 안내다. warning·danger 색을 쓰지 않는다.
- **인원 수**: 팀은 그 팀 재직자 수. 본부·그룹·구역은 하위 팀 재직자의 직원 ID를 중복 없이 센 수다. 본부·그룹에는 목표 인원을 쓰지 않는다. 팀은 `targetCount`가 있을 때만 오른쪽 칸 제목에 "목표 N명"을 쓴다.
- 순서는 M14를 따른다. 부서 이름은 자료 그대로다(M15). 그림의 팀 이름은 지면 때문에 줄인 곳이 있다.
- 펼치기 줄은 `aria-expanded`·`aria-controls`를 가진 버튼이다. 팀 줄은 선택 버튼이며 고른 팀에 `aria-current="true"`를 단다. 새 ARIA tree 위젯은 만들지 않는다(중첩 `ul`/`li`).
- 고른 팀 줄: `brand-soft` 배경, `brand` 글자. 들여쓰기 깊이당 약 16~24px, 부모 아래 1px 세로선.

### 5.3 오른쪽 팀 칸

- 제목 위 경로: 실제 상위 경로(예: `AX사업본부 › AX사업본부 AI플랫폼운영팀`). 상위 미지정 팀은 `상위 부서 미지정 › 팀 이름`.
- 제목: 팀 이름 · `N명`, `targetCount`가 있으면 ` · 목표 N명`.
- 카드: 사진(`PersonAvatar`, 44px 원형) · 이름(굵게) · 직급/직책 · 점수 계산 대상이면 `점수 계산 대상` 글자 표시(테두리 작은 표). 연락처·성별·내부 ID는 보이지 않는다.
- 카드는 버튼이다. 누르거나 Enter·Space로 `PersonDrawer`를 연다. 접근 가능한 이름은 "김민준 상세 보기"처럼 실제 이름을 담는다. 닫으면 그 카드로 초점이 돌아온다.
- 사진은 `personCode`(`SOL-P0001` 형식)로 `/demo/people/<personCode>.png`를 쓴다. 사진이 없거나 못 읽으면 같은 크기의 이름 첫 글자다.
- 팀 인원이 0명이면 "소속 인력이 없습니다".

### 5.4 이름으로 찾기

- 상단 오른쪽 입력. 보이는 라벨이나 `aria-label` "이름으로 찾기".
- 글자를 치면 아래로 후보 목록(이름 · 팀 · 직급, 최대 8개)이 뜬다. 방향키·Enter로 고른다(combobox).
- 고르면 그 팀까지 왼쪽 트리를 펼치고, 팀을 고르고, URL을 `?team=<departmentId>`로 바꾸고, 그 카드로 초점을 옮겨 잠깐 강조한다. 서랍을 자동으로 열지 않는다.
- 결과가 없으면 "일치하는 이름이 없습니다". 이름은 200명 모두 다르다(ADR-019).

### 5.6 권한과 데이터

- 조회는 ADMIN·SALES·ANALYST·VIEWER 모두다. 편집은 없다.
- 서버가 현재 조직을 정하고 요청의 조직 ID를 받지 않는다. 다른 조직 부서·인력은 RLS로 0행이다.
- 미인증은 기존 인증 정책, 출시 전 직접 접근 404, 권한 없는 역할 403(ADR-021 응답 구분).
- 데이터는 `departments`·`team_members`·`job_titles`와 점수 계산 대상 여부(`team_member_scoring` 존재)다. 점수 속성(직무·등급·스킬·가용성)은 카드에 보이지 않고 서랍에서만 보인다.

## 6. `/people` 변경

- `명부`/`조직도` 전환 링크와 조직도 패널을 없앤다. `/people`은 명부(검색·필터·표·페이지)와 `PersonDrawer`만이다.
- 메뉴 이름 "조직·인력"과 경로는 그대로다.
- `view` 쿼리는 무시한다(M12).

## 9. 시안

대화 중 브라우저 시안으로 고른 결과다. 시안 파일은 세션 임시 폴더에만 있고 저장소에 넣지 않았다.

- 사이드바 위치: A(맨 아래 고정 칸) / B(맨 마지막 "참고" 묶음) → **A**
- 트리 묶음 줄: A(묶음에도 아이콘) / B(화살표와 글자만) → **B**
- 조직도 화면: A(두 칸 탐색기) / B(박스 조직도) / C(한 줄 트리) → **A**

## 부록 A. `/people`·`/org-chart` 구현 세션(Codex worktree `5b0c`, `feat/people-read`)에 전달할 내용

사용자가 그 세션에 붙여 넣는다. 이 세션은 그 worktree를 고치지 않는다.

> **대상**: `polaris/specs/done/2026-10-18-solideo-people-ui.md`와 그 구현(`web/components/people/*`, `/people` 페이지, `web/components/app-shell.tsx`), 새 `/org-chart` 페이지
> **근거**: [설계 — 사이드바 트리·메뉴 아이콘과 조직도 화면 분리](docs/plans/2026-10-18-org-chart-sidebar-design.md) U1·U5·U6·U7, M1·M4~M8·M11~M15 (2026-10-18 사용자 결정). main에는 아직 없는 파일이라, 이 worktree에서 쓰려면 사용자에게 그 파일을 받거나 main을 병합한다.
>
> 1. `/people`에서 `명부`/`조직도` 보기 전환(`view=list|tree`)과 조직도 패널을 없앤다. `/people`은 명부(이름 검색·부서·직급·점수 계산 대상 필터·표·페이지)와 `PersonDrawer`만이다. `view` 쿼리가 와도 무시하고 명부를 보인다. 리다이렉트는 만들지 않는다.
> 2. 조직도는 새 화면 `/org-chart`(조직 주소 없는 경로)로 옮겨 이 작업에서 함께 만든다. 이미 만든 `web/components/people/org-chart-model.ts`(`buildOrgChart`)와 `org-chart.tsx`를 재사용한다. 화면 모양은 **두 칸 탐색기**다. 왼쪽은 부서 트리(본부 구역 + 상위 미지정 구역, 팀 줄을 고르는 버튼), 오른쪽은 고른 팀의 사진 카드(사진 44px·이름·직급/직책·`점수 계산 대상` 표시) 격자다. 카드를 누르면 `PersonDrawer`가 열린다. 세부(레이아웃·상태표·접근성)는 설계 문서 §5다.
> 3. 데이터는 서버 컴포넌트가 `@/server/people` 서비스로 현재 조직의 부서·명부 전체를 한 번에 읽는다. 새 Route Handler를 만들지 않는다. 다른 조직은 RLS로 0행이다. 역할 4개 모두 조회한다.
> 4. 순서와 첫 화면: 본부는 소속 인원이 많은 순(같으면 부서 코드 순), 팀·그룹은 부서 코드 순이다. 처음 열면 첫 본부(AX사업본부)를 펼치고 첫 팀을 고른다. 고른 팀은 URL `?team=<departmentId>`와 맞추고, 없는 값·다른 조직 값은 무시하고 기본 선택으로 간다. 팀 안 카드는 직급 카탈로그 순서, 같은 직급은 이름 가나다순이다. 부서 이름은 자료 그대로 보인다(본부명 접두어를 떼지 않는다).
> 5. 상단에 "이름으로 찾기" combobox(후보: 이름·팀·직급, 최대 8개)를 둔다. 고르면 그 팀까지 트리를 펼쳐 고르고 URL을 바꾸고 그 카드로 초점을 옮긴다. 서랍은 자동으로 열지 않는다.
> 6. 사이드바: 지금 템플릿 사이드바의 바닥(사용자 메뉴 바로 위)에 위쪽 선으로 나눈 "조직도" 링크(`NetworkIcon`)를 하나 더한다. "조직·인력"(`/people`) 링크는 그대로 둔다. 사이드바 트리·묶음·메뉴 아이콘 개편은 N1 앱 셸이 맡으니 이번에 하지 않는다.
> 7. `PersonDrawer`와 `PersonAvatar` 이니셜 대체는 두 화면이 함께 쓴다.
> 8. 스펙 문서(`polaris/specs/done/2026-10-18-solideo-people-ui.md`)의 조직도 패널 절·보기 전환 설명·상태표 조직도 행을 `/org-chart` 절로 옮겨 고친다. 시험은 설계 문서 §7 NAV-04(개정)·NAV-11을 기준으로 한다(1440·1280, axe 위반 0, 200명 각자 정확히 한 번, 본부 합 81명, 상위 미지정 29개 부서·119명).
