# 디자인 스펙: 솔리데오 조직·인력 조회

작성일: 2026-10-18. 범위: 승인된 N4a 조회 기능. 구현·브라우저 검증 전인 디자인 명세이며 화면 문구는 카피 초안이다. 서버 계약·인증 가드의 구현은 동반 구현 스펙을 따른다. UI 페이지 크기는 20명이다(`docs/05-API-SPEC.md` §3).

## 범위와 흐름

새 `/people`은 인증된 현재 업무 조직의 조회 화면이다. 기존 AppShell·AppPage를 재사용하고 구현·검증된 “조직·인력” 링크 하나를 `/people`에 연결한다. 이 경로의 제목은 Topbar에서도 “조직·인력”이다. 기존 조직 slug 경로·계정 메뉴·인증 동작은 유지한다. 전체 N1 셸 전환, `/ops`·설정 재설계, 편집·추가·이동·퇴사·시뮬레이션·배정 기능은 이번 작업에 포함하지 않는다.

ADMIN·SALES·ANALYST·VIEWER 모두 같은 읽기 화면을 본다. 역할별 편집 버튼, 비활성 편집 메뉴, 편집용 빈 자리도 두지 않는다. 서버의 현재 조직 판단과 읽기 가드는 UI 노출과 별도로 적용한다.

진입 → 명부 → 이름 검색/필터 → 이름 버튼 또는 행 클릭 → 오른쪽 PersonDrawer → 닫기 후 원래 행으로 복귀한다. “조직도”로 전환하면 전체 조직과 소속 인력을 탐색하고, 사람 버튼으로 같은 서랍을 연다. 상세 전용 페이지는 만들지 않는다.

## 레이아웃과 보기 전환

- AppPage의 단일 `main#main-content`, `h1` “조직·인력”, 기존 `max-w-5xl`·데스크톱 `px-8`·`gap-6`를 사용한다. 별도의 중첩 main은 없다.
- 설명: “솔리데오 가상 인물 명부입니다. 점수 계산 대상 인력만 분석에 사용됩니다.” 바로 아래 `DEMO · 가상 인물` 텍스트 표시를 둔다. 숫자는 응답에서 얻은 `전체 N명 · 점수 계산 대상 M명`으로 표시한다. 현재 seed의 검증 기준은 N=200, M=27이다. 로딩·실패 중에 고정 숫자를 정상 응답처럼 노출하지 않는다.
- 보기 전환은 `명부` / `조직도` 링크 두 개다. 같은 경로의 `view=list|tree`를 사용하고 기본값은 명부다. SettingsNav와 같은 40px 링크 줄, `border-b`, 선택 링크의 2px `foreground` 밑줄, `aria-current="page"`를 쓴다. URL 이동이므로 ARIA tab 역할이나 신규 Tabs 라이브러리는 필요 없다. 화면에는 선택된 패널 하나만 렌더한다.
- 보기 전환은 검색·필터·페이지 파라미터를 보존한다. 조직도 패널에는 “전체 조직도 · 목록 검색 조건은 명부에만 적용됩니다”를 표시한다. 명부로 돌아오면 같은 조건과 페이지를 복원한다. 조직도에 필터된 수치와 전체 수치를 섞지 않는다.
- 1440px·1280px 모두 사이드바가 열린 상태에서 검증한다. 1280px에서 필터가 다음 줄로 흐르는 것은 허용하되 페이지 가로 스크롤은 생기지 않는다. 조직도를 폭 넓은 카드 연결 그래프로 만들지 않고 세로 목록으로 구성한다.

## 명부 패널

### 검색·필터·페이지

- 이름 검색 Input에는 보이는 Label “이름”, placeholder “이름 검색”을 둔다. 부서 Select “부서”, 직급 Select “직급/직책”, 대상 Select “점수 계산 대상”을 나란히 배치한다. 입력·Select 높이는 40px이다. `flex-wrap`, `gap-3`, 각 필드 `min-w-0`로 1280px에서 2줄 이내로 흐른다.
- 부서·직급 표시명은 카탈로그 값만 쓴다. 부서는 실제 직원 소속인 TEAM만 선택지로 제공하고 기본값은 “전체 부서”다. 본부·그룹 필터의 자손 확장 의미를 새로 만들지 않는다. 직급 기본값은 “전체 직급/직책”이다. 대상은 “전체” / “대상” / “비대상”이며 `scoring=1` 직접 링크를 지원한다. 상세 URL 값은 동반 구현 계약을 따른다.
- 이름 입력 뒤 “검색” 버튼 또는 Enter로 적용한다. Select 변경도 같은 폼의 검색으로 함께 적용해 사용자가 조건 묶음을 확인할 수 있게 한다. “초기화”는 outline/ghost로 두고 이름·부서·직급·대상·페이지를 초기화한다. 필터 적용 시 첫 페이지로 이동한다.
- 적용된 이름·부서·직급·대상·페이지는 URL이 정본이다. 새로고침·직접 링크·뒤로/앞으로 이동에서 폼과 결과가 URL에 일치한다. 입력 중인 이름은 적용 전까지 draft다. 잘못된 URL 값의 정규화 정책은 동반 스펙을 따르고 사용자에게 내부 ID나 오류 stack을 노출하지 않는다.
- 표 위 결과 문구: “검색 결과 N명”. 아래는 “전체 N명 중 A–B명”과 이전/다음 outline 버튼이다. 첫·마지막 페이지는 해당 버튼을 disabled 처리한다. 페이지당 20명이며 전체 200명을 순회할 수 있어야 한다. 서버가 제공한 opaque cursor를 URL과 방문 이력에 보존하여 다음/이전으로 이동하고 브라우저 뒤로/앞으로에서도 필터를 유지한다. 클라이언트가 cursor를 해석하거나 자체 생성하지 않는다. 필터 결과 0명일 때 A–B 범위는 표시하지 않는다.

### 표

기존 Table을 가는 border로 감싸고 열은 `사진+이름` / `부서` / `직급·직책` / `점수 계산 대상` 순이다. 첫 열 약 25%, 부서 약 35%, 직급 약 20%, 대상 약 20%로 배분한다. 헤더 40px, 행 최소 56px, 사진 32px, 본문 `type-body`, 머리글 `type-label`을 쓴다. 고정 픽셀 합계로 컨테이너 폭을 넘기지 않는다.

이름은 실제 button으로 만들어 Enter·Space로 서랍을 연다. 클릭 가능한 행은 포인터의 보조 진입점이며 행 자체에 별도 탭 정지를 추가하지 않는다. 버튼의 접근 가능한 이름은 “김민준 상세 보기”처럼 실제 이름을 포함한다. 부서 긴 이름은 줄바꿈하고 실제 확인된 부서명 전체를 유지한다. 숨긴 전체 이름을 hover에만 의존하지 않는다.

대상은 `점수 계산 대상`, 나머지는 `비대상`을 글자로 표시한다. 배지는 기존 토큰을 쓴 작은 테두리 텍스트 표시이며 색만으로 상태를 구분하지 않는다. 직원 UUID·성별·연락처·Auth 계정 연결을 표에 추가하지 않는다.

## 조직도 패널

### 정보 구조와 집계

조직도는 실제 `parentId` 연결만 따라가는 중첩 목록이다. 본부 → 그룹 → 팀은 허용 가능한 계층이지 모든 단계가 존재한다는 뜻이 아니다. 현재 확인된 TEAM→DIVISION 직결 13개에는 중간 그룹을 끼우지 않는다.

두 개의 명확한 구역을 둔다.

1. **본부**: 자연 루트인 `kind=DIVISION, parentId=null` 6개를 최상위에 놓는다. 본부 이름 오른쪽은 실제 소속 직원의 중복 제거 합계다. 현재 연결 확인된 팀 13개·직원 81명이다. null인 본부 부모는 정상이고 “상위 미지정” 표시를 붙이지 않는다.
2. **상위 미지정**: 설명 “자료에서 상위 부서가 확인되지 않은 부서입니다.”와 현재 `29개 부서 · 소속 인력 119명`을 표시한다. 안을 **그룹 4개**와 **팀 25개**로 구분한다. 이 그룹에는 연결된 팀이 없으므로 `소속 인력 0명 · 연결된 팀 없음`을 표시한다. 미지정 팀 25개를 그룹 아래 임의로 넣지 않는다.

위 구역 이름은 화면 분류 제목이며 DB 부서·departmentId·가짜 회사 루트로 저장하지 않는다. 상위 미지정은 정보 안내이며 warning/destructive 오류색을 쓰지 않는다. null parent와 null targetCount는 정상 상태다.

본부·그룹에는 목표 인원 칸을 만들지 않는다. 팀에는 “인력 N명”과 targetCount가 실제로 제공될 때만 “목표 N명”을 보조 텍스트로 표시한다. 상위 부서 수와 하위 부서 수를 합산해 총인원으로 삼지 않는다. 전체 총인원은 직원 ID 집합의 크기다.

### 펼치기와 사람 접근

- 구역 h2, 중첩 ul/li와 각 부서의 disclosure Button을 사용한다. 신규 ARIA tree 위젯은 만들지 않는다. 부서 행은 최소 40px, 깊이별 들여쓰기 24px, 세로 `border-border`로 구조를 보조한다. 표시 순서는 서버/카탈로그 순서를 유지한다.
- 초기에는 본부와 미지정 그룹/팀의 부서 행을 볼 수 있게 하고 직원 목록은 접는다. 부서 disclosure는 `aria-expanded`·`aria-controls`, ChevronRight/Down 16px를 갖는다. 자식이 없는 그룹은 비활성 화살표 대신 “연결된 팀 없음”을 표시한다.
- 팀을 펼치면 소속 사람 전원이 이름 Button+32px 사진+직급으로 나온다. 누락이나 중복 없이 200명이 각각 소속 팀 아래 정확히 한 번 존재해야 한다. 조상 본부/그룹에는 사람을 다시 나열하지 않는다. 접혀 있어도 접근 가능한 펼치기 경로가 있어야 한다.
- 사람 목록은 컨테이너 폭이 충분하면 2열, 부족하면 1열로 흐르고 긴 이름·부서명이 컨테이너를 밀지 않는다. “모두 펼치기” / “모두 접기” outline 버튼은 현재 패널의 disclosure만 제어한다. 트리 펼침 상태는 URL 필수 항목이 아니다.
- 표시 데이터는 목록의 현재 페이지만 재사용해서는 안 된다. 전체 조직·전체 명부를 충족하는 UI 입력이 필요하다. 부분 조회 중에는 “전체 200명”이나 부분 합계를 최종 조직도처럼 표시하지 않는다.

## PersonDrawer

기존 Sheet의 오른쪽 모달 패널을 사용한다. 데스크톱 폭 480px(`w-120`, 기존 max-width는 이 패널에서만 맞춤), 높이 뷰포트 이내, 내부 세로 스크롤, p-6를 적용한다. 제목은 SheetTitle, 설명은 SheetDescription으로 연결한다. 우측 상단 닫기 버튼을 항상 둔다.

- 머리: 사진 80px, 이름 `type-heading`, 부서·직급 `type-body`, `DEMO · 가상 인물`, 점수 계산 대상/비대상 표시.
- 기본 정보: 정의 목록(dl)의 “부서”, “직급/직책”. 확인된 상위 계층이 있으면 실제 경로만 보조 문구로 표시하고, 상위 미지정 팀에는 “상위 부서 미지정”을 표시한다.
- 점수 대상 27명은 “점수 계산 정보” 구역에 직무·등급·스킬·가용성을 표시한다. 직무는 점수 직무이며 `sol_role` 권한과 혼동하지 않는다. 스킬은 실제 문자열 목록, 등급 null은 “미등록”, 빈 스킬은 “등록된 스킬 없음”으로 표시한다.
- 가용성은 실제 항목의 시작일·종료일·FTE를 행으로 표시한다. `endsAt` 배타 여부 등 기간 의미는 점수 계약을 그대로 따르고 “종료일 미포함”처럼 필요한 설명을 붙인다. 제공되지 않은 총 가용률·추천·추정 역량·배정 정보를 계산해서 넣지 않는다. 가용성 배열이 비면 “등록된 가용성 정보 없음”이다.
- 비대상 173명의 detail.scoring은 null이다. 빈 직무·등급·스킬·가용성 표를 만들지 않고 “점수 계산 대상이 아닙니다”만 표시한다. fixture 운영 속성의 OTHER/빈 배열을 점수 정보처럼 보여주지 않는다.
- 상세는 직원 UUID `id`로 읽는다. 사진은 `personCode`(`SOL-P0001` 형식)로 기존 PersonAvatar의 `personId` prop에 전달한다. UUID를 demoPortraitPath에 넣지 않는다. 승인 PNG 200장과 manifest SHA는 보존하며 생성·수정하지 않는다.
- 현재 PersonAvatar의 사진 누락 fallback은 UserRound다. 요구된 이니셜 대체를 위해 이 공유 부품의 fallback을 이름 첫 글자로 조정한다. 사진 없는 경우·로딩 실패 모두 같은 크기 이니셜로 보이고 레이아웃이 흔들리지 않는다. `portraitUrl=null`은 실제 누락으로 존중하여 코드만으로 사진을 강제로 되살리지 않는다. 필요한 optional 입력의 구체 형태는 구현자가 기존 호출부와 맞춘다.

## 접근성과 토큰·부품 매핑

- h1 하나, 구역 h2, 폼의 보이는 Label, Table 헤더 scope, 결과 수 aria-live polite를 제공한다. Skeleton은 장식 처리하고 로딩 안내는 한 번만 읽힌다.
- 키보드 순서는 보기 링크 → 검색/필터 → 검색·초기화 → 이름 버튼 → 페이지 버튼이다. 조직도는 펼치기 버튼과 사람 버튼을 DOM 순서로 접근한다. 마우스 전용 상세 진입은 허용하지 않는다.
- Sheet를 열면 내부로 포커스가 이동하고 모달 내부에 갇힌다. Escape·닫기·바깥 클릭으로 닫을 수 있고 원래 이름 버튼으로 포커스를 돌려준다. 그 버튼이 제거되면 해당 패널 제목으로 이동한다. 브라우저 뒤로 이동/조건 변경으로 선택 직원이 사라지면 오래된 상세를 남기지 않는다.
- `background/card/popover`와 짝 foreground, 구분선 `border`, 보조 글자 `muted-foreground`, 폼 `input`, focus `ring`을 쓴다. DEMO는 흰 바탕 위 `text-demo`와 명시 텍스트다. 새 색·글꼴·토큰은 없다.
- `type-title/heading/body/label/caption`, 전역 Pretendard, 4/8/12/16/24px Tailwind 간격을 사용한다. 버튼은 기존 Button의 default/outline/ghost, 아이콘은 lucide 16px다. 검색을 유일한 default 버튼으로 하고 나머지는 낮춘다.
- AppShell·AppPage·Input·Label·Select·Button·Table·Skeleton·Sheet·PersonAvatar·AvatarFallback을 재사용한다. 기능별 조합은 로컬 UI 구성으로 만들며 새로운 공용 디자인 시스템 primitive·패키지는 추가하지 않는다.
- 색만으로 대상·오류·선택을 표현하지 않는다. 기본 focus-visible 표시를 유지하고 모션 감소 환경에서 서랍 전환 애니메이션을 줄인다.

## 구현·검증 인계와 열린 사항

UI가 필요한 입력은 현재 조직에서 읽은 부서/직급 이름 카탈로그, 전체 인원·대상 인원, 필터 결과·페이지 이동 정보, 조직도용 전체 소속 명부, 직원 상세다. 동반 스펙의 인증된 직급 카탈로그는 `id`(UUID)·`code`(SOL-J)·`label`, 부서는 UUID와 `code`(SOL-D)를 구분한다. 선택값·조회에는 UUID를 사용하고 화면 라벨에는 이름을 쓴다. 공개 가입 옵션의 코드를 인증된 조회 ID와 섞지 않는다. API 추가/변경이나 저장 구조는 여기서 설계하지 않는다. 오류 코드 정규화·URL 상세 값은 동반 구현 스펙을 따른다.

1280·1440px에서 목록·조직도·서랍·긴 텍스트가 가로로 넘치지 않는지, 키보드 복귀·Escape·axe 위반 0을 구현 후 검증한다. seed 기준은 200명/27명, 본부6·그룹4·팀38, 알려진 팀13/81명 + 미지정 팀25/119명, 미지정 부서 총29개다. 펼친 조직도에서 각 직원이 정확히 한 번만 나타나고 사진이 SOL-P 코드로 연결되어야 한다. 이 문서 작성 단계에서는 제품 코드 변경·브라우저 실행·테스트를 수행하지 않았다.

실제 확인된 차이는 기존 PersonAvatar의 아이콘 fallback과 요구된 이니셜 fallback이다. 또한 API 문서의 parentId null 일반 설명은 자연 본부 루트까지 미지정으로 묶을 수 있으므로 이번 승인 범위에 맞게 종류를 함께 판정한다. 두 항목 모두 위에 구체 동작을 정했으며 추가 사용자 승인이 필요한 디자인 질문은 없다.
