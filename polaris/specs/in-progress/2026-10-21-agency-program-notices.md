# 스펙: 부처 지원사업 공고 수집·목록 표시

- 최종 갱신: 2026-10-21
- 승인: 사용자가 2026-10-21 이 설계대로 진행하라고 승인했다("설계에서 정한 것대로 하고").
- 출처 표기: [사용자 결정] = 사용자가 마스터 세션(12) 대화에서 직접 정함. [12 판단] = 마스터 세션이 정함(사용자는 "결정이 필요한 것은 추천안대로" 위임). [작업자 몫] = 구현자가 정한다.

## 1. 목표

나라장터 입찰공고만 보는 지금의 공고 목록에, 정부 부처가 직접 올리는 지원사업 공고(중소벤처기업부 등)를 함께 보여 준다. 영업·분석 담당이 부처 사이트를 따로 돌지 않고 SOL RADAR 한곳에서 "놓친 사업 기회"를 본다. 10-23 freeze 전에 데모에 넣고 해커톤 발표에서 보여 준다. [사용자 결정]

## 2. 비목표

- 부처 공고의 AI 추출·점수·권고(BID/WATCH/NO-BID) 계산은 하지 않는다. [12 판단: 부처 공고에는 추정금액·참가자격이 없어 규칙 엔진을 쓸 수 없다]
- 부처 공고 알림(인앱·카카오·메일)은 하지 않는다. [12 판단] 메일 알림은 카카오 알림과 같은 채널 기능으로 별도 스펙에서 다룬다. [사용자 결정: 메일은 한다]
- 웹훅은 만들지 않는다. [사용자 결정]
- 기술 블로그(토스·네이버 D2)와 arXiv 는 넣지 않는다. [사용자 결정: 토스·네이버 제외. arXiv 는 12 판단, 사업 공고가 아니다]
- 과학기술정보통신부 직접 연결(RSS·API·HTML 긁기)은 하지 않는다. msit.go.kr 에서 RSS·API 를 찾지 못했다(후보 주소 3개 404, 2026-10-21 확인). 기업마당 API 에 과기정통부 사업이 실리면 그만큼만 들어온다. [12 판단]
- HTML 페이지 긁기(스크래핑)는 하지 않는다. [12 판단: 깨지기 쉽고 이용 조건이 불확실하다]
- 기존 나라장터 공고의 수집 저장 RPC(`ingest_save_revision`)·분석 job·`bid_list_items` 등 핵심 컷 코드 경로와 계약은 바꾸지 않는다(ADR-039 조건 ①). [12 판단]
- 모바일 레이아웃·결제·승률 표시는 하지 않는다(ADR-007).

## 4. 수집

- 새 소스 2개는 `infra/sources/registry.yaml` 에 넣지 않는다. 같은 폴더(Compose 가 worker 에 읽기 전용으로 붙이는 `infra/sources/`)에 새 설정 파일(예: `program-notices.yaml`)을 두고 자체 스키마로 검사한다. `registry.yaml` 과 그 검사(`web/server/ingestion/source-registry.ts`, 키 이름 `^G2B_..._SERVICE_KEY$` 고정)는 고치지 않는다. 새 설정 파일이 틀려도 나라장터 수집과 worker 기동은 막지 않는다(부처 소스만 끈다). [12 판단: 15 §8 데이터 계약을 바꾸지 않고(ADR-039 ①), sol-radar-30 이 고치는 `registry.yaml` 과 겹치지 않는다]
- 기업마당 요청 범위: 분야 `searchLclasId=02`(기술)만 받는다. 분야 목록은 설정 파일 값으로 바꿀 수 있다. 중기부 RSS 는 거르지 않는다. [12 판단: 조건 없이 받으면 지자체 소상공인·금융 공고가 목록을 채워 IT 회사의 "놓친 사업 기회" 장면이 약해진다]
- 새 Connector 는 기존 `OfficialApiConnector` 를 고치지 않고 따로 둔다(예: 기업마당 JSON connector, RSS/Atom connector). 이름·파일 배치는 [작업자 몫].
- 호출 대상 호스트는 `www.bizinfo.go.kr`·`mss.go.kr` 두 개로 고정한다(SSRF 방지 허용 목록, 09 보안). 리다이렉트로 다른 호스트로 가면 따르지 않는다. [12 판단]
- XML 파싱은 외부 엔티티(XXE)를 끈다. 제목·개요는 텍스트로만 저장하고 화면에서 HTML 로 해석하지 않는다. [12 판단]
- 주기: worker 반복 job, 기본 1시간(env 로 바꿈). 한 번에 기업마당은 최신 N건(기본 100), 중기부는 RSS 전체(20건). [12 판단: 호출 한도가 명세에 없어 보수적으로]
- 중복: 같은 소스 안에서는 소스별 고유 키(기업마당 `pblancId`, 중기부 `link` 의 게시물 번호)로 upsert 한다. 두 소스 사이 중복(중기부 공고가 기업마당에도 실림)은 정규화한 제목 + 소관기관이 같으면 같은 공고로 묶고 기업마당 쪽을 대표로 보여 준다(필드가 더 많다). 묶는 방법의 세부는 [작업자 몫], 단 묶지 못해도 두 줄로 보이는 것은 허용한다.
- 실패: 한 소스가 실패해도 다른 소스와 나라장터 수집에 영향이 없다. 실패는 기존 `ingest_runs` 와 같은 방식으로 남기되 기존 표의 계약을 바꿔야 하면 새 표로 둔다. [작업자 몫]

## 5. 저장

- 새 표(예: `program_notices`)에 둔다. `bids`·`bid_revisions` 를 재사용하지 않는다. [12 판단: 분석 트리거·계약 보호]
- 최소 항목: 소스 키, 소스 내부 ID, 제목, 소관기관, 원문 URL, 등록일, 신청 시작·마감(없으면 null), 사업개요(없으면 null), 신청방법(없으면 null), 지원대상(없으면 null), 분야·지역 태그(없으면 빈 배열), 수집 시각, `is_demo`.
- 문의처(`refrncNm`)는 저장하지 않는다. 사업개요·신청방법·지원대상은 저장 전에 전화·이메일 패턴을 가린다. 원본 응답 전체는 DB 에 넣지 않는다. [09 보안: live 실제 공고도 담당자 개인정보 필드는 DB 에 넣지 않는다]
- `is_demo` 값과 `/bids` 출처(live·demo) 구분은 녹음한 나라장터 응답의 기존 관례를 따른다. [작업자 몫]
- 공개 공고라 조직 데이터가 아니다. 읽기 권한은 지금 `bids` 의 읽기 정책과 같은 대상에게 연다. 쓰기는 worker(service role)만. 표는 만들자마자 RLS 로 잠그고 `scripts/database.test.mjs` 에 정책 시험을 더한다.
- 마이그레이션 번호는 그 시점 main 의 최대 번호보다 크게 붙인다(3e 규칙). 시작 번호대는 `20261021000500`~ 이다(dc 0001·S5 0100·N9 0200·N2 0300·P0-8 0400 다음). [12 판단, 3e 에 알림] 10-21 12 가 대역을 다시 나눠 `20261023000800`~ 로 옮겼다(클라우드에 먼저 적용된 `000600` 뒤, 카카오 0601~·N2 0610~·S5 0620~·P0-8 0640~). 생성 타입(`pnpm db:types`)을 같은 커밋에 넣는다.

## 6. 화면 [사용자 결정: "공고 목록에 뿌려 준다"]

- 위치: 기존 공고 목록 화면 `/bids` 안에 "나라장터 공고 | 부처 지원사업" 전환(탭 또는 구분 버튼)을 더하고, 부처 지원사업 쪽은 새 Route Handler·새 조회로 그린다. [12 판단: 나라장터 목록과 한 표에 섞으려면 핵심 컷 목록 조회(`bid_list_items`·`/api/v1/bids`)를 고쳐야 해서 ADR-039 ① 에 걸린다. 사용자가 한 표에 섞기를 원하면 freeze 뒤로 미루고 다시 정한다]
- 부처 지원사업 목록 열: 출처(기업마당·중기부 배지), 공고명, 소관기관, 신청 마감(없으면 "기간 미표기"), 등록일. 정렬: 마감 빠른 순(기본, null 은 뒤로)·등록일 최신 순. 필터: 출처, 소관기관 검색어. 점수·권고 열은 두지 않는다.
- 마감이 지난 공고는 기본으로 숨기고 "마감 지난 공고 포함" 토글로 보인다. 마감이 null 인 공고는 늘 보인다. [12 판단]
- 행을 누르면 간단한 상세(서랍 또는 페이지, [작업자 몫])에서 사업개요·신청방법·지원대상·태그와 "문의처는 원문에서 확인" 안내, "원문 보기"(새 창, `rel="noopener noreferrer"`)를 보여 준다. 분석·결정 기록 버튼은 없다.
- 화면 확인은 1440·1280 두 폭. 디자인은 `design/tokens.json`·기존 `BidTable` 관례를 따르고, 새 화면 요소는 web-designer 스펙을 먼저 받는다.

## 7. 데모

- 데모는 인터넷이 없어도 돌아야 한다. 두 소스의 응답을 녹음해(`fixtures/recorded/<소스>/…`, 담당자 연락처 등 개인정보는 가림) mock·fixture 모드에서 그 녹음으로 표를 채운다. live 모드에서만 실호출한다. [12 판단]
- 녹음은 사용자가 키를 넣은 뒤 1회 실호출로 만든다. 키가 늦으면 중기부 RSS 녹음만으로 먼저 데모를 만든다.
- 19 데모 시나리오에 짧은 장면 하나를 더한다(공고 목록 → "부처 지원사업" 전환 → 중기부·기업마당 공고 몇 건 → 원문 보기). 발표 대본 문장은 45·제출물 담당과 맞춘다.

## 8. 완료의 정의

1. 단위 시험: 두 응답 형식의 정규화(기업마당 JSON 샘플, 중기부 RSS 샘플 — `pubDate` `YYYYMMDDHHMMSS` 파싱 포함), 키 마스킹, 허용 호스트 밖 요청 거부, XXE 차단. `pnpm -C web exec vitest run` 해당 파일 통과.
2. DB 정책 시험: 새 표 읽기 허용·비로그인 거부·일반 사용자 쓰기 거부. `pnpm test:db` 통과.
3. worker: mock/fixture 모드에서 녹음으로 적재, 키 없음이면 기업마당 건너뜀, 한 소스 실패가 다른 소스를 막지 않음. 시험으로 고정.
4. 화면: 격리 스택 E2E 1개 이상(전환 → 목록 N건 → 상세 → 원문 링크 속성). 1440·1280 스크린샷을 `docs/evidence/` 에.
5. `pnpm verify` 통과(3e 의 verify-slot.sh 로 감싼다). 3e 게이트 병합.
6. 정본 반영(45 와 절 목록 합의): 07 수집(새 connector·주기·허용 호스트), 15 데이터 계약(새 정규화 형태·registry 항목), 04 DB(새 표·RLS), 05 API(새 Route Handler), 06 화면(`/bids` 전환·목록·상세), 09 보안(키 마스킹·SSRF·XXE), 10 배포(`BIZINFO_API_KEY` env), 12 로드맵·16 ADR(새 ADR: 확장 컷 추가, ADR-039 조건 적용), 19 데모 장면, PROGRESS.

## 9. 엣지 케이스

- 기업마당 키 없음·만료·오류 응답: 기업마당만 건너뛰고 `ingest_runs` 계열 기록에 원인 코드를 남긴다. 화면은 중기부 공고만 보인다.
- 중기부 RSS 형식 변경(날짜 형식·항목 이름): 파싱 실패 항목은 버리고 실패 건수를 남긴다. 전체 실패면 마지막 성공 데이터를 그대로 보여 준다.
- 신청기간이 없거나 "상시" 같은 문자열: 마감 null 로 저장하고 "기간 미표기"로 보인다.
- 같은 공고가 내용만 바뀌어 다시 올라옴: 소스 내부 ID 로 덮어쓴다(이력 비교는 하지 않는다).
- 응답이 아주 큼(`searchCnt` 0 = 전체): 기본값은 100 건으로 제한한다.

## 미결정 사항

- 한 표에 섞기(나라장터 + 부처)는 freeze 뒤 사용자가 원하면 다시 정한다. 지금은 전환 방식이다.
