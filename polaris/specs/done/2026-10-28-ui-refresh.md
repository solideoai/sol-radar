# 화면 UI 전체 개편 — 파스텔 선택색·묶음 사이드바·랜딩 영상과 로고 줄

사용자 요청(2026-10-28): "이제 화면 UI를 전체적으로 고칠 건데, `web/public/reference/ui.png` 에 대시보드 레퍼런스 UI 직접 캡처해서 뒀고, 랜딩페이지는 https://granter.biz/ 처럼 동영상이 들어가고, https://www.solideos.com/portal/govSM.do 여기에 우리 회사(솔리데오)가 대표적으로 수행하는 서비스들이 granter 사이트처럼 옆으로 무한 스크롤되면 좋겠고, 내가 가져오는 나라장터, 한국주택공사 등 API 들도 SOL RADAR가 가져오는 정보라고 해서 옆으로 로고들이 그거도 무한 스크롤 됐으면 좋겠어." 쉬는 작업자 4개(df·0f·ac·09)에게 나눠 맡긴다.

## 1. 왜 하는가

- 사용자가 레퍼런스(granter User Guide 캡처)에서 좋다고 한 점: "UI가 전체적으로 깔끔하고, 사이드바를 눌렀을 때 파스텔톤이고, 아이콘이 심플하고 깔끔함. 색감이 좋음."
- 지금 앱은 회색 위주다. 선택 메뉴도 연회색 바탕(`sidebar-accent` #EDEFF2)이라 어디에 있는지 덜 보인다.
- 랜딩에는 움직이는 제품 화면과 신뢰 근거(솔리데오가 만든 공공 서비스, 실제 데이터 출처)가 없다.

성공한 모습: 심사위원이 랜딩에서 20초 영상으로 제품을 보고, 솔리데오 수행 서비스와 데이터 출처 로고가 흐르는 줄로 "실제 공공 데이터를 다루는 회사의 제품"임을 안다. 로그인 뒤 모든 업무 화면이 같은 깔끔한 틀(파스텔 선택색·경로 표시·큰 제목·구분선·연한 머리 줄 표)로 보인다.

## 3. 목표 · 하지 않을 것 · 실패로 보는 것

목표

1. 색: 선택·강조는 브랜드 파랑(#1B64DA) 하나, 선택 바탕은 그 파랑의 연한 색(파스텔)이다.
2. 앱 틀: U2 사이드바, 모든 업무 화면 머리에 경로 표시(묶음 / 화면) + 큰 제목 + 1px 구분선.
3. 본문: 표 머리 줄 연한 바탕·둥근 1px 테두리, 회색 칩, 넉넉한 여백. 업무 화면 전부에 같은 규칙.
4. 랜딩: 히어로 아래 녹화 영상, 그 아래 흐르는 줄 둘(솔리데오 수행 서비스, 데이터 출처 로고).

하지 않을 것

- 서버·DB·API·계산·문구의 뜻을 바꾸지 않는다. 고지 문구("수주 확률이 아닙니다", 담당자 결정, 예시 데이터 표시), 데이터 출처 표시, 앵커·경로·권한은 그대로다.
- 모바일(1280px 미만) 배치, 결제 화면. 화면 확인은 1440·1280 두 폭.
- 새 차트 라이브러리·애니메이션 라이브러리 설치. 흐르는 줄은 CSS 만으로 만든다.

실패로 보는 것(기술적으로 돌아가도)

- 연결 전 기관 로고가 지금 데이터를 가져오는 곳처럼 보인다.
- 녹화 영상이 실제 분석 결과가 아닌 값을 실제처럼 보인다(가상 데이터면 화면의 DEMO·(가상) 표시가 영상에 그대로 보여야 한다).
- 금지어(승률·확률·가능성·수주 금액·점유율·경쟁사·%)가 새 문구에 들어간다.
- 발표 촬영(덱 클립) 경로의 화면이 깨지거나 촬영 직전까지 계속 바뀐다.

## 4. 설계

### 4.1 색 토큰 (`design/tokens.json` 만 고치고 `pnpm tokens`)

- `sidebar-accent` → 브랜드 파랑의 연한 색(시안 값 `#EAF2FE`), `sidebar-accent-foreground` → `brand`(#1B64DA). 대비 4.5:1 이상인지 확인해 값을 정한다.
- 같은 연한 파랑을 본문 선택 상태(보기 전환·탭·거르기 칩의 켜짐)에도 쓸지는 W1 이 토큰 하나로 정해 전 화면에 같은 규칙을 적용한다(45 판단: 쓴다, 이름은 `accent` 계열 재사용 또는 새 토큰 1개).
- `brand`·`primary`·상태색·`source-*`·`demo` 값은 바꾸지 않는다.

### 4.2 사이드바 (`web/components/app-shell.tsx`, `app-nav.ts`)

- 묶음 머리: 아이콘 + 굵은 묶음 이름 + 접기 표시(⌄). 접기는 지금 동작(`aria-expanded`·`aria-controls`·브라우저 `localStorage`, 지금 화면의 묶음은 펼침)을 유지한다.
- 하위 메뉴: 아이콘 없이 글자만, 묶음 아이콘 폭만큼 들여 쓴다. 선택 메뉴는 연한 파랑 바탕 + 파란 글자 + 굵기 600 + `aria-current="page"`.
- 묶음 아이콘(45 판단, W1 이 lucide 에서 고름): 업무 = 서류가방, 분석 = 막대 차트, 회사 = 건물.
- 접은 64px 아이콘 줄(2026-10-26 결정 S1)은 유지한다. 접었을 때만 메뉴별 아이콘 + 이름 툴팁을 보인다(메뉴별 아이콘은 `app-nav.ts` 에 그대로 둔다).
- 트리 세로선은 없앤다. 글자 +3px 예외(ADR-030 B26), 역할별 메뉴 거르기, 알림 배지, 아래 고정 칸(설정·데이터 수집 관리·사용자 칸), 로고는 그대로다.
- 이력 주의: 2026-10-26 에 "펼친 상태 글자만"을 사용자가 화면을 본 뒤 되돌린 적이 있다(design-declutter 후속 변경). 이번 U2 는 묶음 머리 아이콘을 두는 다른 모양이고 시안으로 골랐다. W1 은 첫 결과 스크린샷을 45 에 먼저 보내고, 45 가 사용자 확인을 받은 뒤 다른 작업자가 본문을 맞춘다.

### 4.3 본문 공통 (`web/components/app-page.tsx`, `web/components/ui/*`)

- `AppPage` 머리: 경로 표시(묶음 이름 / 화면 이름, 회색 작은 글자) → 큰 제목 → 설명 → 1px 구분선. 경로의 묶음 이름은 `app-nav.ts` 에서 찾는다(없는 화면은 경로 줄 없음). 주요 버튼 자리(`actions`)는 그대로.
- 표(`ui/table.tsx`): 머리 줄 연한 회색 바탕(#F9FAFB 근처 토큰), 바깥 둥근 1px 테두리, 행 구분선.
- 칩·배지: 회색 바탕 칩(`secondary`), 강조 배지는 파란 1px 테두리 + 파란 글자. 기존 상태색 배지(충족·확인 필요·미충족, 추천(`BID`)·보류(`WATCH`)·비추천(`NO_BID`))는 의미 색 그대로.
- 카드 상자·그림자를 겹쳐 쓰지 않는다는 2026-10-26 원칙(1px 선과 여백)은 유지한다.
- 위 막대(`AppTopBar`, 45 판단): 화면 이름은 본문 경로·제목으로 옮기고 위 막대에서는 뺀다(한 화면에 같은 이름이 세 번 나오지 않게). 사이드바를 접었을 때 조직 이름(다른 조직에 잘못 추가하는 일을 막는 장치)·수집 상태·알림 종은 그대로 둔다.

### 4.4 업무 화면 본문

4.3 규칙을 화면마다 적용하고 화면 고유의 어색한 곳을 다듬는다. 데이터·문구·흐름은 바꾸지 않는다. 대상 경로:

- 업무: `/dashboard`, `/bids`, `/bids/[id]`(+`revisions`), `/bids/programs`, `/watchlist`, `/projects`, `/projects/[id]`, `/calendar`, `/notifications`
- 분석: `/gaps`, `/market`, `/analysis`, `/workforce`
- 회사: `/company`, `/people`, `/org-chart`
- 아래 고정·기타: `/settings`·`/memos`(실제 화면은 `[slug]/settings`·`[slug]/tasks` 로 넘어감), `/settings/organization`, `/admin/ingestion`
- 로그인·가입(`/auth/*`)은 색 토큰 변화만 따라가고 배치는 바꾸지 않는다(45 판단).

### 4.5 랜딩 (`web/app/page.tsx`, `web/components/landing/*`)

순서: 머리말 → 히어로(가운데 정렬 유지, 문구 그대로) → **녹화 영상** → **솔리데오 수행 서비스 줄** → **데이터 출처 로고 줄** → 기존 구역(분석 예시·문제·기능·3단계·원칙·FAQ·마지막 안내)을 새 색 규칙으로 다듬어 유지.

영상

- `<video autoplay muted loop playsinline preload="metadata" poster=…>`, webm + mp4 두 형식, 합계 4MB 이하, 15~30초, 1440 기준 16:9 근처. 소리 없음.
- 내용: 입찰 공고 목록 → 자격 갭 레이더 → 입찰 일정이 채워지는 장면(U3·U7). D1 운영 사이트에서 녹화하고, 로그인은 사용자가 녹화 브라우저에서 직접 한다. 비밀번호를 스크립트·파일에 넣지 않는다. 회사 역량·조직·인력 화면은 찍지 않는다. 화면에 DEMO 표시가 있으면 영상에 그대로 남긴다.
- `prefers-reduced-motion` 이면 자동 재생하지 않고 포스터 + 재생 버튼.
- 파일은 `web/public/landing/` 아래. 래스터 이미지는 `next/image` 최적화 경로가 Vercel 운영에서 404 이므로(2026-10-28 로고 사고, `679dc3c8`) `unoptimized` 로 두거나 `<img>` 를 쓴다.
- 녹화 방법은 W4 가 정한다(Playwright headed + `recordVideo` 로 사용자가 로그인한 뒤 스크립트가 이동, `ffmpeg` 자르기·변환, `ffmpeg` 은 로컬에 있음). 운영 화면을 찍으므로 녹화는 새 UI 가 운영에 배포된 뒤에 한다(6절).
- 영상 파일이 들어오기 전(1차 배포)에는 영상 구역을 그리지 않는다(45 판단: 새 UI 운영 화면이 없으면 포스터도 만들 수 없다). 영상·포스터를 넣는 2차 배포에서 구역이 생긴다.
- 지금 랜딩 E2E 의 "1440×900·1280×800 첫 화면에서 스크롤 없이 점수와 수주 확률 고지가 보인다"는 분석 예시가 히어로 바로 아래라는 전제다. 영상·흐르는 줄이 그 사이에 들어오므로(사용자가 승인한 순서) 이 시험은 "분석 예시 보기를 눌러 미리보기로 가면 점수와 고지가 함께 화면 안에 보인다"로 바꾼다(45 판단). 지키려던 것(점수가 고지 없이 보이지 않음)은 그대로 단언한다.

흐르는 줄 공통

- CSS 만: 목록을 두 번 이어 붙이고 `translateX(-50%)` 반복. 둘째 사본은 `aria-hidden`. 마우스를 올리거나 키보드 포커스가 들어오면 멈춤. `prefers-reduced-motion` 이면 멈춘 줄(가로 스크롤 없이 줄바꿈).
- 양 끝은 흐려지는 마스크. 줄 위에 작은 회색 제목 한 줄.

솔리데오 수행 서비스 줄 — 제목 "솔리데오가 수행한 공공 서비스"(45 판단: 사용자 표현 "대표적으로 수행하는 서비스"를 따른다. 서비스마다 구축인지 유지보수인지 확인하지 않았으므로 "구축·운영"이라 쓰지 않는다)

- 이미지는 그 페이지의 서비스 이미지를 받아 webp 로 줄여 `web/public/landing/services/` 에 둔다(사용자 회사 자료). 카드 아래 서비스 이름 글자.

- 후보 9곳(45 판단으로 정리): 나라장터(조달청), LH(한국토지주택공사), K-water(한국수자원공사), 한국전력공사, 기업마당, 중소벤처기업부(부처 지원사업 공고, `infra/sources/program-notices.yaml`), 한국도로공사, 국방전자조달, 한국철도공사.
  - 공공데이터포털은 넣지 않는다. 나라장터·K-water 등이 거쳐 오는 창구라 따로 넣으면 같은 출처를 두 번 센다(45 판단).
  - 한국도로공사·국방전자조달·한국철도공사는 코드 연결이 없으므로 늘 "연결 예정"이다.
- **U8 로 바뀜:** 아래 "연결됨/연결 예정" 두 줄은 지난 결정이다. 지금은 9곳 로고만 같은 모양으로 보이고, 연결 상태는 코드가 아니라 `docs/plans/2026-10-28-landing-sources-to-connect.md` 가 관리한다. 로고가 없던 3곳은 공식 누리집이 게시한 로고 파일을 쓴다.
- (지난 결정) "연결됨"(꼬리표 없음) 기준은 **운영 실제 수집**이다(U6). 나머지는 점선 테두리·흐린 표시·"연결 예정" 꼬리표(U5).
  - W4 는 기관마다 `status: "collecting" | "planned"` 를 가진 목록 하나(`web/components/landing/` 안 상수)로 만들고, 화면은 그 값만 따른다.
  - 배포 날 45 가 운영 수집 상태를 확인해 값을 정한다. 확인 방법은 운영 DB 읽기 SELECT(출처별 최근 7일 새 공고 수)이며, 실행 전에 사용자 승인을 받는다. 확인 전 기본값은 나라장터만 `collecting` 이다.
- 로고는 각 기관 공식 CI 안내 페이지의 파일을 받아 `web/public/landing/sources/` 에 둔다(svg 우선). 기본은 회색조, 마우스를 올리면 원래 색(45 판단).
- 줄 아래 작은 글자(45 판단): "기관 로고는 공고 데이터 출처 표시이며 제휴·인증을 뜻하지 않습니다."

## 7. 수용 기준

1. 사이드바가 U2 모양이고, 모든 메뉴를 키보드로 갈 수 있으며, 지금 화면에 `aria-current="page"` 가 있다. 접기·64px 아이콘 줄·역할별 노출이 지금과 같다.
2. 4.4 의 모든 화면이 4.3 머리(경로·큰 제목·구분선)와 표 규칙을 따른다. 보이는 값·문구는 바꾸기 전과 같다.
3. 랜딩: 영상이 자동 재생(소리 없음·반복)되고 `prefers-reduced-motion` 에서 멈춘다. 흐르는 줄 둘이 돌고, 마우스·포커스에 멈춘다. 출처 줄은 9곳 로고만 있고 "연결 예정" 글자가 없다(U8). 11-02 에 연결 안 된 곳이 남으면 사용자가 그 로고를 뺄지 정한다. 고지 문구·앵커·계정 경로는 그대로다.
4. 1440·1280 스크린샷(4.4 전 화면 + 랜딩 전체)에서 가로 넘침·잘림이 없다. 증거 `docs/evidence/ui-refresh/`.
5. 개발 중 `pnpm verify:changed`, 통합 전 전체 `pnpm verify`, 랜딩 E2E, 바뀐 화면의 브라우저 시험이 통과한다. 단언을 약하게 바꾸지 않는다.
6. 운영 배포 뒤 비로그인 랜딩에서 영상·이미지·로고가 모두 200 으로 뜬다(`next/image` 404 재발 없음).

## 8. 남은 것 — 짓는 사람이 정한다

- 연한 파랑의 정확한 값, 표 머리 회색 값, 여백 수치(대비 기준 안에서).
- 화면별 다듬기의 세부(4.3 규칙 안).
- 녹화 도구·자르는 구간·해상도.
- 흐르는 줄 속도(시안 28초 한 바퀴), 카드 크기.
