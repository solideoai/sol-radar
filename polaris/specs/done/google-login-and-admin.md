# 스펙: 구글 로그인 버튼과 관리자 화면

- 최종 갱신: 2026-10-15 (구현 뒤 차이 반영)

## 1. 목표

SaaS 기본 뼈대에서 빠진 두 가지를 더한다. 이메일·비밀번호 로그인 옆에 구글 로그인을 붙이고(설정한 프로젝트에서만 보인다),
운영자(`profiles.is_admin`)가 가입한 사용자를 보는 관리자 화면을 둔다. [사용자 결정]

## 2. 비목표

- 구글 외의 OAuth 제공자, 앱(mobile)의 구글 로그인. [사용자 결정: "구글 로그인 버튼만"]
- 구글 계정 이름으로 표시 이름 채우기(가입 트리거 수정). [제안 후 승인]
- 관리자의 조직·작업·활동 열람. "운영자도 남의 조직은 못 읽는다" 원칙을 바꾸지 않는다. [사용자 결정]
- 관리자의 쓰기(운영자 지정·계정 정지·삭제). 화면은 읽기 전용이다. [사용자 결정]

## 3. 완료의 정의

1. **구글 버튼** — `NEXT_PUBLIC_AUTH_GOOGLE=true` 로 빌드하면 로그인·가입 화면에 "Google 로 계속하기"가 보이고, 없으면 보이지 않는다.
   누르면 Supabase 의 구글 인증 주소로 간다(로컬에서 브라우저로 확인). [사용자 결정]
2. **돌아오는 주소** — `/auth/callback` 이 코드를 세션으로 바꿔 `next`(사이트 안 경로만, 없으면 `/auth/login`)로 보내고, 실패하면 계정 화면에 안내를 보인다.
   웹 단위 시험으로 확인한다(성공·코드 없음·제공자 오류·교환 실패·바깥 주소 next). [제안 후 승인]
3. **설정법** — `supabase/config.toml` 에 구글 설정 자리(주석)를 두고, 클라우드·로컬 설정법을 docs 에 적는다. [제안 후 승인]
4. **관리자 화면** — 로그인 E2E(`pnpm -C web test:e2e:auth`)에서 시드 운영자는 `/admin` 의 사용자 목록·검색·쪽을 보고,
   운영자가 아닌 시드 계정과 로그아웃한 사람에게 `/admin` 은 404 다. 운영자에게만 메뉴에 관리자 링크가 보인다. [사용자 결정]
5. **전체 검증** — `pnpm verify`, `pnpm -C web test:e2e`, `pnpm -C web test:e2e:auth` 가 통과하고, 375·1280px 에서 화면을 직접 본다. [제안 후 승인]

## 4. 인터페이스 계약

### 4.1 구글 로그인 [제안 후 승인]

- 버튼은 브라우저 클라이언트의 `signInWithOAuth({ provider: "google", options: { redirectTo: <사이트>/auth/callback } })` 를 부른다.
- `/auth/callback?code=…&next=…` → 코드 교환 성공이면 `next`, 실패면 `/auth/login?link=oauth-failed`. 계정 화면은 그 경우 "구글 로그인을 마치지 못했습니다" 안내를 보인다.
- 처음 구글로 들어온 사람도 가입 트리거가 프로필과 개인 조직을 만든다(이메일 가입과 같다).

### 4.2 관리자 화면 [사용자 결정]

- 주소 `/admin`(조직 주소 예약어에 이미 있다). 운영자가 아니거나 로그인 전이면 404(있는지 알리지 않는다).
- 사용자 목록: 이메일·표시 이름·가입일·운영자 여부. 이메일·이름 검색, 20개씩 서버 쪽 나눔, 조건은 URL 쿼리.
- 데이터는 기존 정책 "운영자는 전체 프로필 읽기"로만 읽는다. 새 정책·마이그레이션은 없다.
- 시드에 운영자 계정을 하나 더한다(`is_admin` 은 관리 키로만 켠다).

## 5. 엣지 케이스와 실패 시나리오

- 구글 설정 없이 플래그만 켬 → 버튼을 누르면 Supabase 가 자기 주소에서 오류(JSON, "provider is not enabled")를 보이고 사이트로 돌아오지 않는다. 그래서 설정 전에는 플래그를 켜지 않는다(.env 예시·문서에 적음). 구글이 오류로 돌려보내면(`/auth/callback?error=…`) 계정 화면이 실패 안내를 보인다. [구현에서 확인]
- 콜백의 `next` 가 바깥 주소 → `/account` 로 바꾼다(메일 링크와 같은 규칙). [제안 후 승인]
- 운영자가 자기 화면을 보는 사이 운영자에서 빠짐 → 다음 요청부터 404. [제안 후 승인]
- 검색어에 `%`·`,` 같은 특수 글자 → 글자 그대로 찾는다(질의 문법으로 해석하지 않는다). [제안 후 승인]

## 구현 메모

- 2026-10-15 사용자 요청으로 구글 버튼의 모양·위치를 참고 화면(app.edgelink.me/auth/login)에 맞췄다: 이메일 폼과 링크 아래 가는 선 뒤, 높이 36px 테두리 버튼, 브랜드 색 G 로고(`web/public/google.svg`, 24px), "구글 계정으로 로그인"(가입은 "구글 계정으로 시작하기"). 같은 요청으로 계정 화면 주소를 `/auth/login`·`/auth/sign-up`·`/auth/reset`·`/auth/password` 로 옮기고 옛 `/account…` 는 308 로 넘긴다(`web/next.config.ts`). [사용자 결정]

- 관리자 도메인은 `web/server/admin`(profile 에 더하지 않음). 404 는 틀(`web/app/admin/layout.tsx`)에서 낸다 — loading.tsx 가 있으면 화면에서 낸 404 는 200 으로 굳는다. 화면도 다시 확인한다.
- 검색은 PostgREST `imatch`(대소문자 무시 정규식)에 문장 부호를 이스케이프해 넘긴다. 로컬 PostgREST 의 `ilike` 는 `*` 를 늘 `%` 로 바꿔 글자 그대로 찾을 수 없다.
- 관리자 목록의 쪽 줄은 쪽이 하나여도 보인다("1 / 1쪽"). 쪽 줄 부품은 작업 목록과 같이 쓴다(`web/components/pagination.tsx`).

- 2026-10-15 사용자 요청으로 카카오·네이버 로그인 버튼을 구글 아래에 더했다. 모양은 각 회사 버튼 가이드(카카오 #FEE500·검은 말풍선·"카카오 로그인"·글자 검정 85%, 네이버 #03A94D·흰 N 16px·간격 8px)를 따르고, 높이·모서리는 국내 서비스들(와디즈·무신사·29cm)처럼 이메일 폼 버튼과 맞췄다. 카카오는 Supabase 기본 제공자 `kakao`, 네이버는 사용자 정의 제공자 `custom:naver` 다. 네이버 사용자 정보(`response` 아래 한 겹)를 Supabase 가 읽는지는 실제 키로 확인하지 못했다. [사용자 결정]
