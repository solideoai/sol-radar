사이드바는 768px 이상에서 붙박이(256px), 미만에서 서랍이다. 본문 여백은 `px-4`·`sm:px-6`·`lg:px-8`.

칸 나눔은 화면 폭이 아니라 단·카드 폭(`@container`)으로 정한다. 쓰는 눈금: `@md` 448 · `@lg` 512 · `@xl` 576 · `@2xl` 672 · `@3xl` 768 · `@4xl` 896.

### 1.3 한계

로그인 뒤 화면을 브라우저로 보지 않았다. 같은 폴더에서 다른 작업자가 동시에 일하고 있어 개발 서버를 띄우지 않았고, 기존 화면의 구조·수치는 위 코드에서 읽었다.
차트 색은 dataviz 검증기(`validate_palette.js`, 밝은 모드·흰 바탕)로 쟀다. 구현 뒤 QA 가 320·375·768·1280px 에서 직접 확인한다.

## 2. 흐름

### F1. 작업 추가

1. `/<slug>/tasks` → 머리의 "작업 추가"(작업이 하나도 없으면 빈 상태의 "첫 작업 추가") → 추가 대화상자.
2. 제목(필수)·설명·담당자·마감일 → "추가".
   - 성공: 대화상자가 닫히고 토스트 "작업을 추가했습니다". 기본 조건이면 표 맨 위에 새 줄. 초점은 "작업 추가" 단추로 돌아간다(빈 상태에서 열었으면 단추가 사라지므로 표 제목 "작업 목록"으로).
   - 거르기·정렬·쪽이 기본이 아니면 새 줄이 지금 쪽에 안 보일 수 있다. 조건은 그대로 둔다(사용자가 고른 조건을 몰래 바꾸지 않는다).
   - 입력 오류: 칸 아래 오류, 입력값 남음. 담당자가 그새 팀을 떠났으면 담당자 칸 오류(3.2.8).
   - 취소·Esc: 입력을 버리고 닫는다(묻지 않는다, Q7).

### F2. 작업 편집

줄의 제목(단추) 또는 "⋯" → "편집" → 편집 대화상자(값이 채워져 있다) → "저장".
성공: 닫힘, 토스트 "작업을 저장했습니다", 초점은 연 단추로. 지금 조건에서 그 줄이 빠지면(예: "할 일"만 보는 중에 완료로 바꿈) 초점은 "작업 목록" 제목으로.
그새 지워졌으면 대화상자 안 오류 + 목록 새로 그림(3.2.8).

### F3. 상태 바꾸기 (D2-1)

상태 칸의 단추 → 메뉴(할 일·진행 중·완료) → 고르면 바로 저장. 그 줄의 상태 단추는 저장이 끝날 때까지 비활성. 토스트 "상태를 완료로 바꿨습니다".
완료로 바꾸면 DB 가 완료 시각을 채우고 활동 "완료함"이 남는다. 완료에서 되돌리면 "다시 엶"이 남는다(스펙 4.3). 할 일 ↔ 진행 중은 기록이 남지 않는다.

### F4. 삭제

"⋯" → "삭제"(만든 사람·소유자에게만 보인다) → 확인 대화상자 → "삭제". 성공: 줄이 사라지고 토스트 "작업을 삭제했습니다", 초점은 "작업 목록" 제목으로.

### F5. 거르기·정렬·쪽

상태·담당자·정렬 Select 를 바꾸면 주소의 쿼리가 바뀌고(쪽은 1로 돌아간다) 서버가 다시 읽는다. 이전·다음 링크는 쪽만 바꾼다. 주소를 복사해 열면 같은 조건이 보인다.
뒤로 가기는 이전 조건으로 간다.

### F6. 대시보드 보기

`/<slug>/dashboard` → 카드 4개 → 최근 14일 차트 → 기한이 가까운 작업 5개 → 최근 활동 10개. "모두 보기" → `/<slug>/tasks?sort=due`.

### F7. 거절

- 고치는 사이 작업이 지워짐: 동작이 실패하고 문구 + 목록 새로 그림(스펙 5).
- 내가 조직에서 빠짐: 동작이 실패하고 오류 토스트 → 화면을 새로 그리면 404(조직 견본과 같다). 대화상자 안 문구는 404 로 바뀌며 사라지므로 토스트로 알린다(2026-10-14 사용자 결정).
- 삭제 권한이 사라짐(그새 소유자에서 멤버로): 문구 + 새로 그림 → 삭제 항목이 사라진다.
- 다른 조직 사람을 담당자로: DB 가 거절하고 담당자 칸에 "이 팀의 멤버가 아닙니다"(스펙 5).

### F8. 멤버가 떠남

owner 가 내보내거나 멤버가 나가면 그 사람이 맡던 작업의 담당자가 빈다(스펙 3.1). 작업 표에 "없음"으로 보이고, 피드에는 "나감"·"내보냄" 한 줄만 남는다(미결정 기본안).
멤버 화면의 내보내기·나가기 설명에 이 일을 미리 알린다(4절).

### F9. 옛 주소

`/memos` → 개인 조직의 `/<slug>/tasks`(스펙 4.4). `/<slug>/memos` 는 없어져 404 다.

## 3. 화면별 명세

### 3.1 사이드바

- `app-shell.tsx` 의 `NAV`: 대시보드(`LayoutDashboardIcon`, `dashboard`) · **작업(`ListChecksIcon`, `tasks`)** · 설정(`SettingsIcon`, `settings`). 메모 줄과 `StickyNoteIcon` 을 지운다.
- 위 막대의 화면 이름은 `NAV` 를 따라 "작업"이 된다. 쿼리가 붙어도(`/acme/tasks?page=2`) 지금 위치는 경로로 판단하므로 "작업"이 선택된다.

### 3.2 `/[slug]/tasks` — 작업

#### 3.2.1 목적

조직의 작업을 거르고 정렬하고 쪽으로 넘겨 보며, 추가·편집·상태 바꾸기·삭제를 한다. SaaS 데이터 표의 견본이다.

#### 3.2.2 레이아웃

```
작업                                                 [+ 작업 추가]   ← AppPage title / actions(기본 버튼)
디자인팀의 멤버가 함께 보는 작업입니다.                                 ← description
┌ Card gap-0 py-0 @container ─────────────────────────────────────┐
│ 작업 목록                                                   57개 │ ← 머리 줄 border-b px-6 py-4
├──────────────────────────────────────────────────────────────────┤
│ 상태          담당자            정렬                              │ ← 도구 줄 border-b px-6 py-4
│ [전체     ▾]  [전체        ▾]  [최근 만든 순 ▾]  [조건 지우기]      │
├──────────────────────────────────────────────────────────────────┤
│ 작업                 상태      담당자     마감일     만든 날   (관리) │ ← 표 머리 40px
│ 디자인 시안 정리      ◉ 진행 중  (김) 김철수  10. 21.    10. 14.   ⋯  │
│ 회의록 공유           ○ 할 일    없음        10. 12. · 지남 10. 10.  ⋯ │
├──────────────────────────────────────────────────────────────────┤
│ 2 / 3쪽                                      [‹ 이전] [다음 ›]   │ ← 쪽 줄 border-t px-6 py-3 (쪽이 둘 이상일 때만)
└──────────────────────────────────────────────────────────────────┘
```

- `AppPage title="작업"`. 설명(초안): 개인 "나만 보는 작업입니다." / 팀 "<팀 이름>의 멤버가 함께 보는 작업입니다." 문서 제목(`metadata.title`) "작업".
- 머리 동작: `Button` 기본 + `PlusIcon data-icon="inline-start"` "작업 추가". 이 화면의 유일한 주요 버튼이다. 처음 빈 상태(3.2.7)에서는 그리지 않고 빈 상태의 버튼이 그 자리를 맡는다(대시보드 견본과 같다).
- 카드 하나에 머리 줄·도구 줄·표·쪽 줄을 담는다. 거르기가 표와 한 덩어리로 보인다. 카드에 `@container`(칸 숨기기 기준), `section aria-labelledby="tasks-title"`.
- 머리 줄: `h2 id="tasks-title" tabIndex={-1}` "작업 목록"(`type-heading outline-none`, 초점 돌려받는 자리) · 오른쪽 `type-label text-muted-foreground tabular-nums` "57개"(지금 조건에 맞는 전체 수).

#### 3.2.3 도구 줄 (거르기·정렬)

| 칸 | 부품 | 값(초안) | URL |
|---|---|---|---|
| 상태 | `Field` + `FieldLabel htmlFor="task-filter-status"` + `Select` / `SelectTrigger size="sm" id=… className="w-full"` | "전체"(기본)·"할 일"·"진행 중"·"완료" | `status=todo\|in_progress\|done`, 전체는 쓰지 않는다 |
| 담당자 | 같은 구성, `id="task-filter-assignee"` | "전체"(기본)·"담당자 없음"·멤버(나 먼저 "홍길동 (나)", 그다음 이름 가나다순) | `assignee=<user id>\|none` |
| 정렬 (D3-1) | 같은 구성, `id="task-sort"` | "최근 만든 순"(기본, 만든 시각 내림)·"마감일 순"(마감일 오름, 없는 것은 맨 뒤, 같으면 최근 만든 순) | `sort=due`, 기본은 쓰지 않는다 |
| 조건 지우기 | `Link` + `cn(buttonVariants({ variant: "ghost", size: "sm" }))` + `FilterXIcon` | 셋 중 하나라도 기본이 아닐 때만 보인다 | `/<slug>/tasks` 로 |

- 배치: `grid grid-cols-2 gap-3 @2xl:flex @2xl:flex-wrap @2xl:items-end`. `@2xl` 이상에서 상태 `w-36`·담당자 `w-44`·정렬 `w-44`, "조건 지우기"는 줄 끝(`@2xl:ml-auto`). 좁으면 두 칸씩: 상태|담당자 / 정렬|조건 지우기(`self-end`).
- 라벨은 늘 보인다(`FieldLabel`, `type-label`). 트리거 32px(`size="sm"`), 도구 줄이라 조밀하게 둔다. Select 트리거는 단추라서 16px 규칙(입력칸의 iOS 확대)과 상관없다.
- 바꾸면: 쿼리를 새로 만들어(기본값은 지우고 `page` 도 지운다) `router.push(url, { scroll: false })` 를 `startTransition` 안에서 부른다. 초점은 Select 트리거에 남는다.
- 기다리는 동안(`isPending`): 표 영역에 `aria-busy="true"` + `opacity-60`(`motion-reduce` 와 상관없는 정지 효과), 도구 줄은 그대로 조작된다. Next 16 에서 쿼리만 바뀔 때 `loading.tsx` 뼈대가 다시 보이는지 구현자가 확인하고, 보인다면 뼈대의 도구 줄 자리가 같은 높이여야 한다(화면이 튀지 않게).
- 잘못된 값(없는 상태·멤버가 아닌 담당자·숫자가 아닌 쪽): 그 조건만 기본값으로 보고 화면을 그린다. 주소는 고치지 않는다(스펙 5).

#### 3.2.4 표

`CardContent` 대신 표를 카드에 바로 둔다(`Table className="table-fixed" aria-labelledby="tasks-title"`). 첫 칸 `pl-6`, 끝 칸 `pr-6`.

| 칸 | 머리 | 폭 | 보이는 단 | 내용 |
|---|---|---|---|---|
| 작업 | "작업" | 나머지 | 늘 | 제목 단추 + (좁은 단) 둘째 줄 |
| 상태 | "상태" | `w-14 @xl:w-32` | 늘 | 상태 메뉴 단추(3.2.5) |
| 담당자 | "담당자" | `w-36` | `hidden @xl:table-cell` | `Avatar size="sm"`(24px, 머리글자) + 이름 `truncate`, 내 줄이면 " (나)" `text-muted-foreground`. 없으면 `text-muted-foreground` "없음" |
| 마감일 | "마감일" | `w-32` | `hidden @xl:table-cell` | 날짜 표기(아래), `tabular-nums` |
| 만든 날 | "만든 날" | `w-32` | `hidden @3xl:table-cell` | `<time>` 날짜 표기, `text-muted-foreground tabular-nums` |
| 관리 | `<span class="sr-only">관리</span>` | `w-14` | 늘 | `Button variant="ghost" size="icon-sm"` + `MoreHorizontalIcon`, `aria-label="<제목> 관리"` |

- **제목 단추**: `button type="button"` 에 `block w-full truncate rounded-sm text-left font-medium text-foreground outline-none hover:underline focus-visible:ring-3 focus-visible:ring-ring/50`, `title`=전체 제목, `aria-haspopup="dialog"`. 누르면 편집 대화상자.
- **둘째 줄(`@xl` 미만)**: `mt-0.5 flex min-w-0 gap-1 type-caption text-muted-foreground @xl:hidden` — `담당자 이름(또는 "담당자 없음", 말줄임)` `·`(`aria-hidden`) `마감일 표기(shrink-0)`. 마감일이 없으면 담당자만.
- **날짜 표기**(서버 모델이 만든다, 서울 날짜): 올해면 "10. 21.", 다른 해면 "2027. 1. 5.". `<time dateTime="2026-10-21">`.
  - 기한 지남(열린 작업이고 마감일 < 오늘): `text-destructive` 로 "10. 12. · 지남". 색만으로 알리지 않도록 "지남" 글자를 둔다.
  - 오늘 마감(열린 작업): "10. 14. · 오늘", `text-foreground`.
  - 완료된 작업: 날짜만, `text-muted-foreground`(지나도 "지남"을 붙이지 않는다).
  - 없음: `<span aria-hidden>—</span><span class="sr-only">없음</span>`, `text-muted-foreground`.
- **관리 메뉴**(`DropdownMenuContent align="end"`): "편집"(`PencilIcon`) · (만든 사람이나 owner 일 때만) `DropdownMenuSeparator` + "삭제"(`Trash2Icon`, `variant="destructive"`). 삭제 가능 여부는 서버가 줄마다 계산해 넘긴다(`canDelete`). 화면은 판단하지 않는다.
- 줄 hover 바탕은 표 부품 기본(`hover:bg-muted/50`). 줄 전체를 누르는 대상으로 만들지 않는다(안에 단추가 셋이다).

#### 3.2.5 상태 메뉴 단추 (D2-1)

| 상태 | 아이콘(16px, `text-muted-foreground`) | 글자 |
|---|---|---|
| `todo` | `CircleIcon` | 할 일 |
| `in_progress` | `CircleDotIcon` | 진행 중 |
| `done` | `CircleCheckIcon` | 완료 |

- 단추: `Button variant="ghost" size="sm"` `-mx-2`(글자를 칸 선에 맞춘다), 안에 아이콘 + `<span className="hidden @xl:inline">진행 중</span>`. 좁은 단에서는 아이콘만 남아 32×32 근처가 된다.
- 이름: `aria-label="<제목> 상태: 진행 중"`(보이는 글자 "진행 중"을 포함한다 — 2.5.3). 저장 중 `disabled`.
- 메뉴(`DropdownMenuContent align="start"`): `DropdownMenuLabel` "상태" + `DropdownMenuRadioGroup`(세 항목, 앞에 같은 아이콘). 같은 값을 고르면 아무 일도 하지 않는다.
- 아이콘·글자 짝은 화면 전용 파일 하나(`web/app/(app)/[slug]/tasks/task-status.tsx`)에 두고 표·메뉴·편집 대화상자가 같이 쓴다.

#### 3.2.6 쪽 줄 (D4-1)

- 쪽이 둘 이상일 때만 그린다. `flex items-center justify-between gap-3 border-t border-border px-6 py-3`.
- 왼쪽 `type-label text-muted-foreground tabular-nums`: "2 / 3쪽"(읽는 글자 `<span class="sr-only">3쪽 중 2쪽</span>`, 보이는 글자는 `aria-hidden`).
- 오른쪽 `nav aria-label="쪽 이동"`: "이전"(`ChevronLeftIcon data-icon="inline-start"`)·"다음"(`ChevronRightIcon data-icon="inline-end"`). `Link` + `cn(buttonVariants({ variant: "outline", size: "sm" }))`, 주소는 지금 조건 + `page`(1쪽이면 `page` 를 지운다).
- 첫 쪽의 "이전"·끝 쪽의 "다음"은 링크가 아니라 `Button variant="outline" size="sm" disabled` 로 그린다(초점을 받지 않는다).
- 쪽을 옮기면 화면 맨 위로 스크롤하고(`Link` 기본) 초점을 "작업 목록" 제목으로 옮긴다. 화면 낭독기 사용자가 새 쪽의 처음부터 듣는다.

#### 3.2.7 빈 상태

| 처음(작업 0개) | 조건이 모두 기본이고 0개 | 도구 줄·표 없이: `ListChecksIcon` 상자(`size-10 rounded-lg bg-muted text-muted-foreground`, `aria-hidden`) + "아직 작업이 없습니다"(`type-body font-semibold`) + 둘째 줄 `type-label text-muted-foreground` 개인 "첫 작업을 추가해 할 일을 정리하세요." / 팀 "첫 작업을 추가하면 팀 멤버 모두에게 보입니다." + `Button` 기본 "첫 작업 추가"(대화상자) | 그리지 않는다 |

제목
[______________________________________]
                                  0/120
설명 (선택)
[                                      ]
[                                      ]
                                 0/2000
상태(편집만)        담당자
[◉ 진행 중   ▾]    [김철수        ▾]

- `DialogContent showCloseButton={false} className="sm:max-w-lg"`(512px. 375 에서는 343px). 높이 제한·안쪽 스크롤은 부품 기본을 지킨다.
- 처음 초점: 제목 칸(부품 기본 — 첫 입력칸. 넘쳐서 스크롤되면 팝업 자체).
- 폼: `form` + `FieldGroup`. 칸 묶음 `@container` 안에서 `grid gap-4 @md:grid-cols-2`(상태·담당자, 추가에서는 담당자·마감일이 나란히).

| 칸 | 부품 | 규칙(화면 검증은 편의, 서버·DB 가 다시 본다) |
|---|---|---|
| 제목 | `Input id="task-title" autoComplete="off"` + 글자 수 `0/120`(메모 폼과 같은 자리·모양) | 앞뒤 공백 빼고 1~120자. `maxLength` 를 걸지 않는다(붙여 넣은 글이 말없이 잘린다) |
| 설명 | `Textarea id="task-description" className="max-h-60 min-h-24 resize-none"` + `0/2000`. 라벨 뒤 `<span className="font-normal text-muted-foreground">(선택)</span>` | 비우면 null. 1~2000자 |
| 상태 (편집만, D6-1) | `Select` + `SelectTrigger id="task-status" className="w-full"`(40px), 항목에 3.2.5 아이콘 | 셋 중 하나 |
| 담당자 | `Select` + `SelectTrigger id="task-assignee" className="w-full"` | "담당자 없음"(추가의 기본)·멤버(나 먼저 "(나)", 이름 가나다순). 지금 멤버만 |
| 마감일 | `Input type="date" id="task-due"` + 값이 있으면 옆에 `Button variant="ghost" size="icon-sm" aria-label="마감일 지우기"`(`XIcon`) | 날짜만, 비우면 null. 브라우저마다 지우는 방법이 달라 지우기 단추를 따로 둔다 |

- 버튼: `DialogClose` 로 감싼 `outline` "취소" / 기본 "추가"(중 "추가 중…") · "저장"(중 "저장 중…").
- 제출 중: 입력칸 `readOnly`, Select `disabled`, 대화상자는 닫히지 않는다(`onOpenChange` 에서 막는다 — 메모 삭제와 같다).
- 편집의 메타 줄(`type-caption text-muted-foreground`): "<만든 사람> 님이 <만든 시각>에 만들었습니다." 만든 사람이 비었거나 읽을 수 없으면 "떠난 멤버가 …". 완료된 작업이면 뒤에 " · <완료 시각>에 완료" 를 붙인다. 시각은 메모와 같은 표기("2026. 10. 14. 오후 3:00", 서울 시간).
- 바뀐 것이 없어도 "저장"을 막지 않는다(가장 단순한 안). 닫을 때 바뀐 내용을 버릴지 묻지 않는다(Q7).

오류 문구(초안):

| 원인 | 어디에 | 문구 |
|---|---|---|
| 제목 비어 있음 | 제목 칸 | "제목을 입력하세요" |
| 제목 김 | 제목 칸(글자 수도 `text-destructive`) | "제목은 120자 이하입니다" |
| 설명 김 | 설명 칸 | "설명은 2000자 이하입니다" |
| 마감일 형식 | 마감일 칸 | "마감일 형식이 아닙니다" |
| 담당자가 이 팀 멤버가 아님(DB 거절) | 담당자 칸 | "이 팀의 멤버가 아닙니다. 담당자를 다시 고르세요." + `router.refresh()`(멤버 목록이 새로 온다, 대화상자는 열린 채) |
| 작업이 그새 지워짐(편집) | 폼 아래 `role="alert"` | "이 작업은 그사이 지워졌습니다. 목록을 새로 고칩니다." + `router.refresh()`, "저장" 비활성 |
| 조직에서 빠짐 | 오류 토스트 | "이 팀의 멤버가 아니어서 저장할 수 없습니다. 화면을 새로 고칩니다." + 새로 그림(→ 404). 폼 아래 문구는 404 와 함께 사라지므로 쓰지 않는다 |
| 로그인 풀림 | 폼 아래 | "로그인이 풀렸습니다. 다시 로그인하세요." |
| 네트워크·서버 | 폼 아래 | "저장하지 못했습니다. 잠시 뒤 다시 시도해 주세요."(입력값을 남긴다) |

서버 함수가 이 경우들을 상태값으로 나눠 돌려줘야 한다(스펙 5, 조직 견본과 같은 방식): `saved` · `invalid`(칸·문구) · `not-member`(담당자) · `gone` · `forbidden` · `signed-out`. 이름은 구현이 정한다.

#### 3.2.9 삭제 확인 대화상자

메모 삭제 대화상자와 같은 모양이다.

| 자리 | 내용 |
|---|---|
| 제목 | "작업을 삭제할까요?" |
| 설명 | "삭제한 작업은 되돌릴 수 없습니다. 활동 기록에는 제목이 남습니다." + 남이 만든 작업이면 " <만든 사람> 님이 만든 작업입니다." |
| 상자 | `rounded-lg bg-muted px-4 py-3` 안에 제목 `line-clamp-3 type-label wrap-anywhere text-foreground` |
| 버튼 | `outline` "취소"(처음 초점) / `destructive` "삭제"("삭제 중…") |
| 성공 | 닫힘, 토스트 "작업을 삭제했습니다", 초점 → "작업 목록" 제목 |
| 오류(`role="alert"`) | 지워짐 "이 작업은 이미 지워졌습니다. 목록을 새로 고칩니다." · 권한 없음 "이 작업을 삭제할 권한이 없습니다. 화면을 새로 고칩니다." · 로그인 풀림 · 그 밖 "작업을 삭제하지 못했습니다. 잠시 뒤 다시 시도해 주세요." (앞의 둘은 새로 그림). 조직에서 빠짐은 대화상자 대신 오류 토스트 "이 팀의 멤버가 아니어서 삭제할 수 없습니다. 화면을 새로 고칩니다." + 새로 그림(→ 404) |

상태 바꾸기 실패는 대화상자가 없으므로 `toast.error` 로 같은 문구를 보인다(지워짐·조직에서 빠짐은 새로 그림).

#### 3.2.12 접근성

- 제목 계층: `h1` "작업" → `h2` "작업 목록". 표는 `aria-labelledby="tasks-title"`. 쪽 이동은 `nav aria-label="쪽 이동"`.
- Tab 순서: "작업 추가" → 상태 → 담당자 → 정렬 → 조건 지우기 → 줄마다 [제목 → 상태 → 관리] → 이전 → 다음.
- 조건·쪽이 바뀌면 `sr-only` `role="status"` 한 곳이 알린다: "작업 57개 중 21–40번째를 보여 줍니다." / 0개면 "조건에 맞는 작업이 없습니다."
- 초점이 돌아가는 자리: 대화상자를 닫으면 연 단추. 그 단추가 사라졌으면(삭제, 조건에서 빠짐, 처음 빈 상태의 단추) "작업 목록" 제목(`tabIndex={-1}`). 쪽 이동 뒤에도 같은 제목.
- 단추 이름에 대상을 넣는다: "<제목> 관리", "<제목> 상태: 진행 중", "마감일 지우기". 제목 단추의 이름은 제목 글자 그대로.
- 기한 지남·오늘은 색과 글자("지남"·"오늘")를 같이 쓴다. 비어 있는 날짜는 "없음"으로 읽힌다.
- 폼: `FieldLabel htmlFor`, 오류 `aria-invalid` + `FieldError`, 글자 수는 `aria-describedby`(메모 폼과 같다). 대화상자 안 오류·폼 아래 오류는 `role="alert"`.
- 메뉴·Select 는 부품 기본 키보드(화살표, 글자 찾기, Enter, Esc 로 닫고 초점 복귀). 상태 항목은 `menuitemradio` 라 지금 값이 "선택됨"으로 읽힌다.
- 뼈대는 `motion-reduce:animate-none`. 흐리게 하는 효과는 움직임이 아니다.

### 3.3 `/[slug]/dashboard` — 대시보드

#### 3.3.1 목적

조직의 작업이 얼마나 열려 있고, 무엇이 급하고, 최근 누가 무엇을 했는지 한 화면에서 본다. 수치는 DB 집계 함수 하나가 낸다(스펙 4.4).

- 아래 두 카드: `@container` 안에서 `grid items-start gap-6 @4xl:grid-cols-[minmax(0,3fr)_minmax(0,2fr)]`. 1280 에서 두 단(왼쪽 ≈ 562px, 오른쪽 ≈ 374px), 768·375 는 한 단.

#### 3.3.3 요약 카드 (`StatCard`, 고치지 않는다)

`section aria-labelledby` + `sr-only` `h2` "요약", `@container` 안 `grid grid-cols-2 gap-4 @2xl:grid-cols-4`.

| 기한 지남 | 숫자 | "마감일이 오늘보다 이른 열린 작업" | 열린 작업 중 마감일 < 오늘(서울) |

#### 3.3.4 차트 카드 — 최근 14일

#### 3.3.5 기한이 가까운 작업

### 3.4 활동 문장 (스펙 4.3)

조사가 이름·제목의 받침에 따라 달라지지 않게 **이름 뒤에는 "님", 제목 뒤에는 "작업"** 을 붙여 조사를 고정한다. 문장은 서버 모델의 순수 함수가 만든다(단위 시험 대상).

| 종류 | 문장(초안) | 예 | 필요한 값 |
|---|---|---|---|
| 작업 만듦 | {행위자}이 ‘{제목}’ 작업을 만들었습니다. | 홍길동 님이 ‘회의록 공유’ 작업을 만들었습니다. | 제목(기록 시점) |
| 작업 완료함 | {행위자}이 ‘{제목}’ 작업을 완료했습니다. | | 제목 |
| 작업 다시 엶 | {행위자}이 ‘{제목}’ 작업을 다시 열었습니다. | | 제목 |
| 담당자 바꿈 — 남에게 | {행위자}이 ‘{제목}’ 작업의 담당자를 {대상}으로 바꿨습니다. | 홍길동 님이 ‘회의록 공유’ 작업의 담당자를 김철수 님으로 바꿨습니다. | 제목, 새 담당자 이름(기록 시점) |
| 담당자 바꿈 — 스스로 | {행위자}이 ‘{제목}’ 작업을 맡았습니다. | | 새 담당자 = 행위자 |
| 담당자 바꿈 — 비움 | {행위자}이 ‘{제목}’ 작업의 담당자를 비웠습니다. | | 새 담당자 없음 |
| 작업 지움 | {행위자}이 ‘{제목}’ 작업을 지웠습니다. | | 제목 |
| 들어옴(초대 수락) | {대상}이 팀에 들어왔습니다. | 김철수 님이 팀에 들어왔습니다. | 들어온 사람 이름(기록 시점) |
| 역할 바뀜 | {행위자}이 {대상}의 역할을 소유자로 바꿨습니다. / …멤버로 바꿨습니다. | | 대상 이름, 새 역할 |

| 초대 보냄 | {행위자}이 한 명을 소유자로 초대했습니다. / …멤버로 초대했습니다. | | 역할만(이메일 없음 — 미결정 기본안) |

이름 자리의 모양:

| 자리 | 이름이 있음 | 떠난 멤버 |
|---|---|---|
| {행위자}이 · {대상}이 | "홍길동 님이" | "떠난 멤버가" |
| {대상}을 | "김철수 님을" | "떠난 멤버를" |
| {대상}의 | "김철수 님의" | "떠난 멤버의" |
| {대상}으로 | "김철수 님으로" | "떠난 멤버로" |

- **이름**: 표시 이름, 없으면 이메일 @ 앞부분(앱 틀·멤버 화면과 같은 규칙). 내가 한 일도 내 이름으로 쓴다("나"로 바꾸지 않는다 — 조직 견본과 같다).
- **행위자가 지워진 경우**: `actor_id` 가 null(계정 삭제, `on delete set null`)이거나 그 사람의 프로필을 읽을 수 없으면(팀을 떠남) "떠난 멤버". 조직 견본의 작성자 규칙(그 문서 Q6)과 같다.
- **대상 이름**은 기록 시점의 사본을 쓴다(스펙 4.1 "표시할 값을 기록 시점에 함께 남긴다"). 그래서 "나감"·"들어옴"은 행위자가 아니라 대상 이름으로 문장을 만든다 — 나간 사람은 곧바로 프로필을 읽을 수 없게 되기 때문이다. 대상의 계정이 지워져 사본도 지워졌다면 "떠난 멤버".
- 행위자 이름도 사본으로 남길지는 Q1.
- 기록에 남은 제목은 그 뒤 제목을 고쳐도 바뀌지 않는다.
- 미결정 기본안에 따라 "멤버가 빠지며 담당자가 비는 일"과 첫 owner 멤버십은 피드에 나오지 않는다.
- 알 수 없는 종류(나중에 더한 종류를 옛 화면이 받음)는 줄을 빼고 그린다. 빈 문장을 그리지 않는다.

### 6.1 넓힐 부품 — `BarChart` 두 계열 (승인 필요, 새 패키지 없음)

지금 `BarChart` 는 계열 하나(`days[].count`)만 그린다. 계열을 여럿 받도록 넓히되, 첫 화면 견본(`dashboard-preview.tsx`)의 지금 호출은 그대로 둔다.

```ts
// 그대로 — 한 계열
export type BarChartDay = { date: string; label: string; count: number };
// 새로 — 여러 계열. counts 는 dates 와 같은 순서·같은 길이다.
export type BarChartTone = "brand" | "chart-2";
export type BarChartSeries = { name: string; tone: BarChartTone; counts: number[] };

type BarChartProps = { caption: string; unit?: string; className?: string } & (
  | { days: BarChartDay[]; valueHeader: string } // 지금과 같다
  | { dates: { date: string; label: string }[]; series: BarChartSeries[] } // 두 계열 이상
);
```

- 안에서는 한 계열 호출을 `series=[{ name: valueHeader, tone: "brand", counts }]` 로 바꿔 같은 길로 그린다.
- 눈금 맨 위: 모든 계열의 값 중 최댓값으로 `barAxisMax`(지금 함수 그대로).
- 막대: 날짜 칸 안에 계열 수만큼 `flex items-end justify-center gap-0.5`(2px 바탕 틈). 계열이 하나면 지금처럼 `max-w-8`, 둘 이상이면 막대마다 `max-w-4`. `rounded-t-sm`, 값이 있으면 `min-h-1` 은 그대로.
- 색: `tone` → 클래스 표 `{ brand: "bg-brand", "chart-2": "bg-chart-2" }`(Tailwind 가 찾도록 글자 그대로 적는다). 계열 순서대로 쓴다.
- 범례(계열이 둘 이상일 때만): 그림 위 `mb-4 flex flex-wrap gap-x-4 gap-y-1 type-label` 의 `ul`. 항목 `flex items-center gap-1.5`: 색 칸 `size-2.5 rounded-xs bg-<tone>`(`aria-hidden`) + 이름 `text-muted-foreground` + 14일 합계 `font-medium text-foreground tabular-nums` + `<span class="sr-only">개</span>`. 글자는 계열 색을 쓰지 않는다.
- 날짜 칸에 `title="10. 13. 추가 3개 · 완료 2개"`(한 계열이면 "10. 13. 3개") — 마우스로 정확한 값을 본다. 화면 낭독기는 표로 읽는다.
- `sr-only` 표: 머리 `날짜` + 계열마다 `th`(계열 이름), 칸은 값 + 단위.
- 날짜 글자 솎기(`labelVisibility`)·여백(`COLUMNS`)은 그대로다.
- 시험: 순수 계산(최댓값·한 계열 → 여러 계열 바꾸기)은 단위 시험, 320px 에서 두 계열 막대가 칸 안에 드는지는 브라우저 시험(`bar-chart.browser.test.tsx`)이나 QA.

### 6.2 새 토큰 — `chart-2` (D1-1, 승인 필요)

`design/tokens.json` 의 `colors` 에 `brand-foreground` 다음 줄로 더한다.

```json
"chart-2": "#0E9F8E",
```

- 쓰임: 차트의 둘째 계열 막대와 범례 색 칸에만. 글자·바탕·버튼에 쓰지 않는다. 첫째 계열은 `brand` 다(따로 `chart-1` 을 두지 않는다 — 같은 값을 두 곳에 적지 않는다).
- 검증(dataviz `validate_palette.js "#1B64DA,#0E9F8E" --mode light --surface "#FFFFFF"`): 밝기 띠·채도·색맹 구분(ΔE 21.4, deutan)·정상 시각 구분(ΔE 22.7)·바탕 대비 모두 통과. 흰 바탕 대비 `brand` 5.41:1, `chart-2` 3.30:1(그래픽 3:1 이상).
- 비교한 후보: 회색 `#5E6978`(D1-2)은 대비·구분은 통과하지만 채도 0.027 로 "꺼짐"처럼 읽힌다. 옅은 파랑 `#7FA8EC` 은 대비 2.41:1 로 미달.
- 함께 고칠 것: `pnpm tokens`(웹 `--color-chart-2` → `bg-chart-2`, 앱 `colors.chart2` 는 쓰지 않지만 생성된다), `tokens.json` 의 `$comment` 에 "chart-2 는 차트의 둘째 계열 색이다", `design-system` 스킬 "반드시" 절에 같은 한 줄. 글자 대비 시험(`usedPairs`)에는 넣지 않는다(글자 색이 아니다).
- 다크 모드는 비목표라 밝은 값 하나만 둔다.

### 6.4 구현 메모

- 새 경로 `/acme/tasks` 를 `web/e2e/responsive.spec.ts` 목록에 넣고 `/acme/memos` 를 뺀다(스펙 3.4).
- `web/app/(app)/home.ts` 의 `redirectToPersonal` 경로 값에 `tasks` 를 더하고 `/memos` 가 그것을 쓴다(스펙 4.4).
- 화면이 받는 값(서버 모델이 만든다): 작업 줄 `{ id, title, description, status, statusLabel, dueDate, dueText, dueState: "overdue"|"today"|"later"|"done"|"none", assignee: { name, isMe } | null, createdAt, createdAtText, creatorName, completedAtText, canDelete }`, 목록 `{ rows, total, page, pageCount, filters, members }`, 대시보드 `{ counts, weekStartLabel, daily: { date, label, added, completed }[], dueSoon, activities: { id, text, subjectName | null, createdAt, createdAtText }[] }`.
- Select 부품(`web/components/ui/select.tsx`)의 항목 글자가 `text-sm`·`text-xs` 이고 항목 높이가 약 28px 다(디자인 시스템은 `type-*`, 메뉴 항목 32px). 항목 글자(`ItemText`)가 `shrink-0` 이라 긴 멤버 이름이 말줄임 없이 잘린다. 담당자 Select 를 만들 때 함께 고칠지 정한다(Q12).
- 구현 차이: 이 문서의 `router.refresh()` 는 서버 함수가 같은 응답에서 `next/cache` 의 `refresh()` 로 다시 그리는 것으로 했다(`tasks/actions.ts`). 결과는 같다.
- 구현 차이: 담당자 고르기는 지금 멤버만 고를 수 있다. 다만 칸의 값이던 사람(편집하는 작업의 담당자, 이 대화상자에서 고른 사람)이 그새 떠났으면 목록 끝에 흐리게(고를 수 없게) 남긴다. 그래야 Select 가 값을 말없이 "담당자 없음"으로 바꾸지 않고, 무엇이 거절됐는지 보인다.

## 7. 열린 질문

괄호 안은 이 문서가 임시로 둔 기본값이다.
