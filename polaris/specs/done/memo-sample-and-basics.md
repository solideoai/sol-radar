# 스펙: 메모 견본과 앱·웹 기본기 보강

- 최종 갱신: 2026-10-13

## 1. 목표

표 하나를 웹과 앱이 같이 쓰는 목록형 견본(메모: 목록·추가·삭제)을 넣어 "여러 행, 본인 것만" 기능의 기준 코드를 만든다.
함께 앱의 공용 부품과 빠진 흐름, 웹의 공용 머리말을 채운다. [사용자 결정]

## 2. 비목표

- 메모 수정. 수정 견본은 `display_name` 이 맡는다. [사용자 결정]
- 다크 모드. [사용자 결정]
- 네이티브 스플래시(`expo-splash-screen` 설치). [사용자 결정]
- OAuth, 딥링크, 앱 E2E, i18n, 결제. [제안 후 승인]
- 머리말의 로그인 상태 표시. [제안 후 승인]
- 오류 수집 도구 설치와 오류 수집 자리(`instrumentation.ts`). Next 가 서버 오류를 이미 기록하므로 동작 없는 자리만 남는다. [제안 후 승인]
- robots·sitemap·metadataBase. 공개 페이지가 `/` 하나뿐이다. [제안 후 승인]
- 목록의 페이지 넘김. [제안 후 승인]
- 운영자가 남의 메모를 읽는 정책. [제안 후 승인]

## 3. 완료의 정의

1. 새 표 `public.memos` 가 마이그레이션 한 장으로 생기고 RLS, 권한 회수 후 필요한 grant, 본인 것만 읽기·추가·삭제 정책,
   `user_id` 인덱스, 본문 길이 제약을 갖는다.
   검증: `pnpm test:db` 에 더한 시험 — 남의 행이 안 보인다, 남의 행을 못 지운다, 남의 `user_id` 로 못 넣는다. [제안 후 승인]
2. DB 타입 생성물이 마이그레이션과 맞다. 검증: `pnpm check:db-types`. [제안 후 승인]
3. 웹 도메인 `web/server/memo/` 가 `profile` 과 같은 모양(model·repo·service·배럴)이고 규칙에 시험이 있다.
   검증: `pnpm -C web test`, `pnpm -C web lodestar`. [제안 후 승인]
4. 웹 `/memos` 에 목록, 추가 폼, 삭제 확인 대화상자, `loading.tsx`, 빈 상태가 있다.
   검증: 로컬 Supabase(`pnpm db:start`)에 연결해 가입 → 추가 → 목록 → 삭제를 375px·1280px 에서 확인한다. [제안 후 승인]
5. `/memos` 가 320·375·768·1280px 에서 가로로 넘치지 않는다.
   검증: `web/e2e/responsive.spec.ts` 경로 목록에 추가한 뒤 `pnpm -C web test:e2e`. [제안 후 승인]
6. 정적 머리말(홈·메모·계정 링크)이 화면마다 보이고 `/` 는 정적 렌더링을 유지한다.
   검증: `pnpm -C web build` 출력의 `○ /`. [제안 후 승인]
7. 앱에 메모 목록 화면 `mobile/app/memos.tsx`(빈 상태, 당겨서 새로고침, 추가, 삭제)가 있고 로직은 `mobile/lib/` 에 시험과 함께 있다.
   검증: `pnpm -C mobile test`, 화면은 로컬 Supabase 에 연결해 확인한다. [제안 후 승인]
8. `mobile/components/` 에 버튼, 입력칸, 화면 틀(안전 영역·키보드 회피·스크롤)이 있고 `mobile/app/account.tsx` 가 그것을 쓴다.
   검증: `pnpm -C mobile verify`. [제안 후 승인]
9. 앱 계정 화면에 로딩 표시, 표시 이름 수정, 재설정 메일 보내기가 있다.
   검증: `pnpm -C mobile test`(lib 로직), 화면은 로컬 Supabase 에 연결해 확인한다. [제안 후 승인]
10. `mobile/app.json` 에 `icon` 과 임시 이미지가 있다. 검증: `pnpm -C mobile check:expo`. [사용자 결정]
11. `docs/database.md` 로그인 견본 표가 바뀐 내용과 맞다. 검증: `pnpm test`(문서 경로 대조 시험). [제안 후 승인]
12. `pnpm verify` 가 통과한다. [제안 후 승인]

화면 확인(4·7·9)의 전제: 사용자가 Docker 를 켜고 Supabase CLI 를 설치한다(`brew install supabase/tap/supabase`). [제안 후 승인]

## 4. 인터페이스 계약

- 표 `public.memos` 는 소유자 `user_id` 와 본문을 갖는다. [제안 후 승인]
- 본문은 앞뒤 공백 없이 1~500자다. [제안 후 승인]
- 화면 역할 권한은 `authenticated` 의 select·insert·delete 뿐이다. update 는 없다. [제안 후 승인]
- 정책은 본인 것만 읽기·추가·삭제다. 운영자 정책은 없다. [제안 후 승인]
- 웹은 `web/server/memo/` 배럴이 목록·추가·삭제를 내보내고, 추가·삭제는 서버 함수가 부른다. 경로는 `/memos` 다. [제안 후 승인]
- 목록은 최신순 50개다. [제안 후 승인]
- 앱은 `mobile/lib/` 에 목록·추가·삭제 로직을 두고 화면은 `mobile/app/memos.tsx` 다. [제안 후 승인]
- 앱의 삭제 확인은 OS 기본 확인 창이다. [제안 후 승인]
- 앱의 비밀번호 재설정은 메일 요청만 한다. 링크는 웹 `/auth/confirm` 이 받는다. [제안 후 승인]
- 임시 아이콘은 토큰의 primary 색 단색 PNG(1024px)다. 실제 아이콘은 나중에 교체한다. [제안 후 승인]

## 5. 엣지 케이스와 실패 시나리오

- 표 이름은 `notes` 가 아니다. 옛 `notes` 가 남은 DB 에서 `create table if not exists` 가 옛 모양을 두고 지나가기 때문이다. [제안 후 승인]
- 빈 본문과 길이 초과는 화면, 서버, DB 제약이 각각 막는다. [제안 후 승인]
- 남의 행 읽기·삭제와 남의 `user_id` 로 넣기는 RLS 가 막는다. [제안 후 승인]
- 로그인하지 않았거나 DB 가 연결되지 않은 상태로 메모 화면을 열면 계정 화면과 같은 안내와 계정 화면 링크를 보여 준다. [제안 후 승인]
- 머리말에 로그인 상태를 넣지 않는다. `/` 가 동적 렌더링으로 바뀌기 때문이다. [제안 후 승인]
