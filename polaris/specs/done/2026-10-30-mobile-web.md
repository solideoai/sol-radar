# 모바일 웹 기본 대응

## 승인과 기준

2026-10-30 사용자가 모바일에서 화면이 깨지는 문제의 개선을 요청하고, 메뉴 서랍·한 열 본문·공고 요약 목록·필터 서랍·세로 상세·모바일 일정 목록으로 구성한 제안을 승인했다. 이 승인으로 ADR-007의 1280px 미만 반응형 금지를 모바일 웹 기본 대응에 한해 변경한다. 네이티브 앱·Expo·결제·구독은 계속 범위 밖이다.

기존 흰 바탕·가는 선·남색 주요 버튼·Pretendard·상태색과 데이터·권한·경로를 유지한다. 설계 근거는 `docs/06-UI-UX.md`, `design/tokens.json`, `.claude/skills/design-system/SKILL.md`와 실제 화면 코드다. 본 명세는 코드 구조를 확인해 작성했으며 시각적 수용은 브라우저 검증에서 판단한다.

사용자가 승인한 방향을 아래 단계별 계획으로 구체화한다. 새 디자인 토큰·외부 UI 패키지는 필요 없다. 기존 `Button`·`Sheet`·`Dialog`·`Chip`·`Input`·`Select`·목록과 구분선을 재사용한다.

## 폭과 공통 배치

| 폭 | 틀 | 본문 |
|---|---|---|
| 1280px 이상 | 기존 데스크톱 머리말·사이드바 | 기존 열 수와 최대 폭·고정 보조 패널 유지 |
| 768~1279px | 업무 사이드바의 기존 접기 사용, 마케팅 메뉴는 공간에 맞게 서랍 전환 | 보조 패널은 본문으로 내려 한 열, 통계·카드만 가능한 범위에서 2열 |
| 767px 이하 | 업무 메뉴는 기존 서랍, 마케팅은 로고·시작하기·메뉴 | 좌우 16px, 본문 한 열, 요약 지표 2열 |

본문 내부의 열 수는 `@container` 기준으로 정한다. 고정 열의 기본값을 한 열로 하고 충분히 넓을 때만 기존 열을 켠다. 페이지 전체의 가로 넘침을 숨겨 결함을 가리지 않는다. 비교 표·조직도·차트는 이름이 있는 영역 안에서만 가로 이동을 허용한다.

화면 제목은 기존 `type-title`을 쓰되 랜딩의 `type-display`·`type-headline`은 작은 폭에서 기존 `type-title`·`type-heading-lg` 등으로 내린다. 본문은 기존 14px, 보조 라벨은 13px를 유지하고 정보가 빽빽하다는 이유로 줄이지 않는다. 메뉴·아이콘·주요 버튼 등 반복 조작 영역은 모바일 최소 44px로 한다. 입력 글자는 iOS 확대를 피하는 기존 기본 크기를 유지한다.

## 사용자 흐름

1. 랜딩: 설명 읽기 → 예시 공고 선택 → 분석·근거 확인 → 시작하기.
2. 업무: 메뉴 서랍에서 화면 선택 → 서랍 닫기 → 검색·필터 → 공고 요약 목록 → 상세 → 근거 서랍 또는 검토 기록.
3. 일정: 달 이동·업무 범위·종류 선택 → 해당 달의 날짜별 일정 목록 → 공고 또는 프로젝트 이동.

데스크톱과 모바일에서 같은 URL·필터 쿼리·권한·데이터를 쓴다. 폭 변경으로 필터·선택·관심 상태가 초기화되지 않는다.

## 접근성과 부품

- 제목 하나·본문 건너뛰기 링크·기존 랜드마크와 경로를 유지한다.
- 메뉴·필터·근거는 기존 `Sheet`의 제목·닫기·초점 가두기·Escape·트리거 초점 복귀를 따른다. 터치로도 닫을 수 있어야 한다.
- 모바일 메뉴·관심·필터·월 이동 등 아이콘 버튼은 44px 영역과 접근 이름을 갖는다.
- 숨긴 데스크톱 표/탭은 초점과 낭독 대상에서 빠진다. 요약 목록의 관심 버튼을 공고 링크 안에 넣지 않는다.
- 서랍은 `100dvh` 안에서 스크롤하고 닫기·적용 버튼에 항상 닿을 수 있다. 키보드가 올라와도 입력과 제출에 닿을 수 있다.
- 흰 바탕·`border`·`foreground`·`muted-foreground`·`selected`·기존 권고 상태색만 사용한다. 새 색·토큰·외부 부품 도입 없음.
- `prefers-reduced-motion`의 기존 동작과 수주확률/DEMO/원문 관련 고지를 보존한다.
