# 랜딩 업무 데모 애니메이션 개선안

"참여 여부는 담당자가 정합니다." 아래 업무 데모의 클릭, 화면 전환, 처리 결과를 더 분명하게 보여 준다. 기존 다섯 장면과 약 25초 재생 흐름에 방향 있는 패널 이동과 결과 강조를 더한다. 사용자가 2026-10-29 이 설계대로 구현하도록 승인했다.

## 1. 근거와 현재 상태

기준은 [UI 명세 §3.4](../../../docs/06-UI-UX.md)와 [디자인 시스템](../../../.claude/skills/design-system/SKILL.md)이다. 별도 애니메이션 개선 스펙이 없어 이 초안을 만든다.

2026-10-29 [Granter](https://granter.biz/#top)와 [SOL RADAR 운영 랜딩](https://www.solideos-radar.com)을 1440×1000 브라우저에서 각각 25초 관찰했다. [관찰 기록](../../../docs/evidence/landing-motion/20261029-observation.json)에 측정과 판단을 구분했다.

Granter에서는 사이드바가 접히며 작업 공간이 넓어지고, 패널이 수평으로 들어온다. 클릭 표시와 변경된 셀의 강조, 결과 안내가 행동과 결과를 연결한다. 관찰한 전환은 사이드바 300ms, 패널 500ms, 커서 700ms였다. 이 값은 참고이며 아래 설계 수치와 구분한다. 마지막 결과는 다음 행동을 기다렸으므로 무한 자동 재생으로 단정하지 않는다.

현재 업무 데모에는 이미 숫자 증가, 행의 순차 등장, 점수 막대, 인용 강조, 커서 이동, 버튼 눌림이 있다. 하지만 행의 이동은 6px, 장면의 이동은 8px이고 대부분 같은 페이드 전환이다. 따라서 효과를 새로 늘리기보다 장면 사이의 변화와 처리 완료를 눈에 잘 띄게 하는 쪽이 낫다.

## 2. 선택지

| 안 | 변화 | 판단 |
|---|---|---|
| 작은 등장 효과 강화 | 현재 페이드의 이동 거리·시차만 키움 | 가장 작지만 사용자가 느끼는 차이가 적을 수 있다 |
| 패널 전개와 결과 강조 | 수집·상세 패널이 옆에서 열리고 클릭·변경 위치를 강조 | 추천. 기존 단계와 틀 안에서 변화가 뚜렷하다 |
| 전체 화면 확대와 사이드바 접기 | 업무 공간 전체를 재배치하며 초점을 이동 | 후순위. 커서 좌표와 최소 폭 검증 부담이 크다 |

## 3. 추천 장면 구성

아래 시간은 구현 초안이다. 전환 시간도 기존 단계의 체류 시간 안에 포함해 전체 한 바퀴 24.68초를 유지한다. 한 번에 강하게 움직이는 대상은 하나다.

| 장면 | 제안할 움직임 | 시간 초안 | 관객이 알아야 할 것 |
|---|---|---|---|
| 대시보드 | 커서가 확인 버튼에 도착한 뒤 누름. 클릭점에서 원형 테두리가 한 번 퍼지고 사라짐 | 눌림 120ms·클릭 표시 360ms | 담당자의 확인이 수집 결과를 연다 |
| 수집 | 본문 안에서 수집 패널이 오른쪽 경계부터 들어옴. 출처 5곳은 행 간 시차로 완료를 보여 주고 완료된 행을 잠깐 강조 | 패널 480ms·행 시차 약 240ms·완료 강조 320ms | 여러 출처의 공고가 모여 관련 공고로 좁혀진다 |
| 관련 공고 | 기존 행 순차 등장을 16px 이동과 약 120ms 시차로 다듬고, 열 공고는 커서 도착 → 선택 바탕 → 클릭 순서로 강조 | 행 320ms·클릭 360ms | 어떤 공고를 골랐는지 보인다 |
| 분석 상세 | 선택한 공고의 상세 패널이 오른쪽에서 본문을 덮으며 열림. 자격 판정 → 점수 → 근거 강조의 기존 순서를 분명히 분리 | 패널 500ms·체크 180ms·근거 강조 650ms | 판단이 공고문 근거와 연결된다 |
| 관심 공고 | 새 행이 위에서 들어오고 저장 확인이 작게 나타남. 이후 알림 일정과 상단 알림 점을 순서대로 강조 | 행 300ms·확인 280ms·알림 강조 400ms | 저장과 마감 알림이 이어진다 |

상세 패널은 **데모 내부의 전환 연출**이다. 앱의 실제 상세 라우팅을 바꾸거나 새 drawer 기능을 만들지 않는다. 패널이 도착한 뒤 커서가 다음 목표로 이동한다. 마지막 복귀는 240ms 페이드로 처리하고 별도 확대 효과를 더하지 않는다.

## 4. 구현 제약

- 기존 흰 판, 1px 테두리, 사이드바·상단바, 제목·설명·섹션 위치를 유지한다. 연한 강조는 `selected`·`brand` 토큰으로 표현한다.
- 새 색·글꼴·글자 눈금·라이브러리를 추가하지 않는다. 타사의 그라데이션·광원·그림자·소스·이미지를 복제하지 않는다.
- 기존 `step` 상태를 유일한 재생 시계로 사용한다. 별도 `setInterval`이나 장면별 타이머를 만들지 않는다.
- CSS 모듈의 `transform`·`opacity` 중심으로 구현한다. 패널 안에 내용을 유지해 화면 밖으로 글자가 잘리지 않게 한다. 큰 이동은 수집과 상세 진입에만 쓴다.
- 커서 목표 좌표는 이동 중인 패널에서 측정하지 않는다. 패널 도착 시점에 목표가 정해지도록 기존 단계와 좌표 측정 의존성을 점검한다.
- 숨은 장면은 장식 애니메이션도 돌리지 않는다. 루프 재시작 때 출처·체크·원형 클릭 표시가 이전 상태에서 남지 않아야 한다.
- 멈춤은 단계 타이머와 추가 keyframe을 함께 멈춘다. CSS transition은 `animation-play-state`로 멈추지 않으므로, 멈춤 시 진행 중 효과가 어떻게 정착할지 명시하고 관찰한다.
- 화면 밖·탭 비활성에서 중지하는 기존 조건을 유지한다. `prefers-reduced-motion`에서는 이동·크기·반복 강조를 끄고 기존 분석 완성 화면을 보인다.
- 키보드 초점 때 보이는 재생·멈춤 버튼, `aria-hidden`·`inert`, 화면 낭독기 요약, 가상 공고, 담당자 결정 대기를 유지한다.
- 1280px 미만 레이아웃, 업무 기능 변경, 새 숫자·성능 주장, 전체 랜딩의 반복 등장 효과는 범위 밖이다.

## 5. 구현 순서와 완료 기준

| 단계 | 예상 파일 | 완료 기준 |
|---|---|---|
| 1. 패널 전환과 클릭 | `work-demo-scenes.tsx`, `work-demo.module.css`, 필요 시 `demo-cursor.tsx` | 수집·상세 진입이 구별되고 커서 클릭점이 목표와 일치한다 |
| 2. 처리 결과의 리듬 | `work-demo-scenes.tsx`, `work-demo-data.ts`, 필요 시 `work-demo.tsx` | 기존 22단계·24.68초 안에서 수집·판정·점수·근거·저장 순서가 읽힌다 |
| 3. 동작과 접근성 확인 | 기존 `web/e2e/landing-showcase.spec.ts`, `docs/06-UI-UX.md`, 검증 증거 | 1440·1280에서 한 바퀴와 재시작·멈춤·움직임 줄이기를 확인하고 UI 정본에 최종 수치를 반영한다 |

위 파일명은 `web/components/landing/` 기준이며 실제 변경 파일은 구현 시 최소화한다. 다른 구역과 공유하는 `demo-playback.ts`·`demo-cursor.tsx`를 바꾸면 공고 분석 예시의 자동 재생·직접 조작도 함께 확인한다.

개발 검증은 `pnpm verify:changed`와 기존 업무 데모 E2E 범위를 사용한다. 화면 확인은 1440×900과 1280×800에서 수행한다. 통합 시 전체 `pnpm verify`를 실행한다. 정적인 스타일 값 복사 시험이나 장면별 전수 행렬은 추가하지 않는다.

## 6. 구현과 검증 결과

2026-10-29 구현을 마쳤다. 실제 변경은 `work-demo.tsx`·`work-demo-scenes.tsx`·`work-demo.module.css`와 기존 `landing-showcase.spec.ts`다. 단계 수와 재생 시간, 공유 커서·재생 훅은 그대로다. 멈춤은 keyframe·지연 시간을 동결하고 기존 transition의 값은 현재 단계의 끝값에 정착하도록 정했다.

1440×900·1280×800에서 한 바퀴와 재시작, 패널 안팎 가로 넘침을 확인했다. 기존 업무 데모 E2E 세 건은 전체 루프·클릭 좌표·패널 움직임, 멈춘 keyframe 시간, 움직임 줄이기를 검증하고 모두 통과했다. 새 시험 파일이나 장면별 행렬은 추가하지 않았다.

`pnpm verify` 최초 실행은 공통 검사 통과 후 새 E2E의 타입 오류에서 멈췄다. `KeyframeEffect` 확인으로 수정해 타입 검사를 통과했고, 공통 성공 결과는 재사용하며 웹 후속 검사·빌드와 AI·결정 서비스 검사를 모두 마쳤다. 상세 명령·결과·스크린샷은 [구현 검증 기록](../../../docs/evidence/landing-motion/20261029-implementation.json)에 있다.

커밋·푸시는 별도 요청 때 진행한다.
