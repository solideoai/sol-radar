# 솔리데오 가입·필수 정보 보완 UI

## 1. 기준과 범위

이 문서는 [승인된 기능 스펙](2026-10-16-solideo-people-signup.md) §8과 [UI 정본](../../../docs/06-UI-UX.md) §5.2.1~5.2.2를 구현 가능한 화면 기준으로 보충한다. 기능 범위나 권한 정책을 새로 정하지 않는다. 데이터 계약은 [API 정본](../../../docs/05-API-SPEC.md) §8이다. 아래 화면 카피는 구현·검수용 초안이다.

기존 화면은 브라우저가 아닌 코드로 확인했다. `web/app/auth/account-card.tsx`의 `AccountCard`는 이름과 달리 테두리 카드가 아닌 `AuthFrame` 래퍼다. 현재 인증 화면의 좁은 단폭과 여백을 유지한다. 참고한 코드는 가입 페이지·폼·스키마·약관 안내, `auth-frame.tsx`, `ui/field.tsx`, `ui/input.tsx`, `ui/select.tsx`, 멤버 초대 폼의 Select 연결 방식이다. 색·글꼴·글자 눈금은 `design/tokens.json`과 저장소 `design-system` 스킬을 따른다.

대상은 이메일 가입과 OAuth·기존 계정의 첫 업무 진입 전 정보 보완이다. 회사는 **솔리데오** 고정이며 회사 선택·생성·전환은 없다. 화면과 안내는 한국어다. 승인 카탈로그에 있는 영문 직급 표기는 원문 표시명을 유지한다. 1280px 이상 데스크톱만 다루며 검수 폭은 1440px·1280px이다. 모바일·결제·가상 직원 선택·새 권한 선택·인물 이미지·명부 화면은 범위에 넣지 않는다.

## 2. 공통 레이아웃과 필드

- `AccountCard` / `AccountHeader`를 사용한다. `main#main-content`는 인증 틀이 하나만 제공한다. 제목 `h1`도 하나다. 별도 로고·사이드바·장식 카드를 추가하지 않는다.
- 단폭은 `max-w-100`(400px), 가로 중앙 정렬이다. 데스크톱의 기존 `px-4`, `py-16`, 내부 `my-auto`를 따른다. 긴 가입 폼은 문서 전체를 세로로 스크롤하고 제목·제출 버튼까지 도달할 수 있어야 한다. 고정 높이·중첩 폼 스크롤을 만들지 않는다.
- 제목과 설명은 가운데 정렬, 입력 필드와 오류는 왼쪽 정렬한다. 제목·설명 사이는 `gap-2`, 헤더·폼 사이는 `gap-6`이다. 기존 가입 폼의 큰 묶음 사이는 `gap-8`, 필드 사이는 `gap-4`, 라벨·컨트롤·설명 사이는 `gap-2`를 따른다. 오류와 주요 버튼은 `gap-3`, 폼과 하단 링크는 `gap-4`다.
- 회사·이름·부서·직급/직책을 한 열로 배치한다. 두 Select를 좁은 두 열로 나누지 않는다. 컨트롤은 모두 단폭 전체이며 높이 40px, 둥근 모서리 8px이다. 주요 버튼은 기존 기본 높이 36px, 단폭 전체다.
- 회사는 `회사` 라벨과 `솔리데오` 값의 정적 텍스트로 표시한다. 비활성 Select나 입력칸 모양으로 만들지 않고 탭 순서에서도 제외한다.

| 필드 | 라벨·초기 표시 | 동작·검증 | 오류 카피 |
|---|---|---|---|
| 이름 | `이름 (필수)` / `이름을 입력해 주세요` | 기존 표시 이름 규칙: 앞뒤 공백을 정리한 뒤 1~40자. 자동완성 이름 사용. 영문·두 글자·네 글자 등도 동일한 길이 규칙 적용 | `이름을 입력하세요` / `이름은 40자 이하입니다` |
| 부서 | `부서 (필수)` / `부서를 선택해 주세요` | 승인 목록에서 한 개 선택. 이메일 가입의 최초 값은 미선택 | `부서를 선택해 주세요` |
| 직급/직책 | `직급/직책 (필수)` / `직급/직책을 선택해 주세요` | 승인 목록에서 한 개 선택. 이메일 가입의 최초 값은 미선택 | `직급/직책을 선택해 주세요` |

두 Select 아래 공통 안내는 `부서와 직급/직책은 본인이 입력하는 정보입니다. 서비스 이용 권한은 별도로 확인합니다.`이다. 필수 정보임을 텍스트로 표시하며 색이나 별표만으로 뜻을 전달하지 않는다. 가상 명부의 한글 세 글자 규칙을 실제 사용자에게 적용하지 않는다.

## 3. `/auth/sign-up`

제목은 `회원가입`, 설명은 `솔리데오에서 사용할 계정 정보를 입력해 주세요.`로 한다. 순서는 회사 → 이름 → 부서 → 직급/직책 → 공통 안내 → 이메일 → 비밀번호 → 비밀번호 확인 → 기존 선택 정보 → 기존 약관 동의 → 폼 오류 → `회원가입` 버튼 → `이미 계정이 있나요? 로그인` → 활성화된 기존 간편 가입 버튼이다.

이메일·비밀번호·비밀번호 확인·약관의 기존 검증과 확인 메일 흐름은 유지한다. 새 필수 수집 항목과 맞게 기존 개인정보 안내의 필수 항목에 `부서, 직급/직책`을 함께 표시한다. 선택 정보 저장 기능이나 새로운 동의 절차를 이 작업에 추가하지 않는다. 새 안내에는 내부 API·DB·카탈로그 코드·마이그레이션 설명을 넣지 않는다.

목록을 준비한 뒤에는 미입력 상태에서도 `회원가입` 버튼을 활성화한다. 사용자가 제출하면 잘못된 필드에 오류와 초점을 제공한다. 목록을 사용할 수 없거나 가입 처리 중일 때만 이메일 가입 제출을 비활성화하고 이유를 보이는 텍스트로 알린다. 목록 장애가 기존 로그인 링크와 간편 가입 버튼까지 막지는 않는다. 간편 가입으로 인증한 사용자도 정보 보완을 마쳐야 업무 화면으로 갈 수 있다.

확인 메일이 필요한 가입 성공은 기존 확인 메일 안내와 로그인 링크로 폼을 교체한다. 메일 확인 없이 세션이 생기면 완료 상태와 멤버십을 확인하는 기존 인증 진입 흐름을 따른다. 선택했다는 이유로 회사 가입·권한 승인이 끝났다는 문구를 표시하지 않는다.

## 4. `/auth/complete-profile`

제목은 `필수 정보 입력`, 설명은 `서비스를 이용하려면 이름과 부서, 직급/직책을 확인해 주세요.`다. 같은 인증 틀 안에서 회사 → 이름 → 부서 → 직급/직책 → 공통 안내 → 폼 오류 → `저장하고 계속` → `로그아웃` 순서로 배치한다. 이메일·비밀번호·약관·선택 연락처 입력을 다시 요구하지 않는다.

기존 이름이 있으면 그대로 채워 수정 가능하게 하고, 없거나 유효하지 않으면 수정할 수 있도록 표시한다. 현재 승인 목록에 속한 기존 선택값은 유지한다. 값이 없으면 placeholder, 더 이상 유효하지 않은 값은 미선택 상태와 `선택한 항목을 사용할 수 없습니다. 다시 선택해 주세요.` 오류를 표시한다. 비슷한 이름의 부서나 첫 항목으로 자동 교체하지 않는다. 기존 프로필을 불러오기 전에 빈 기본값으로 저장할 수 없어야 한다.

저장 중 카피는 `저장 중…`이다. 이름·두 선택값은 함께 저장하며, 저장 실패는 세 필드의 현재 입력을 유지한다. `PATCH /api/v1/me/employment`의 200 응답에 포함된 서버 계산 `EmploymentState.profileComplete`가 `true`이면 저장과 완료 확인을 충족하며 기존 진입 정책에 따라 이동한다. 별도의 GET 확인 요청이나 확인 전용 버튼은 요구하지 않는다. 저장 응답이 미완료이면 현재 입력을 유지한 채 보완 화면에 머물고 `필수 정보를 확인해 주세요.`와 해당 필드 안내를 표시한다. 필요한 정보를 수정한 뒤 같은 `저장하고 계속` 버튼으로 다시 제출한다.

### 완료 후 이동과 계정 이탈

- 서버에서 이미 완료로 확인된 사용자가 직접 이 경로에 오면 편집 폼을 다시 요구하지 않고 기존 인증 진입 경로로 보낸다. 완료 화면에서 이름과 부서를 다시 선택하는 반복을 만들지 않는다.
- 원래 요청한 경로가 있으면 검증된 같은 서비스 내부 목적지에만 복귀한다. 외부 URL·다른 도메인·인증/보완 경로로 되돌아가는 목적지는 버리고 기본 업무 진입 경로를 사용한다. 목적지가 존재해도 현재 사용자의 접근 권한을 다시 확인한다.
- 완료 후에도 초대·멤버십 확인을 따른다. 조직 접근 권한이 없다면 기존 초대/접근 안내를 보여 준다. 이 경우 정보 보완 화면으로 되돌리지 않는다. 정보 입력만으로 솔리데오 조직에 자동 합류하지 않는다.
- 보완 전에도 `로그아웃`은 항상 찾을 수 있다. 조회 오류·빈 목록에서도 사용할 수 있고, 저장 요청 중에도 별도 동작으로 제공한다. 로그아웃이 시작되면 늦게 도착한 저장 성공 응답이 업무 이동을 유발하지 않게 한다.
- 로그아웃 성공은 `/auth/login`으로 이동한다. 실패는 현재 입력을 유지한 채 `로그아웃하지 못했습니다. 다시 시도해 주세요.`와 재시도를 제공한다. 현재 세션을 유지한 채 로그인 화면으로만 보내는 동작으로 대체하지 않는다.
- 세션이 끝났으면 `로그인이 필요합니다. 다시 로그인해 주세요.`와 `로그인`을 표시한다. 보완·로그아웃·초대 안내처럼 계정 정리에 필요한 경로는 미완료 가드 때문에 반복 이동하지 않는다. 새 조직 생성이나 자동 초대 수락을 추가하지 않는다.

## 5. 선택 목록·긴 표시명

선택지는 승인된 공개 가입 카탈로그 응답에서만 얻는다. 이름이나 원본 파일을 화면에서 읽지 않으며 부서·직급 목록을 UI에 별도로 하드코딩하지 않는다. 서버가 제공한 순서와 표시명을 사용하고, ID·버전은 내부 데이터로만 취급한다. 동일 팀명은 승인 목록에서 한 번만 나타나며 화면에서 임의 병합·번역·서열 재정렬하지 않는다. 직급은 부서에 따라 임의로 필터링하지 않는다. 자유 입력·직접 추가·`기타`·빈 선택 항목을 새로 만들지 않는다.

기존 `SelectTrigger` / `SelectValue` / `SelectContent` / `SelectItem`을 사용한다. 팝업은 트리거 폭을 기준으로 하고 화면의 가용 높이 안에서 세로로 스크롤한다. 화면 아래쪽에서는 위로 열릴 수 있다. 기존 포털·스크롤 화살표·선택 체크 표시는 유지한다. 조회 실패/빈 목록을 선택 가능한 항목으로 넣지 않는다.

긴 표시명은 닫힌 트리거에서는 한 줄 말줄임하되 전체 값이 접근 가능한 이름에 남아야 한다. 말줄임된 선택값의 전체 표시명은 해당 필드 아래 설명으로도 줄바꿈하여 보여 준다. 팝업 항목에서는 호출부의 텍스트 래퍼로 긴 표시명을 줄바꿈해 전체를 읽게 하고 항목 높이를 늘린다. 기존 primitive를 수정하거나 hover tooltip에만 의존하지 않는다. 체크 아이콘 영역을 침범하거나 가로 스크롤을 만들지 않는다. 목록이 길어도 키보드로 마지막 항목까지 접근 가능해야 한다.

## 6. 상태표

| 상태 | 언제 | 보이는 것 | 사용자가 할 수 있는 것 |
|---|---|---|---|
| 최초 로딩 | 선택 목록을 읽는 동안 | 두 라벨과 40px 컨트롤 자리를 유지하는 Skeleton, `선택 목록을 불러오는 중입니다.`. 제출 비활성 | 가입의 다른 필드 입력, 로그인·간편 가입 이동. 보완 화면은 로그아웃 |
| 프로필 로딩 | 보완 화면에서 기존 정보 조회 중 | 이름·선택 필드 자리를 유지하는 Skeleton, `정보를 불러오는 중입니다.`. 제출 비활성 | 로그아웃. 로딩 완료가 입력 중 값을 덮어쓰는 흐름은 만들지 않음 |
| 준비·미선택 | 조회 성공, 선택 없음 | placeholder, 오류 없음, 제출 활성 | 각 목록 선택 또는 제출하여 필수 오류 확인 |
| 빈 목록 | 부서 또는 직급 목록이 비어 있음 | 정보 아이콘과 `선택할 부서 또는 직급/직책이 없습니다.` 및 `목록 다시 불러오기`. 해당 Select와 제출 비활성 | 목록 재조회, 기존 입력 유지, 로그인/로그아웃 |
| 목록 오류 | 선택 목록 조회 실패·사용할 수 없는 응답 | `불러오지 못했습니다`와 `선택 목록을 다시 불러와 주세요.`, `다시 시도`. 제출 비활성 | 실패한 조회 재시도, 다른 입력 유지, 계정 이탈 |
| 프로필 오류 | 기존 정보 조회 실패 | `불러오지 못했습니다`, `다시 시도`. 미확인 값을 빈 값으로 저장하지 않음 | 조회 재시도 또는 로그아웃 |
| 필드 오류 | 이름 오류·필수 선택 누락 | 해당 칸 아래 오류, 오류 테두리, 첫 오류 필드에 초점 | 입력/선택 수정. 최초 제출 이후 수정한 필드 재검증 |
| 목록 변경 | 선택한 값이 서버에서 거절되거나 새 목록에서 사라짐 | 해당 필드에 `선택한 항목을 사용할 수 없습니다. 다시 선택해 주세요.` | 새 목록 조회 후 해당 필드 재선택. 이름·다른 유효 선택·가입 입력 유지 |
| 처리 중 | 가입/보완 제출 중 | `가입 중…` / `저장 중…`, 필요 시 아이콘과 텍스트 병기, 폼 busy 상태 | 중복 제출 불가. 입력 컨트롤은 비활성. 보완의 로그아웃은 별도 제공 |
| 가입 실패 | 인증 가입 요청 실패 | 기존 가입 오류 영역에 한국어 안내와 필드별 오류. 입력 보존 | 오류 수정 후 `회원가입` 재시도 |
| 저장 실패 | 보완 저장 요청 실패 | 제출 위 `저장하지 못했습니다. 입력한 내용을 확인하고 다시 시도해 주세요.`. 입력·선택 보존, 버튼 재활성 | 수정하거나 같은 `저장하고 계속` 버튼으로 재시도, 로그아웃 |
| 요청 제한 | 다시 시도까지 기다려야 함 | `잠시 후 다시 시도해 주세요.`. 서버가 알려 준 경우에만 대기 안내 | 입력 보존. 실제 재시도 가능한 때 버튼 재활성 |
| 가입 성공·메일 확인 | 확인 메일 발송 응답 | 기존 확인 메일 안내, `로그인` 링크. 폼·간편 가입 버튼 제거 | 메일 확인 또는 로그인 |
| 저장 성공·완료 | 저장 응답의 서버 계산 완료 상태가 참 | `정보를 저장했습니다.` 상태 안내 후 기존 진입 정책에 따라 이동 | 안전한 내부 목적지 또는 기존 초대/접근 안내로 진행 |
| 저장 응답·미완료 | 저장 응답의 서버 계산 완료 상태가 거짓 | 현재 입력 유지, `필수 정보를 확인해 주세요.`와 해당 필드 안내. 보완 화면 유지 | 필요한 정보 수정 후 `저장하고 계속`으로 재제출 또는 로그아웃 |
| 접근 권한 없음 | 정보 완료 후 멤버십이 없음·대상 경로 권한 없음 | 기존 초대/접근 안내. 정보 보완 성공을 권한 승인으로 표시하지 않음 | 기존 초대 안내와 계정 이탈 동작 사용 |
| 세션 만료 | 보완 조회/저장 때 로그인 필요 | `로그인이 필요합니다. 다시 로그인해 주세요.`, `로그인` | 로그인 후 저장된 정보부터 다시 확인 |

조회·저장 실패의 상세 원인은 서버가 제공한 사용자용 한국어 안내만 추가한다. 지원용 요청 번호가 있으면 기존 오류 규칙대로 보조 텍스트로 표시한다. 원시 오류·스택·필드 코드·환경 설정 명령은 제품 카피에 노출하지 않는다. 입력 보존은 현재 화면의 실패·재시도 동안의 보존이며 로그아웃 후 비밀번호나 개인정보를 별도 저장하는 기능을 뜻하지 않는다.

## 7. 접근성과 토큰 매핑

| 역할 | 기존 부품·토큰 |
|---|---|
| 화면 틀·제목 | `AccountCard`, `AccountHeader`; `background`, `foreground`, `type-title` |
| 본문·보조 안내 | `type-body`, `type-label`, `muted-foreground`; Pretendard 기반 `font-sans` |
| 필드·오류 | `Field`, `FieldLabel`, `FieldDescription`, `FieldError`; `input`, `destructive` |
| 입력·선택 | `Input`, 기존 `Select` 조합; `background`, `foreground`, `popover`, `popover-foreground`, `accent`, `accent-foreground` |
| 초점·테두리 | 기존 `ring` 초점 링, `border`, `input`; 오류는 텍스트와 `destructive` 테두리 병기 |
| 동작 | `Button` 기본 주요 버튼 하나, 재시도 `outline`, 로그아웃 `ghost`, 기존 `AccountLink` |
| 로딩·아이콘 | `Skeleton`, `muted`, `lucide-react` 16px; 로딩 텍스트 병기 |

기존 primitive와 토큰으로 충분하다. 두 화면이 공유할 회사·이름·선택 필드 묶음은 기존 부품을 조합해 표현할 수 있다. 새 primitive·새 토큰·새 라이브러리 승인을 요구하지 않는다.

- 라벨을 실제 Input/Select 트리거와 연결한다. 필수 상태와 `aria-invalid`, 안내·오류 `aria-describedby`를 함께 제공한다. 오류가 없는 칸을 오류 상태로 읽지 않게 한다.
- 탭 순서는 보이는 순서와 같다. 회사는 건너뛰고 이름 → 부서 → 직급/직책 → 나머지 필드/버튼 → 하단 링크로 진행한다. 팝업을 닫으면 기존 순서로 이어져야 한다.
- Select는 키보드로 열기, 위/아래 이동, Enter 선택, Escape 취소·닫기를 지원한다. 열었을 때 현재 선택 항목을 찾을 수 있고, 닫으면 트리거에 초점이 돌아온다. Tab으로 밖으로 나갈 수 있으며 팝업에 초점이 갇히지 않는다. 라이브러리의 기본 문자 탐색 동작을 방해하지 않는다.
- 제출 검증 실패는 첫 오류 Input/Select 트리거로 이동한다. 일반 서버 오류는 제출 위 오류 영역에 알림을 제공하고 다시 시도할 버튼에 도달 가능하게 한다. 조회·저장 성공 상태는 `role="status"` 등으로 알린다. 오류 알림의 중복 낭독을 피한다.
- 초점 링이 팝업·스크롤·버튼 비활성 전환에 가려지지 않게 한다. 팝업 애니메이션은 움직임 줄이기 설정을 존중한다. 선택·오류·필수 의미는 색만으로 전달하지 않는다.
- 1440px와 1280px 모두 긴 이름·긴 표시명·여러 필드 오류·열린 팝업 상태에서 가로 넘침이 없어야 한다. 세로 공간이 부족해도 제목·오류·로그아웃까지 문서 스크롤로 접근 가능해야 한다.

## 8. 구현자·QA 요구사항 체크리스트

- [ ] 고정 회사 `솔리데오`가 두 화면에 보이고 회사 선택·권한 선택이 없다.
- [ ] 가입 폼의 이름 바로 아래에 부서·직급/직책 필수 Select가 있다. 최초 값은 미선택이다.
- [ ] 보완 화면은 기존 유효 이름·선택을 유지하고 누락된 이름도 입력받는다. 실제 이름 검증은 1~40자다.
- [ ] 두 화면이 같은 승인 공개 카탈로그를 사용한다. UI 자체 선택 목록·직원 이름·원본 연락처·사진 데이터가 없다.
- [ ] 빈 값·알 수 없는 선택을 제출하면 해당 칸 오류가 보이고 첫 오류에 초점이 간다.
- [ ] 목록 로딩·빈 목록·조회 실패에서 제출이 막히며 이유·재시도·계정 이탈이 보인다.
- [ ] 선택 목록 재조회와 저장 실패가 이름·현재 선택·기존 가입 입력을 지우지 않는다. 실패 뒤 버튼을 다시 사용할 수 있다.
- [ ] 저장 중 중복 제출이 불가능하고, 저장 응답의 서버 계산 `profileComplete=true`를 확인한 뒤 기존 진입 정책에 따라 이동한다. 별도 확인 요청·전용 재시도 버튼을 요구하지 않는다.
- [ ] 저장 응답이 미완료이면 현재 입력과 보완 화면을 유지하고 필요한 수정·재제출을 안내한다. 이미 완료된 계정은 보완 화면을 반복하지 않는다.
- [ ] OAuth·기존 미완료 계정·이름 누락 계정이 보완 화면으로 진입한다. 완료 계정은 기존 진입 정책을 따른다.
- [ ] 저장 전후 모두 로그아웃 경로가 유효하다. 조회/저장/로그아웃 오류와 세션 만료에서 이동 반복이 없다.
- [ ] 완료 후 검증된 내부 목적지만 사용하고, 권한 없음은 기존 초대/접근 안내로 처리한다. 자동 조직 합류가 없다.
- [ ] 기존 이메일·비밀번호·약관 검증·간편 가입·확인 메일 동작을 유지한다. 새 필수 수집 항목이 기존 개인정보 안내에 반영된다.
- [ ] 1440px·1280px에서 400px 인증 단폭·간격·본문 스크롤과 긴 표시명 전체 읽기를 확인한다.
- [ ] 마우스 없이 Select 열기/선택/닫기, 오류 수정, 저장 재시도, 로그아웃까지 수행한다. 라벨·오류 연결·초점 링을 확인한다.
- [ ] 새 색·글꼴·토큰·primitive·모바일/결제 화면이 추가되지 않는다.

이 문서는 화면 설계 산출물이다. 현재 상태표와 체크리스트는 구현 후 검수 기준이며, 브라우저 검수나 기능 테스트를 이미 통과했다는 뜻이 아니다. 이 문서 작성 단계에서는 코드·토큰·생성물을 변경하지 않는다.

## 열린 질문

현재 승인 범위의 화면 설계를 막는 미결정 사항은 없다. 실제 부서·직급 표시명과 개수는 승인 공개 카탈로그의 산출물을 사용하고, 구현·QA는 그 목록에서 가장 긴 항목도 확인한다. 개인정보 안내의 새 항목 표시 외에 기존 약관 정책을 새로 확정하지 않는다.

## 구현 중 확인한 호환 확장: 보완 전 계정 관리

기존 계정 정리 접근을 유지하기 위한 2026-10-16 설계 보완이다. 사용자 결정이 필요한 새 기능은 추가하지 않는다. 아래의 로그인 세션은 기존 계정 상태 정책에서 사용 가능한 세션을 뜻하며, 정지 계정 안내·권한은 기존 규칙을 따른다.

### 디자인 스펙 확장: 가입 보완 전 계정 관리

#### 기준과 범위

승인된 `polaris/specs/done/2026-10-16-solideo-signup-ui.md` §4의 계정 정리·복구 접근을 구체화한다. 현재 `/account`는 로그인으로 보내는 호환 경로이고 실제 계정 UI는 조직 레이아웃 안의 `web/app/(app)/[slug]/settings/page.tsx`에 있다. 필수 정보 가드 뒤에 있는 설정만으로는 보완 전 계정 정리를 제공할 수 없으므로, 조직 밖 `/auth/account`에 기존 계정 화면의 구역을 재사용한다.

코드로 기존 구조를 확인했다. 브라우저 검수 결과는 아니다. 참고한 자료는 `.claude/agents/web-designer.md`, `.claude/skills/design-system/SKILL.md`, 승인 UI 스펙, `auth/account-card.tsx`, `components/auth-frame.tsx`, 기존 설정 페이지·`SettingsSection`·`LoginMethods`·`SessionActions`·`DeleteAccount`·`DisplayNameForm`·`SignOutButton`이다. 카피는 구현·검수용 초안이다.

새 계정 기능이나 권한 정책을 추가하지 않는다. 기존 설정 자체를 재설계하지 않는다. 화면 구성·데이터 준비를 공통으로 추출하여 두 진입점에서 사용하고, 조회·행 변환·동작 로직을 복사하지 않는다. 기존 도메인 접근·RLS·마지막 로그인 수단 해제 방지·탈퇴 제한·복구 의미를 유지한다. 조직 데이터·조직 탐색·팀 관리·회사 선택·새 가입 정보 편집 구역은 이 화면에 넣지 않는다.

#### 흐름과 정확한 경로

- `/auth/complete-profile`: 기존 `저장하고 계속` 아래에 `AccountLink`의 `계정 관리` 링크(`/auth/account`) 한 줄을 추가하고, 그 아래 기존 `로그아웃`을 유지한다. 입력 필드·설명·400px 단폭은 그대로다. 계정 링크는 목록/프로필 로딩·빈 목록·조회 실패에도 보인다. 저장 요청 중에도 계정 이탈을 사용할 수 있으며, 이탈이 시작되면 늦은 저장 응답이 업무 이동을 일으키지 않는다. 보완 폼의 임시 입력을 다른 경로까지 영속 보존하는 새 기능은 요구하지 않는다.
- `/auth/account`: 유효한 로그인 세션이 있으면 프로필 완료 여부나 조직 멤버십 때문에 보완 화면으로 자동 이동하지 않는다. 조직 레이아웃·`requireWorkspace`를 통해 열지 않는다. 직접 접근과 OAuth 연결 복귀도 같은 화면을 연다.
- 계정 화면 헤더 바로 아래 `필수 정보 입력으로 돌아가기` 링크는 `/auth/complete-profile`로 간다. 미완료 계정은 저장된 프로필부터 보완하고, 이미 완료된 계정은 기존 보완 경로의 완료 판정에 따라 정상 인증 진입으로 이동한다. 계정 화면을 완료 후 업무 복귀 목적지로 자동 채택하지 않는다. 기존에 전달하던 검증된 업무 목적지가 있다면 기존 안전한 내부 경로 규칙을 유지한다.
- 계정의 비밀번호 재설정 링크는 기존 `/auth/reset`이다. 기존 메일·복구·`/auth/password` 흐름을 보완 가드로 가로막지 않는다. 로그인 수단 연결은 기존 `/auth/callback?next=…&flow=link`를 사용하고 `settingsPath`를 `/auth/account`로 넘겨 결과가 이 화면에 돌아오게 한다. 연결 결과를 확인하기 전에 보완으로 보내지 않는다.
- 로컬/전체 로그아웃 성공은 기존 `/auth/login`, 탈퇴 성공은 기존 `/`로 간다. 세션이 없는 계정 화면 접근은 기존 로그인 흐름으로 보낸다. 로그인 후에는 완료 여부를 다시 판단한다. 계정 → 보완 → 계정의 자동 반복 이동을 만들지 않는다.

#### `/auth/account` 구조와 기존 부품

`AccountCard`/`AccountHeader`를 사용한다. 제목은 `계정 관리`, 설명은 `프로필과 로그인 정보를 관리합니다.`다. `main#main-content`와 `h1`은 각각 하나다. 로고·사이드바·조직 메뉴·설정 탭·추가 카드 없이 흰 인증 바탕을 쓴다.

가로 중앙 `max-w-100`(400px), 기존 `px-4`, 데스크톱 `py-16`, 내부 `my-auto`를 유지한다. 헤더 묶음과 다음 내용은 `gap-6`, 복귀 링크는 가운데 정렬 `type-body`다. 구역 묶음은 기존 `divide-y divide-border`, 각 `SettingsSection`의 `py-8`, 제목·설명·내용 간격과 기존 컨트롤을 재사용한다. 이 폭에서는 다섯 구역 모두 제목·설명 위, 내용 아래의 한 열이다. 고정 높이·중첩 세로 스크롤을 만들지 않는다. 페이지 전체 스크롤로 마지막 탈퇴 구역에 도달한다.

| 순서 | 기존 구역·내용 | 재사용 기준 |
|---|---|---|
| 1 | 프로필: 기존 아바타, 이름, 이메일/없음 안내, 계정 유형, 표시 이름 수정·저장 | 기존 프로필 렌더링과 `DisplayNameForm`. 이름이 없어도 기본 이름을 지어내 저장하지 않음. 계정 유형을 조직 권한 선택으로 바꾸지 않음 |
| 2 | 로그인 수단: 기존 제공자 순서·연결/해제·마지막 수단 안내 | `LoginMethods`, 기존 행 변환 및 `canUnlink`, `LOGIN_METHODS_HEADING_ID`, 연결 결과 처리 |

프로필 저장은 기존 주요 버튼 하나, 연결·재설정·세션 동작은 기존 `outline`, 복귀는 텍스트 링크, 탈퇴는 기존 `destructive`다. 프로필과 로그인 수단의 사용자 데이터만 기존 본인 조회로 준비한다. 계정 정리 화면을 열기 위해 가입 카탈로그나 조직 업무 데이터를 읽어야 하는 의존성을 추가하지 않는다.

#### 토큰·접근성·검수 기준

새 토큰·primitive·의존성은 필요 없다. `background`/`foreground`, `border`, `input`, `muted`/`muted-foreground`, `primary`, `destructive`, `ring`과 기존 제공자 표시 토큰을 사용한다. 글꼴은 기존 `font-sans`, 화면 제목 `type-title`, 구역 제목 `type-heading`, 본문 `type-body`, 라벨/오류 `type-label`, 기존 메타 정보 `type-caption`이다. 기존 40px 입력·36px 기본 버튼·32px 작은 버튼·8px 모서리를 유지한다.

- 1440px·1280px 모두 보완 화면과 계정 화면의 단폭이 400px이다. 보완 화면 변경은 링크 한 줄이며 계정 제어부를 보완 폼 안에 펼치지 않는다.
- 두 폭에서 긴 이메일·이름·제공자 안내가 구역이나 버튼을 밀어 가로 스크롤을 만들지 않는다. 기존 말줄임·전체 값 확인 방식을 유지하며, 긴 계정 텍스트는 필요한 곳에 줄바꿈한다.
- 페이지 높이가 창을 넘을 때 제목·복귀 링크·모든 계정 구역·탈퇴까지 문서 스크롤로 접근한다. 세션 버튼은 겹치지 않고 줄바꿈한다.
- 키보드 순서는 복귀 링크 → 프로필 컨트롤 → 로그인 수단 → 재설정 → 세션 → 탈퇴의 시각 순서다. 기존 라벨·필드 오류 연결·초점 링·Dialog 초점 관리를 유지한다. unlink 후 사라진 버튼으로 초점을 돌리지 않는다.
- OAuth 성공 복귀는 로그인 수단 제목, OAuth 실패 복귀는 기존 오류 안내로 초점을 보내고 결과 쿼리를 제거하는 기존 동작을 유지한다. 새 링크의 초점은 `AccountLink`의 `ring`을 사용한다.
- 보완 로딩·목록 빈 상태·조회 실패에서 `계정 관리`와 로그아웃을 찾을 수 있다. 계정 조회 실패에서도 복귀·재시도·로그아웃에 도달한다.
- 미완료·완료·멤버십 없음·세션 만료 각각에서 직접 `/auth/account` 접근, 보완 왕복, 로그인 수단 연결 복귀, 비밀번호 복구, 로그아웃을 확인한다. 조직 업무 화면/API 차단은 계속 유지한다.
- 기존 이름 저장·연결/해제·마지막 로그인 수단 보호·복구·로컬/전체 로그아웃·탈퇴 확인/거절 동작이 두 계정 진입점에서 같아야 한다. 이 항목은 구현 후 QA 기준이며 현재 검증 통과를 뜻하지 않는다.

#### 구현 경계와 열린 질문

컨트롤·본인 조회·로그인 수단 행 준비를 공유하는 최소 추출 위치는 구현자가 기존 계층 규칙에 맞춰 정한다. 호출자가 확인한 현재 인증 구현은 같은 서비스 `/auth/account`를 기존 `safeNextPath`로 허용하고 `flow=link`는 보완 검사 전에 연결 결과로 복귀한다. 이 확장을 위해 인증 도메인의 허용목록이나 복구 정책을 재설계할 필요는 없다. 실제 회귀는 구현 검증으로 확인한다.

승인된 호환 범위 안에서 추가 사용자 결정은 필요 없다. 설계 산출물만 작성하며 런타임 코드·테스트·토큰·승인 원문은 이 작업에서 변경하지 않는다.

| 활동 계정 + 정보 완료 + 업무 조직 2개 이상 | `/auth/organization-state`의 지원되지 않는 계정 안내. 임의 첫 조직으로 들어가지 않음                      |
| 본인/조직 상태 조회 실패                   | 조회 실패 화면. 업무 이동 없이 재시도·계정 관리·로그아웃 제공                                             |

이메일 가입·확인 메일·성공한 간편 로그인·기존 계정 로그인은 이 판정으로 합류한다. 가입 완료를 개인 조직 생성 성공 또는 업무 권한 부여로 안내하지 않는다. 기존 가입 폼·메일 안내·소셜 버튼과 필수 입력 구조는 유지한다.

### 안전한 업무 복귀

- 기본 업무 재진입 주소는 `/dashboard`다. 이번 좁은 확장에서는 `/dashboard`가 서버가 고른 실제 업무 조직의 기존 대시보드로 연결하는 브리지여도 된다. 신규 전체 앱 셸이나 미출시 업무 경로가 완성됐다고 표시하지 않는다.
- `/auth/organization-state`는 필요할 때 `next` 하나로 검증된 기존 업무 목적지를 이어받을 수 있다. `orgId`·회사·slug 선택 입력은 받지 않는다. 값이 반복되거나 문자열이 아니면 기본 목적지를 사용한다.
- 기존 `safeNextPath`·`safeEmploymentNext`와 실제 지원 업무 경로 검증을 재사용한다. 외부 출처, `//`, 역슬래시·인코딩 우회, `/auth/*` 반복 목적지, 지원하지 않는 업무 경로는 기본 `/dashboard`로 정리한다. 현재 조직과 다른 legacy slug 경로는 해당 조직 데이터로 이동시키지 않으며 기존 404 정책을 유지한다.
- `safeEmploymentNext`의 `/auth/*` 차단을 넓히지 않는다. 보완 `next`에 `/auth/organization-state`를 넣지 않는다. 보완의 `next`는 안전한 업무 경로이고 그 업무 진입점이 현재 완료 상태와 조직 상태를 다시 판정한다. 기본 경로도 `/dashboard`다.
- 완료된 사용자가 `/auth/complete-profile`을 직접 열어도 같은 재진입 판정을 거친다. 보완 → 로그인 → 개인 조직 없음 → 보완 같은 반복을 만들지 않는다.
- 상태 화면의 `다시 확인`·조회 실패의 `다시 시도`·계정 화면의 복귀는 서버 상태를 재조회한다. 이전에 선택한 조직·쿼리·브라우저 캐시만으로 업무 진입시키지 않는다.
- 계정·초대에서의 복귀는 명시적인 링크다. 브라우저 history에 의존하는 뒤로가기를 사용하지 않는다. 계정 화면을 보완 성공 후 자동 업무 목적지로 만들지 않는다.

### 보완·계정·초대의 연결

`/auth/complete-profile`의 기존 폼, `계정 관리` 링크, 로그아웃과 실패 시 입력 보존을 유지한다. 저장 응답이 완료면 검증된 업무 재진입 주소로 이동한다. 저장 성공이 조직 합류 성공을 뜻하지 않는다. 계정 이동·로그아웃이 시작된 뒤 늦은 저장/조회 응답이 업무 이동을 일으키지 않는 기존 동작을 유지한다.

`/auth/account`의 기존 `필수 정보 입력으로 돌아가기`를 **`서비스로 돌아가기`**로 바꾸고 `/auth/organization-state`에 연결한다. 로딩·조회 실패 화면에서도 같은 링크를 사용한다. 완료 여부를 모르거나 조직이 없어도 의미가 맞고, 추가 본인/조직 조회를 해야만 링크를 렌더링하는 의존성이 없다. 상태 경로는 미완료면 보완으로, 완료+0/복수면 안내로, 완료+1이면 업무로 보낸다. 기존 다섯 구역의 데이터·계정 동작·OAuth `flow=link` 복귀 `/auth/account`·성공 초점·실패 안내는 유지한다. 기존 비밀번호 복구·로컬/전체 로그아웃·탈퇴 제한도 유지한다.

`/invitations`는 기존 받은 초대 화면을 사용한다. 이메일별 초대 조회·만료·정렬·수락/거절·빈 목록을 유지하고 새 초대 목록을 상태 안내 화면에 중복 구현하지 않는다. 개인 조직의 `homeSlug` 유무로 복귀 링크를 숨기거나 기본 조직을 고르지 않는다. 목록 아래 공통 복귀/이탈 줄에 `서비스로 돌아가기`(`/auth/organization-state`) → `계정 관리`(`/auth/account`) → 기존 로컬 `로그아웃` 순으로 둔다. 로딩·빈 목록·조회 실패에도 이 줄은 도달 가능하다.

초대 직접 접근은 보완 전에도 허용한다. 초대를 수락한 뒤 기존 `result.slug`를 그대로 업무 이동 권한으로 사용하지 않는다. 기존 수락 결과를 표시한 후 안전한 업무 재진입 판정을 다시 거친다. 미완료면 보완, 완료+1이면 현재 실제 조직, 완료+복수면 정확한 지원 불가 안내가 된다. 추가 멤버십 생성·거부 정책 자체를 새로 만들지 않으며 서버/DB의 기존 초대 제약을 유지한다. 초대 거절은 기존 목록 갱신과 삭제된 행의 다음 행동으로 초점 이동을 유지한다.

| 조회 실패                  | 초대 조회가 실패                   | `받은 초대를 불러오지 못했습니다. 다시 시도해 주세요.`, outline `다시 시도`, 공통 복귀/이탈 줄 | 목록 재조회·복귀·계정 관리·로그아웃. 실패를 빈 목록으로 표시하지 않음       |
| 수락/거절 중               | 기존 행 요청 처리                  | 기존 진행 문구·중복 방지. 임의 대시보드 미리 표시 없음                                         | 기존 허용 동작·페이지 이탈                                                  |
| 수락 성공                  | 기존 초대 수락이 성공              | 기존 수락 알림 후 완료·실제 업무 조직 재판정                                                   | 미완료 보완 또는 현재 조직 업무 또는 복수 상태 안내                         |
| 거절 성공·만료·수락 실패   | 기존 도메인 결과                   | 기존 행 제거·초점·만료·취소/오류 문구                                                          | 허용된 재시도·다른 초대 처리·복귀·계정 정리                                 |
| 로그인 필요·정지           | 기존 인증 결과                     | 기존 계정 상태 처리                                                                            | 기존 로그인·로그아웃. 조직 상태 때문에 초대 안내를 반복 리다이렉트하지 않음 |

### 1440px · 1280px

두 승인 폭 모두 동일한 400px 인증 단폭·한 열·간격이다. 1280px 미만 전용 레이아웃을 설계하지 않는다. 긴 복수 조직 안내·이메일·초대 조직명·여러 오류는 단 안에서 줄바꿈하고 가로 넘침을 만들지 않는다. `AuthFrame`의 `my-auto`를 유지하여 화면이 짧아질 때 제목이 위로 잘리지 않게 한다. 고정 높이·중첩 세로 스크롤 없이 페이지 스크롤로 마지막 로그아웃/탈퇴까지 도달한다.

## 접근성 체크 항목

- 화면당 `main#main-content`와 `h1`을 하나씩 사용한다. 기존 건너뛰기 링크·`tabIndex=-1`를 유지한다. 상태 경로 안에 별도 `main`을 만들지 않는다.
- 키보드 순서는 상태 설명 → 받은 초대 버튼(0개만) → 재확인/재시도 → 계정 관리 → 로그아웃이다. 계정·초대 복귀 줄도 보이는 순서대로 이동한다.
- 로딩/재조회는 `role=status`, 조회/동작 오류는 기존 패턴의 `role=alert`로 전달한다. Skeleton은 `aria-hidden`이고 움직임 줄이기 설정을 존중한다. 동일한 문장을 여러 live 영역으로 중복 낭독하지 않는다.
- 재조회 후 같은 상태이면 활성화된 재시도 버튼에 초점을 유지한다. 상태가 바뀌어 버튼이 사라지는 경우 새 상태 제목/안내에 초점을 보낸다. 서버가 업무로 이동한 경우 목적지의 기존 페이지 초점 처리를 따른다.
- 새 링크는 `AccountLink` 또는 `cn(buttonVariants(...), ...)`로 만들고 기존 focus-visible 링을 유지한다. 아이콘만 있는 새 동작은 필요 없다.
- 지원 불가 의미는 본문으로 전달한다. 빨간색만으로 오류를 표현하지 않는다. 원시 코드·스택·SQL·연락처·개인/타 조직 이름을 노출하지 않는다.
- 기존 v1 오류 계약이 유효한 지원 요청 번호를 주는 경우 승인된 검증·표시 패턴으로만 보조 표시한다. 조회 재시도 시작 시 이전 번호를 지운다. 상태 안내 자체에 새 요청 번호 API를 요구하지 않는다.
- 계정 Dialog·로그인 수단 해제 후 초점·초대 행 삭제 후 초점과 기존 이름/선택 입력의 label·오류 연결을 유지한다.
- 계정/로그아웃 이탈 후 늦은 재조회·저장 응답이 원래 화면으로 돌아가거나 업무로 이동시키지 않는다. 로딩·오류에도 이탈 경로가 키보드로 도달 가능해야 한다.

## 구현자·독립 QA 인계 기준

- [ ] 기존 개인 조직만 가진 완료 계정도 업무 조직 0개로 안내한다. 기존 개인 조직 행은 유지되고 업무 접근 목적지로 선택되지 않는다.
- [ ] 신규 이메일/OAuth 계정에 개인 조직이 없어도 본인 프로필이 유효하면 프로필 없음 오류를 표시하지 않는다. 필수 보완과 확인 메일 동작은 유지한다.
- [ ] 업무 조직 0/1/2+ 모두 서버 실제 멤버십으로 판정하고, 회사 신고·권한 메타데이터·요청 orgId로 소속을 선택하지 않는다. 자동 솔리데오 합류·회사/조직 선택 동작이 없다.
- [ ] 미완료+0/1/2+는 업무 진입에서 보완이 먼저다. 완료+0은 받은 초대 링크, 완료+1은 현재 업무 조직, 완료+2+는 확정 문구와 업무 API 403 `UNSUPPORTED_ACCOUNT_STATE`다.
- [ ] 조회 로딩/실패를 0개 또는 프로필 없음으로 오인하지 않는다. 재확인·재시도·로그아웃 실패 후 재실행·늦은 응답 이탈 방지를 확인한다.
- [ ] 0개/복수 상태에서 계정 관리 직접 접근·본인 이름/로그인 수단·복구·로그아웃·탈퇴 제한이 기존과 같다. 전체 로그아웃/탈퇴 Dialog와 결과를 조직 가드가 가로막지 않는다.
- [ ] 계정 정상/로딩/오류의 `서비스로 돌아가기`가 모두 정적 안전 경로이며 미완료/0/1/복수에 맞는 결과로 간다. OAuth 연결 복귀는 계정에 먼저 결과를 보여 준다.
- [ ] 초대 목록·빈 목록·이메일 없음·로딩·조회 실패에서 복귀/계정/로그아웃이 도달 가능하다. 초대 직접 접근은 보완 전에 유지된다.
- [ ] 초대 수락 직후 완료 상태와 실제 업무 조직을 다시 판정한다. 오래 열린 창의 멤버십 변경·복수 조직도 임의 accepted slug로 우회하지 않는다. 기존 초대 제약·거절 초점은 유지된다.
- [ ] 직접 상태 경로·직접 보완 경로·로그인/메일/간편 로그인 성공·업무 URL 직접 진입·새로고침·뒤로가기를 확인한다. 외부/인코딩/auth-loop/반복 next와 타 조직 slug가 안전하게 처리되고 반복 이동이 없다.
- [ ] 1440px·1280px에서 상태 정상/로딩/오류·복수 확정 문구·긴 이메일/초대명·계정 전체 스크롤·키보드 초점·움직임 줄이기를 확인한다.
- [ ] 수정된 계약/경로 회귀 시험과 저장소 정규 검증을 통과한 뒤에만 구현 완료를 주장한다. 이 문서 작성은 위 시험 통과 증거가 아니다.

## 열린 질문

승인된 UI 범위를 막는 사용자 결정은 없다. 두 사항은 구현 계약/검수에서 확인한다.

1. 업무 조직 0개 API의 구체 오류 코드는 정본에 확정되지 않았다. UI는 특정 코드를 새로 요구하지 않는다. 2개 이상은 정본의 403 `UNSUPPORTED_ACCOUNT_STATE`를 그대로 사용한다.
2. 완전한 slug 없는 앱 셸 이행은 별도 범위다. 이번 최소 연결은 `/dashboard`의 서버 선택 브리지와 실제 지원 중인 목적지만 사용한다. 해당 별도 구현 전 미출시 화면으로 버튼을 연결하지 않는다.
