# 업무 화면 정보 정리 디자인 스펙

작성: 2026-10-30. 승인된 방향을 구현하기 위한 명세. 추가 승인 없이 구현한다. 카피는 초안이다.

## 기준과 범위

- 근거: `AGENTS.md`, `docs/CLAUDE.md`, `docs/00-README.md`, `docs/17-CLAUDE-IMPLEMENTATION.md` ADR-046, `docs/06-UI-UX.md` §3.5·5.12, `.claude/agents/web-designer.md`, `.claude/skills/design-system/SKILL.md`, `design/tokens.json`.
- 현재 화면의 page/view·공용 필터·분석 비교·인력 결과 코드를 확인했다. 브라우저 시각 관찰은 하지 않았으므로 실제 줄바꿈·스크롤·포커스는 구현 후 1440px·1280px에서 확인한다. `polaris/mission.md`는 없다. 기존 제품 설계와 승인 범위를 따른다.
- 표시 위계만 변경한다. 계산·데이터 조회·API·권한·저장·URL 계약·백엔드 위치는 유지한다. 모바일·신규 화면·신규 토큰·신규 UI 라이브러리는 범위 밖이다.

## 공통 동작과 흐름

진입 → 업무 정보와 주요 행동 확인 → 필요한 경우 세부정보 펼침 → 기존 분석·검토·필터·비교·시뮬레이션 수행.

- 접기는 기존 네이티브 `<details><summary>` 패턴을 사용한다. 최초 진입·새로고침은 닫힘이며, 접힌 상태에서도 적용 중인 조건과 결과 해석에 필요한 고지는 보인다. 접기 자체로 요청·분석·저장·선택 초기화를 실행하지 않는다.
- DEMO/가상 회사 프로필, mock 응답·저장 공고 기반 분석에 대한 사용자용 안내, PARTIAL/FAILED·정보 부족·오래된 결과·출처 충돌·비교 기준 불일치, 가정 적용 및 추정 기준은 항상 펼친 영역에 둔다. 경고의 제목만 남기고 본문을 모두 접지 않는다.
- 원시 실행 모드 `live`/`fixture`/`mock`와 `runMode`는 모두 접힌 상세정보 안에만 둔다. `live`는 바깥에 별도 실행 모드 표시를 두지 않는다. mock은 `Mock 응답(데모 데이터)`, fixture는 `저장 공고 기반 분석` 안내를 바깥에 표시한다. AI 제공자가 mock이면 실행 모드와 별개로 Mock 안내를 표시한다. 데이터 구분(실제/데모/전체)은 실행 모드와 별개로 유지한다.
- 접힌 기술정보는 삭제하지 않는다. 표시 값·원문·시각의 KST 표기·미확인 값 `—`를 유지한다. 기존 업무 행동과 근거 확인 경로를 보존한다.

## 1. 공고 상세 `/bids/[id]`

대상: `web/app/(app)/(work)/bids/[id]/bid-detail-view.tsx` (`AnalysisBand`; `SummaryLines`의 기존 수집 출처 정보는 유지).

| 기본 노출 | 기본 접힘 |
|---|---|
| 제목·출처·기관·공고번호·예산·마감, 기존 공고 revision·수집 시각·마지막 변경 시각, 원문·관심·분석 행동 | 공고 수집 정보는 이번 접기 대상에서 제외 |
| 분석 상태·완료/접수 시각·Mock 응답/저장 공고 안내·회사 프로필 출처 고지 | `분석 상세 정보`: 원시 실행 모드·알고리즘 버전·분석 기준 공고/프로필 revision·그 외 현재 표시 중인 기술 식별자 |
| 점수·권고·자격·근거·사람의 최종 결정·가정 시나리오·주의 사항 | 기존 `분석 이력` 접기는 유지 |

공고번호는 업무 식별에 사용하므로 남긴다. AI 제공자의 mock 응답과 미응답 등 해석상 제한은 사용자용 안내로 기본 노출한다. 공고 헤더의 기존 provenance는 그대로 유지한다. 분석 중에는 기존처럼 지난 run의 모델·모드를 새 결과처럼 표시하지 않는다. 단계 이력·자격·점수 근거는 이번 접기 대상이 아니다.

## 2. 대시보드 `/dashboard`

대상: `web/app/(app)/(work)/dashboard/dashboard-view.tsx`, 필요 시 `page.tsx`의 설명 문구.

순서: 기존 AI/DEMO/전체 출처 고지 → 업무 요약 숫자 띠 → 우선 검토할 입찰 → 예정 사업 및 사전규격 → **단일 닫힌 `수집 현황·참고 통계`**.

- 기존 다섯 업무 요약 수치는 유지한다. 업무 목록을 본문 전체 폭으로 배치해 닫힌 운영 패널의 빈 오른쪽 칸을 남기지 않는다.
- `IngestMetrics`, `OpportunitySourceStatus`, `TopAgencies`, `Portfolio`를 하나의 details 안에 그대로 유지한다. 중첩 접기는 추가하지 않는다. 수집 조회·지표 계산·props·백엔드 위치를 옮기지 않는다.
- details 안에 기존 목적지 `/market`의 `발주 현황 보기`, 권한이 있는 사용자에게 `/admin/ingestion`의 `수집 관리` 링크를 둔다. `canRunIngestion`을 사용하고 기존 목적지의 서버 권한 검사를 유지한다. 관리자 화면을 대시보드 안에 복제하지 않는다.
- 출처 충돌, 조회 실패, 수집 지연 등 기존 패널의 이상 상태는 details 바깥에 짧은 실제 상태 안내로도 남긴다. 알 수 없는 상태를 정상/0건으로 표시하지 않는다. 상세 원인과 기존 복구 경로는 펼치면 확인한다.
- 빈 공고의 기존 안내·허용된 수집 관리 경로는 기본 노출한다. 운영 패널 오류가 검토 목록을 숨기지 않는다.

## 3. 공고·관심 목록 `/bids`, `/watchlist`

대상: `web/components/work/opportunities-filters.tsx`; 두 경로는 기존 `BidListView`를 공유한다.

- 기본 줄은 **검색 / 기관 / 권고 / 정렬**만 둔다. 기관은 검색 가능한 기존 `MultipleFilter` 한 개다. 검색은 기존 Enter 제출, 나머지는 기존 즉시 URL 반영을 유지한다.
- 아래에 닫힌 `상세 검색` 하나: 분야 키워드, AI·SI 우선, 수집 출처, 예정 사업 포함(`includeEarly`), 단계, 상태, 최종 결정, KEPCO 회사 구분, 데이터 구분. 회사 선택은 기존처럼 선택지가 있을 때만 표시한다.
- 출처 빠른 선택 칩과 중복 출처 선택기를 한 개의 출처 `MultipleFilter`로 통합한다. 기관 빠른 선택과 중복 기관 선택기도 기본 줄의 한 개로 통합한다. `bids-source-nav`의 공고 종류 이동은 필터 중복이 아니므로 유지한다.
- 기본 줄 아래, details **밖**에 `적용 중: …` 요약과 기존 `필터 초기화`를 둔다. URL에서 읽은 검색·기관·권고·비기본 정렬 및 모든 비기본 고급 조건을 사람이 읽는 이름으로 표시한다. 기본 동작인 `진행 중 · AI·SI 우선`도 짧게 알린다. 데이터 구분은 실제/데모/전체 중 현재 값을 항상 표시한다.
- 요약은 긴 조건을 다음 줄로 감싸고 고급 조건을 생략하지 않는다. 요약 자체에 새 개별 해제 기능을 만들 필요는 없다. 상세 검색 제목에는 활성 고급 조건의 **필터 종류 수**를 표시한다(예: 출처 2개 선택은 1종). 필터 값이 있어도 자동으로 펼치지 않는다.
- 쿼리 다중 값, `defaultOrigin`, `stage`↔`includeEarly` 연동, 변경 시 `cursor/limit/asOf` 제거, 뒤로/앞으로 이동을 보존한다. `/watchlist` 초기화는 `/watchlist`에 머물고 관심 한정 조건을 해제하지 않는다. 관심 해제 직후 행 유지도 보존한다.

## 4. 분석 이력·비교 및 인력 배치

| 화면·파일 | 기본 노출 | 닫힌 정보 |
|---|---|---|
| `analysis/analysis-history-view.tsx` | 공고명·DEMO·비교 선택·상태·점수·권고·시각·Mock 응답/저장 공고 안내·오류와 모든 reviewFlags | 행별 `분석 상세 정보`: 원시 실행 모드·공고/프로필 revision·알고리즘. 기존 `분석 기준·주의 사항` 안의 경고를 밖으로 이동하고 revision 전용 열은 없앰 |
| `analysis/analysis-comparison.tsx` | 선택 분석 2~4건·열별 DEMO·Mock 응답/저장 공고 안내·상태·점수·요소·자격·시각·주의/실패·기준 불일치 경고 | 비교표 아래 단일 `비교 기준`: 원시 실행 모드·공고 revision·프로필 revision·알고리즘 행을 같은 분석 열 순서의 보조 표로 이동 |
| `workforce/workforce-results.tsx` | 분석 상태·수행 기간·기본 기간 가정·필요/가용 FTE·추정/정보 부족 이유·팀 지원 요청·후보·현재 배정·충돌·가상 데이터 및 미저장 안내 | 공고별 `계산 기준`: 분석 ID·공고 revision·분석 시각·인력 스냅샷 시각·계산 기준일 |

`analysis/analysis-history-filters.tsx`의 실행 모드 필터도 기본 닫힌 `비교 기준`으로 옮긴다. 알고리즘 버전·공고/프로필 revision 관련 비교 기준 제어가 있으면 같은 영역에 둔다. 활성 요약은 원시 실행 모드 대신 `실제 분석`/`저장 공고 기반 분석`/`Mock 응답(데모 데이터)`로 표시하며 필터 URL·적용 동작은 유지한다.

위 경로의 접두사는 `web/app/(app)/(work)/`다. `/analysis`의 **업무인 이력 목록과 비교 결과 자체는 접지 않는다**. 비교 선택 URL·최대 4건·열별 재시도·선택 해제·비교 제목 포커스 이동은 유지한다. 비교 기준 불일치 검사는 숨겨진 revision도 계속 사용한다.

인력 화면은 `분석 당시 가용`과 `현재 배정` 구분을 계속 노출한다. 접기 제목 옆에 `분석 당시 스냅샷 기준`을 남겨 현재 값으로 오해하지 않게 한다. 수행 기간 DEFAULT 설명·예산 구간 추정·FTE와 실제 인원 차이·후보 부족은 인력 부족 확정이 아니라는 고지는 접지 않는다. 기존 팀 목록의 더 보기는 유지한다.

## 상태·폭·접근성

| 상태 | 언제 | 보이는 것 | 사용자가 할 수 있는 것 |
|---|---|---|---|
| 정상 | 데이터 있음 | 핵심 업무와 닫힌 접기 제목·활성 요약 | 기존 행동, 상세 펼치기/접기 |
| 로딩 | 필터 전환·분석/비교/시뮬레이션 요청 | 기존 pending·상태 표시, 기존 고지 유지 | 기존 허용 행동; 접기는 요청을 만들지 않음 |
| 빈 상태 | 결과 0건·분석 없음 | 기존 빈 안내·활성 조건·미확인 `—` | 초기화·선택 변경·기존 분석 진입 |
| 오류/부분 실패 | 조회·분석·비교 열 실패 | 접기 밖 실패/부분 결과 안내, 기존 복구 행동 | 기존 새로고침·열별 재시도 |
| 비활성/권한 없음 | 진행 중·비교 4건·관리 권한 없음 | 기존 사유, 관리자 링크는 권한에 따라 생략 | 허용된 업무·선택 해제; 기존 서버 가드 유지 |
| 긴 값/대량 | 긴 제목·조건 다수·기존 페이지 초과 | 제목 줄바꿈·조건 전체 요약·기존 페이지/더 보기 | 펼침·검색·기존 추가 로드 |

- 1440px·1280px 모두 기존 AppShell/AppPage 사용. 1280px에서는 컨테이너 폭에 따라 필터 줄을 감싸고 검색은 `min-w-60 flex-1`, 기관·권고·정렬은 기존 적정 폭을 유지한다. 화면 전체 가로 넘침 금지. 비교표는 기존 표 스크롤 영역을 사용한다.
- 운영 패널 내부는 컨테이너 폭에 따라 2열/1열, 업무 목록은 항상 먼저 읽힌다. 사이드바 펼침/접힘 양쪽에서 확인한다. 1280px 미만 설계는 추가하지 않는다.
- h1 하나, 기존 h2/h3와 표 caption/scope 유지. summary는 명확한 이름·최소 32px 클릭 높이·키보드 Enter/Space·focus-visible 링. summary 안에 링크/버튼을 중첩하지 않는다. 접힌 내용은 Tab 순서에서 제외한다. 전환 애니메이션은 추가하지 않는다.
- 기술정보 내부를 가리키는 기존 링크가 있으면 해당 details를 펼친 뒤 초점을 이동시킨다. 비교 제목으로의 기존 포커스 이동을 끊지 않는다.

## 토큰·부품

새 토큰·공용 부품 없음. 기존 `Button` outline/ghost, `Field`·`Input`·`Select`·`DropdownMenu`·`Switch`·`Table`, `DemoBadge`·`StatusBadge`·출처 배지를 재사용한다. 접기는 화면 내 네이티브 요소로 구현한다.

`bg-background/card`, `text-foreground/muted-foreground`, `border-border`, 선택은 `selected/selected-foreground`, 포커스는 `ring`, 경고는 기존 `warning/destructive` 의미색과 텍스트를 병기한다. Pretendard/기존 글꼴, `type-title/heading/body/label/caption`을 유지하고 대시보드의 기존 type scale을 유지한다. 구역은 가는 선·`rounded-lg`·그림자 없음, 내부 `p-4`·`gap-3/4`, 주요 구역 `gap-8/10`. 주요 default 버튼은 기존 업무 행동 하나만 유지한다.

구현 전 관련 Next.js 규약은 `web/node_modules/next/dist/docs/`에서 읽는다. 각 구현 단계는 `pnpm verify:changed`, 통합·제출 전은 `pnpm verify`를 실행한다(ADR-046). 표시 문서만 작성한 이번 작업에는 앱 테스트를 실행하지 않는다. 새 전수 행렬·상수 복사 시험은 만들지 않는다.

### 수용 체크

- [ ] 네 영역의 기술/운영/고급 접기가 최초 진입 시 닫히며, 펼치면 이전 값과 행동을 모두 확인한다. 접기만으로 네트워크 요청·데이터 변경 없음.
- [ ] 대시보드 네 운영 패널이 단일 details 안에 있고, 일반 사용자에게 수집 관리 링크가 보이지 않는다. `/market`·허용된 `/admin/ingestion` 이동이 동작한다.
- [ ] 두 목록의 기본 필터는 검색·기관·권고·정렬이며 출처·기관 제어가 각각 한 개다. 고급 조건이 적용된 직접 URL도 닫힘+전체 활성 요약을 보인다.
- [ ] 필터 변경/초기화/뒤로·앞으로·추가 로드와 관심 목록 한정 조건이 유지된다. 기본 진행 중·AI/SI 우선·현재 데이터 구분이 명시된다.
- [ ] 모든 DEMO·Mock 응답/저장 공고 안내·부분 실패·검토 플래그·기준 불일치·가정/추정·스냅샷/현재 구분이 닫힌 상태에서도 보인다.
- [ ] 원시 실행 모드 live/fixture/mock와 실행 모드 필터는 닫힌 상세/비교 기준 안에만 있다. live 모드 표시는 기본 화면에 없고, mock/fixture에는 사용자용 안내가 보인다. 공고 헤더의 기존 수집 정보는 유지된다.
- [ ] 비교 2~4건의 선택·해제·열별 오류 복구, 상세 분석/사람 결정, 인력 팀/충돌 확인이 기존처럼 동작한다.
- [ ] 1280/1440px, 사이드바 양 상태에서 페이지 넘침·잘린 제어 없음. 키보드만으로 접기·필터·비교 조작 가능, 접힌 내부에 초점이 들어가지 않는다.

## 열린 질문

없음. 사용자 승인 방향과 이번 추가 지시로 구현에 필요한 선택을 확정했다. 시각 검증은 구현 후 수행한다.


## 구현 결과 (2026-10-30)

승인한 네 영역의 표시 정리와 관련 기존 로그인 E2E의 기대 화면 수정을 완료했다. 원문·회사 프로필 성격·모의 응답·부분 실패·가정·비교 불일치 고지는 유지했다. 추가로 입찰 상세의 추천 분석 생성 모델·점수 버전·결정 모델 식별자·오류 코드도 상세 접기로 정리했다.

`pnpm verify:changed`, 전체 `pnpm verify`(빌드 포함), 관련 Chromium 31시험이 통과했다. 1280·1440px의 대시보드/필터 본문과 네이티브 접기·키보드·URL·오류 복구를 확인했다. 독립 리뷰 1회 지적은 수정·해결 확인했다. 전체 AppShell 사이드바 조합과 로그인 후 실제 DB·Worker E2E, 운영 배포는 실행하지 않았다. [검증 기록](../../../docs/evidence/work-screen-declutter/20261030/README.md).


## 사용자 후속 수정 (2026-10-30)

사용자 지시 "자격 갭 레이더에 회사 프로필 r6 기준 ... 이런 거좀 다 지우고 입찰 공고에는 필터링 ... 다시 넣어"가 위 목록 필터 접기 명세보다 우선한다. `/bids`·`/watchlist`의 필터를 정리 전 구성으로 복원해 모두 상시 노출한다. `/gaps`는 프로필 revision·기준 시각을 표시하지 않으며 데이터 성격·범위·가정 안내만 유지한다. 서버 계산·조회 조건은 바꾸지 않는다.
