# 스펙: 기본 디자인 — 웹은 SaaS 제품형, 앱은 Toss 식

- 최종 갱신: 2026-10-15
- 상태: 마침(2026-10-15). 대시보드·메모 부분은 작업·활동 견본으로 대체됐다. 지금 기준은 아래 머리말이 가리키는 스펙이다.

> **메모 견본은 없어졌다(2026-10-14).** 메모 견본은 작업·활동 기록 견본으로 바뀌었다(`polaris/specs/done/tasks-and-activity.md`).
> 이 문서의 메모·대시보드 내용(`memos` 표, `@/server/memo`, `/memos` 화면, 메모 수로 그리는 대시보드)은 그때의 기록이다.
> 지금 대시보드·작업 화면과 그 데이터의 기준은 위 스펙과 `tasks-and-activity.design.md` 다. [사용자 결정]
>
> **계정 화면 주소도 바뀌었다(2026-10-15).** 이 문서의 `/account`·`/account/sign-up`·`/account/reset`·`/account/password` 는 지금 `/auth/login`·`/auth/sign-up`·`/auth/reset`·`/auth/password` 다.
> 옛 주소는 `web/next.config.ts` 가 새 주소로 넘긴다. [사용자 결정]

## 1. 목표

웹 견본이 "내용 없는 화면에 모바일 눈금을 확대한 것"으로 보인다. 웹을 SaaS 제품형(조밀한 눈금, 가는 선, 앱 틀)으로 다시 짓고
견본 화면(랜딩·로그인·대시보드·메모·설정)을 채운다. 앱(Expo)은 Toss 식을 유지한다. [사용자 결정]

에이전트는 견본 화면을 베껴 새 화면을 만든다. 그래서 견본 화면과 규칙(`design-system` 스킬)을 같이 고친다. [제안 후 승인]

참고로 본 것: mobbin 의 공개 탐색(사이트 트렌딩, 웹 앱 대시보드·사이드 내비게이션 화면), midday.ai·linear.app·plain.com·mercury.com,
shadcn 대시보드 예제(사이드바 256px, 항목 32px·14px, 통계 숫자 24px·600, 표 행 53px, 배지 22px).

## 2. 비목표

- 다크 모드. [제안 후 승인]
- 문구 말투(합니다체) 변경. [제안 후 승인]
- 외부 디자인 스킬 설치. [사용자 결정]
- 앱 화면 재설계. 앱은 지금 모양을 유지하고, 토큰이 바뀌어 달라지는 곳만 맞춘다. [사용자 결정]
- 새 DB 표·마이그레이션. 대시보드는 있는 `memos` 로 만든다. [작성자 판단]
- 차트 라이브러리. 막대 차트는 CSS 로 그린다. [작성자 판단]
- 지어낸 고객 로고·후기·수치. 랜딩의 견본 화면은 "견본 데이터"라고 밝힌다. [작성자 판단]
- OAuth, 결제, 검색, 알림 같은 새 기능. 동작하지 않는 메뉴·버튼을 두지 않는다. [작성자 판단]

## 3. 완료의 정의

1. `design/tokens.json` 이 4.1·4.2 의 값이고, 생성기가 웹 눈금(`typography`)과 앱 눈금(`nativeTypography`)을 따로 만든다.
   검증: `pnpm check:tokens`, 루트 `pnpm test`(생성기 시험·대비 시험).
2. 웹 공용 부품이 4.3 의 크기이고 새 부품(sidebar·avatar·table)이 저장소 규칙(색 검사·`cn`)을 지킨다.
   검증: `pnpm -C web verify`, 브라우저에서 높이를 잰다.
3. 4.4 의 경로가 모두 열리고 로그인 전·후 틀이 표와 같다. 검증: 브라우저(375·1280px), 로그인 뒤는 로컬 Supabase.
4. 대시보드가 메모 데이터로 통계·막대 차트·최근 표를 그리고, 메모가 없으면 빈 상태를 보인다.
   검증: 도메인 단위 시험(`pnpm -C web test`), 브라우저에서 메모 0개·여러 개.
5. 랜딩에 로고가 있는 머리말, 견본 화면이 있는 히어로, 기능 칸, 시작 3단계, 바닥글이 있고 `/` 는 정적 렌더링을 유지한다.
   검증: `pnpm -C web build` 출력의 `○ /`, 브라우저.
6. 모든 공개·보호 경로가 320·375·768·1280px 에서 가로로 넘치지 않는다. 검증: `web/e2e/responsive.spec.ts`.
7. 앱은 지금 모양을 유지한다(채움 버튼은 파랑). 검증: `pnpm -C mobile verify`. 화면 모양은 시뮬레이터가 있어야 볼 수 있다.
8. `design-system` 스킬의 방향 절과 문서의 견본 경로·수치가 구현과 맞다. 검증: 루트 `pnpm test`(문서 경로 시험), 직접 읽기.
9. `pnpm verify` 와 `pnpm -C web test:e2e` 가 통과한다. 화면 구조가 바뀐 만큼 E2E 는 구현과 다른 에이전트가 고친다.

### 4.2 글자 눈금 [작성자 판단]

웹과 앱의 눈금을 나눈다(`fonts`·`nativeFonts` 와 같은 방식). 항목은 `size`·`lineHeight`(px), 선택으로 `weight`·`tracking` 을 갖는다.
`tracking` 이 없으면 전역 `tracking` 을 쓴다. 웹은 전역 `0em` 하나로 통일하고 항목마다 따로 좁히지 않는다.
`html` 에 `antialiased` 를 두지 않는다(macOS 에서 글자가 가늘게 그려진다). [사용자 결정 — 2026-10-14, 참고 화면의 글꼴·굵기에 맞춤]

웹 `typography`:

| 이름 | 크기/줄 높이 | 굵기 | 자간 | 쓰임 |
|---|---|---|---|---|
| `display` | 56/62 | 700 | | 랜딩 큰 제목(넓은 폭) |
| `headline` | 36/44 | 700 | | 랜딩 제목(좁은 폭), 랜딩 구역 제목 |
| `title` | 30/36 | 700 | | 화면 제목(`h1`) [사용자 결정 — 2026-10-14] |
| `heading` | 16/24 | 600 | | 카드·구역 제목 |
| `lead` | 18/28 | | | 랜딩 설명 |

### 4.3 웹 부품 [작성자 판단]

- `button`: xs 28px, sm 32px, 기본 36px, lg 44px. 글자 12·13·14·15px, 굵기 500, 모서리 `rounded-lg`(8px).
- `input`·`textarea`: 40px(textarea 최소 80px), 좌우 12px, 글자는 좁은 폭 16px·`md` 부터 14px(iOS 확대 방지), `border-input`.
- `card`: `rounded-xl` + `border` + `shadow-xs`, 안쪽 여백 24px(작은 것 16px). 구역은 가는 선으로 나눈다.
- `label` 13px·500. `dialog` 는 `rounded-xl`, `dropdown-menu` 는 `rounded-lg`·항목 32px.
- 새 부품(shadcn `base-nova`): `sidebar`(딸려 오는 `sheet`·`tooltip` 포함), `avatar`, `table`. `badge`·`breadcrumb` 은 쓰는 화면이 없어 넣지 않는다. [사용자 결정]
- 아이콘은 `lucide-react`, 기본 16px. 로고는 `web/components/logo.tsx`(마크 + `project.json` 의 `title`) 하나를 머리말·바닥글·사이드바가 같이 쓴다.

| 경로 | 로그인 전 | 로그인 뒤 | 틀 |

| `/account` | 로그인 폼 | `/dashboard` 로 보낸다 | 인증 틀 |
| `/account/sign-up`·`/account/reset`·`/account/password` | 지금 동작 그대로 | 그대로 | 인증 틀 |

| `/memos` | "로그인이 필요합니다" 안내. 제목·링크는 그대로이고 설명은 앱 틀의 공통 문구다 [구현에 맞춤] | 메모 | 앱 틀 |

- 마케팅 틀: 머리말(로고, 구역 링크, `로그인`·`시작하기`)과 바닥글. 머리말 파일은 `web/components/site-header.tsx` 그대로 쓴다.
  바닥글은 위에 링크 묶음(왼쪽부터 칸), 가는 선 아래에 로고와 설명을 두고, 바탕을 뒤집어(`bg-foreground`·`text-background`) 본문과 구분한다. [사용자 결정 — 2026-10-14]
  머리말은 흰색이고 본문 바탕은 그보다 아주 조금 어둡다(`bg-muted/50`). 구역 사이에는 선을 긋지 않고 여백으로 나눈다. [사용자 결정 — 2026-10-14]
- 인증 틀: 화면 가운데(가로·세로)의 좁은 단(`max-w-100`, 400px). 로고와 카드 없이 가운데 정렬한 제목 아래에 폼·버튼을 둔다.
  비밀번호 칸에는 보기·숨기기 버튼이 있다. [사용자 결정 — 2026-10-14, 참고 화면에 맞춤]
- 앱 틀: 경로 묶음 `web/app/(app)/` 의 `layout.tsx`. 사이드바(로고, 대시보드·메모·설정, 아래에 사용자 메뉴)와 위 막대(사이드바 여닫기, 지금 화면 이름).
  로그인 전이면 틀 대신 인증 틀의 안내를 그린다. DB 가 없으면 지금의 "DB 가 연결되지 않았습니다" 안내를 그린다.
- `web/app/memos/` 는 `web/app/(app)/memos/` 로 옮긴다. 주소는 그대로 `/memos` 다.
- 건너뛰기 링크는 루트 `layout.tsx` 에 두고, `#main-content` 는 틀마다 `main` 이 갖는다. 머리말·사이드바 뒤로 건너뛰어야 해서다. [구현에 맞춤]
- 프로필 행이 없는 계정(`missing`)과 DB 없음은 `/account` 에서 지금처럼 안내한다(보내지 않는다).

### 4.5 화면 [작성자 판단]

- **랜딩**: 제목은 `type-headline md:type-display`, 설명 `type-lead`, 버튼 둘(`시작하기` → `/account/sign-up`, 보조 → `/account`).
  히어로 아래에 견본 화면: 브라우저 틀 안에 대시보드 부품(통계 카드·막대 차트)을 견본 데이터로 그린 것. 조작 대상이 아니다(`aria-hidden`·`inert`).
  기능 칸은 이 저장소에 실제로 있는 것만 적는다(검증 게이트, RLS, 토큰 정본, 웹·앱 한 저장소, 스킬·에이전트, CI). 시작 3단계(`/setup`·`/verify`·`/predeploy-review`)를 남긴다.
- **대시보드**: 화면 제목, 통계 카드(최근 7일 추가·오늘 추가·마지막 작성), "최근 14일" 막대 차트, 최근 메모 표(5줄, `/memos` 로 가는 링크), 빈 상태.
  데이터는 도메인 `@/server/memo` 가 준다. 목록은 최신 50개까지만 읽으므로 그 한계를 화면에 밝힌다.
- **메모**: 추가 폼 카드와 목록 카드. 줄은 가는 선으로 나누고 삭제는 줄마다 둔다. 있는 id·접근성 이름·동작은 그대로다.
- **설정**: 구역(프로필 / 비밀번호 / 세션)을 가는 선으로 나눈 폼. 넓은 폭에서는 왼쪽에 구역 이름, 오른쪽에 내용.
- 화면 제목은 `type-title`, 한 화면에 `h1` 하나, 주요 버튼(`default`)은 화면에 하나.
  랜딩만 `시작하기` 가 머리말(4.4)과 히어로에 하나씩 있고 둘 다 `/account/sign-up` 으로 간다 [구현에 맞춤]

### 4.6 대시보드 데이터 [작성자 판단]

`@/server/memo` 에 요약을 더한다. 화면은 조립만 한다.

- 순수 함수: 메모 목록과 기준 시각을 받아 `최근 7일 수`·`그 앞 7일 수`·`오늘 수`·`날짜별 수 14칸`·`마지막 작성 글자`·`50개 한계에 닿았는지`를 돌려준다.
  날짜 경계는 `Asia/Seoul` 이다(`formatCreatedAt` 과 같다).
- 서비스: `getMyMemos` 와 같은 상태 합집합(`no-database`·`signed-out`·`ready`)으로 요약과 최근 5개를 돌려준다. 저장소 호출은 늘리지 않는다.

### 4.7 앱 [사용자 결정: 유지]

- 채움 버튼·커서·선택 색처럼 브랜드 색으로 쓰던 `colors.primary` 를 `colors.brand`(글자는 `colors.brandForeground`)로 바꾼다. 모양은 지금과 같다.
- 글자 눈금은 `nativeTypography` 에서 온다. 값이 같으므로 화면은 달라지지 않는다.

## 5. 엣지 케이스와 실패 시나리오

- 320px: 가로로 넘치지 않는다. 머리말은 한 줄이고 좁으면 구역 링크를 숨긴다. 랜딩의 견본 화면은 줄어들거나 일부를 숨긴다.
- 좁은 폭의 앱 틀: 사이드바는 서랍(sheet)으로 열린다.
- 메모 0개: 대시보드와 메모 화면 모두 빈 상태를 보인다. 차트는 빈 눈금을 보인다.
- 메모가 50개에 닿았을 때: 통계가 "최근 50개 기준"임을 밝힌다.
- 긴 프로젝트 이름·긴 이메일: 말줄임한다.
- 글꼴을 못 받았을 때: 시스템 한글 글꼴로 보이고 레이아웃이 깨지지 않는다.
- 로그인 뒤 `/account` 로 오는 길(로그인 직후, 메일 확인 링크): `/dashboard` 로 간다. 로그아웃하면 `/account` 로 간다.
- 대비가 4.5:1 에 못 미치는 조합이 생기면 값을 조정하고 이 문서의 표를 같이 고친다.

## 미결정 사항

- 주요 버튼 색(남색)은 사용자가 따로 고르지 않았다. 추천안으로 진행했고, 파랑으로 되돌리려면 `primary` 를 `brand` 값으로 바꾸면 된다.
- "작성자 판단"으로 표시한 값(색, 글자 눈금, 부품 크기, 경로 구조)은 사용자가 확인하지 않았다.
- 앱 화면 모양은 시뮬레이터에서 확인하지 못할 수 있다.
- 랜딩 머리말의 `시작하기` 를 `outline` 으로 낮출지는 정하지 않았다("주요 버튼은 화면에 하나"와 글자 그대로는 어긋난다).
