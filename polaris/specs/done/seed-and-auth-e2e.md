# 스펙: 시드 사용자와 로그인 뒤 E2E

- 최종 갱신: 2026-10-14

## 1. 목표

로그인 뒤 화면(대시보드·작업·멤버·초대)을 에이전트가 사람 손 없이 검증하게 한다. 지금은 QA·고침 에이전트가 계정을
Mailpit 으로 손수 가입시키고, 로그인 뒤 흐름을 지키는 자동 시험이 없다. 로컬 Supabase 에 정해진 계정과 데이터를 만드는
시드 명령과, 그 위에서 도는 로그인 E2E 를 더한다. [사용자 결정]

## 2. 비목표

- `supabase/seed.sql`(`db reset` 때만 돈다). 시드는 스크립트로 한다. [사용자 결정]
- CI·push 전 검사·`pnpm verify` 에서 로그인 E2E 돌리기. 둘은 가짜 Supabase 자리값으로 돌고, CI 설정(`.github/`)은 편집 금지다. [사용자 결정]
- 운영(클라우드) DB 에 시드 넣기. 시드는 로컬 Supabase 에만 넣는다. [제안 후 승인]
- 앱(mobile) E2E. [제안 후 승인]

## 3. 완료의 정의

1. **시드** — `pnpm db:seed` 가 로컬 Supabase 에 4.1 의 계정과 데이터를 만든다. 두 번 연달아 돌려도 같은 상태가 된다.
   로컬이 아닌 주소면 아무것도 하지 않고 실패한다. 순수 부분(주소 검사·시드 계획)의 시험이 루트 `pnpm test` 에서 통과한다. [제안 후 승인]
2. **로그인 E2E** — `pnpm -C web test:e2e:auth` 가 시드를 넣고 4.3 의 시나리오를 돌려 통과한다. 연달아 두 번 돌려도 통과한다.
   로컬 Supabase 가 꺼져 있으면 `pnpm db:start` 를 안내하며 실패한다(건너뛰지 않는다). [사용자 결정]
3. **기존 검증** — `pnpm verify` 와 `pnpm -C web test:e2e` 가 그대로 통과한다. [제안 후 승인]
4. **에이전트 연결** — qa-web·e2e-web 에이전트, testing 스킬, `AGENTS.md`·docs 에 시드 계정과 두 명령을 쓰는 법을 적는다. [사용자 결정]

## 4. 인터페이스 계약

### 4.1 시드 계정과 데이터 [제안 후 승인]

- 계정 넷(같은 로컬 전용 비밀번호, 이메일 확인된 상태): 소유자 · 멤버 · 조직 밖 사람 · 초대받은 사람. 이메일은 `@example.test`.
- 팀 하나(소유자가 owner, 멤버가 member). 초대받은 사람에게는 수락 전 초대가 하나 있다. 조직 밖 사람은 그 팀과 관계가 없다.
- 팀의 작업: 상태 셋·담당자(소유자·멤버·없음)·마감일(지남·오늘·나중·없음)이 섞이고, 최근 14일에 걸쳐 만든 날과 완료한 날이 흩어진다.
  대시보드 수치는 실행한 날짜와 상관없이 같다(기한 지남·이번 주 완료·내 담당 수가 고정).
- 데이터는 그 사람으로 로그인해 넣는다(RLS 를 거치고 활동 기록에 행위자가 남는다). 날짜를 과거로 옮기는 것만 관리 키로 한다.
- 다시 돌리면 시드 계정과 시드 계정만 멤버인 조직을 지우고 처음부터 다시 만든다. 다른 로컬 데이터는 건드리지 않는다.

### 4.2 명령 [사용자 결정]

- 루트 `pnpm db:seed` — 시드만 넣는다. 계정 목록과 비밀번호를 출력한다.
- `pnpm -C web test:e2e:auth` — 시드를 넣고 로그인 E2E 를 돈다. 빌드(`pnpm -C web build`)가 먼저 있어야 한다(기존 `test:e2e` 와 같다).

### 4.3 시나리오 [사용자 결정]

- 대시보드 수치·차트·기한 표·활동 피드가 시드와 맞는다.
- 작업 추가·편집·상태 변경·삭제, URL 거르기·정렬·쪽.
- 권한 차이: 멤버에게는 남의 작업 삭제 항목이 없고, 멤버 화면에서 관리 메뉴가 없다.
- 격리: 조직 밖 사람에게 팀 주소는 404 다.
- 초대받은 사람이 초대를 수락해 팀에 들어온다. 조직 전환기로 개인 공간과 팀을 오간다.

## 5. 엣지 케이스와 실패 시나리오

- 로컬 Supabase 가 꺼짐·CLI 없음 → 이유와 `pnpm db:start` 를 안내하고 0 이 아닌 코드로 끝난다. [제안 후 승인]
- 시험이 데이터를 바꾼다 → 시험은 다시 돌려도 통과하도록 스스로 만든 것만 바꾸거나, 실행마다 시드를 다시 넣는다. [제안 후 승인]
- 시드 계정이 테스트 중 만든 다른 조직 → 시드 계정만 멤버인 조직은 다시 돌릴 때 지운다. [제안 후 승인]
