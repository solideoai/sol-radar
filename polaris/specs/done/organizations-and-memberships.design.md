### 1.2 화면 폭과 단 폭 (계산 근거)

사이드바는 768px 이상에서 붙박이(256px), 미만에서 서랍(`min(18rem, 85vw)`)이다(`web/lib/use-mobile.ts`). 본문 좌우 여백은 `px-4`·`sm:px-6`·`lg:px-8`.

| 화면 폭 | 사이드바 | 본문 단 폭 | 기본 카드 안쪽 폭(여백 24px×2 뺌) |
|---|---|---|---|
| 375 | 서랍(288px) | 343px | 295px |
| 768 | 붙박이 256px | 464px | 416px |
| 1280 | 붙박이 256px | 960px | 912px |

칸 나눔은 견본처럼 화면 폭이 아니라 단 폭(`@container` + `@lg:`(512)·`@2xl:`(672)·`@3xl:`(768))으로 정한다. 사이드바를 접으면 같은 화면 폭에서도 단이 넓어진다.

### 1.3 한계

로컬 DB·개발 서버가 꺼져 있어 로그인 뒤 화면을 브라우저로 보지 못했다. 기존 화면의 구조와 수치는 위 코드에서 읽었다. 구현 뒤 QA 가 375·768·1280px 에서 직접 확인한다.

## 2. 흐름

### F1. 팀 만들기 → 초대

1. 사이드바의 조직 전환기 → "새 팀 만들기" → `/teams/new`.
2. 팀 이름·주소 이름 입력 → "팀 만들기".
   - 성공: `/<slug>/settings/members` 로 간다. 토스트 "팀을 만들었습니다. 이제 멤버를 초대하세요." 전환기의 지금 조직이 새 팀이 된다.
   - 실패: 형식·예약어·중복이면 폼에 오류. 입력값은 남는다.
   - 취소: "취소" 링크 → `/dashboard`(스펙 4.3 에 따라 개인 조직 대시보드로 간다).
3. 멤버 화면의 초대 폼에 이메일·역할 → "초대".
   - 성공: 대기 중인 초대 목록에 생긴다. 메일은 보내지 않으므로 토스트로 "직접 알려 주세요"를 안내한다.
   - 이미 멤버·내 이메일: 폼 오류. 이미 초대한 이메일: 기한을 7일로 늘리고 성공으로 알린다.

### F2. 초대 수락

1. 초대받은 사람이 초대받은 이메일로 가입·로그인한다 → `/dashboard`(개인 조직).
2. 사이드바 머리의 "받은 초대 1" 줄(또는 전환기 메뉴의 같은 항목) → `/invitations`.
3. "수락" → `/<slug>/dashboard` 로 간다. 토스트 "<팀 이름>에 들어왔습니다."
   - 만료: 줄에 "만료됨", 수락 버튼 비활성, 다시 초대해 달라는 안내.
   - 다른 이메일로 로그인: 그 초대는 목록에 없다. 빈 상태 문구가 지금 로그인한 이메일을 보여 줘서 알아챌 수 있게 한다.
   - 거절: 줄이 사라진다. 토스트 "<팀 이름> 초대를 거절했습니다."

### F3. 조직 전환

전환기 열기 → 조직 고르기 → 그 조직의 `/<slug>/dashboard`. 서랍에서는 메뉴와 서랍이 같이 닫힌다.
고른 조직의 같은 화면(메모 → 메모)으로 가지 않고 늘 대시보드로 간다 — 규칙이 하나라 예측하기 쉽고, 개인·팀 사이에 없는 화면이 생겨도 깨지지 않는다.

### F4. 멤버 관리 (팀, owner)

- 역할 변경: 줄의 "…" 메뉴 → 역할 고르기 → 바로 바뀐다(토스트). 자기 자신을 멤버로 내릴 때만 확인 대화상자.
- 내보내기: "…" 메뉴 → "내보내기" → 확인 대화상자 → 줄이 사라진다.
- 마지막 owner: 나가기·자기 강등을 화면이 미리 막고(비활성 + 이유 글자), 동시에 일어난 경우는 DB 가 거절한 것을 오류로 보여 준다.

### F5. 팀 나가기 (팀, 누구나)

멤버 화면 맨 아래 "팀 나가기" → 확인 대화상자 → 개인 조직 대시보드로 간다. 토스트 "<팀 이름>에서 나갔습니다."

### F6. 팀 메모

`/<slug>/memos` 에서 쓰면 그 조직의 멤버 모두에게 보인다. 삭제 버튼은 작성자와 owner 에게만 보인다.

### F7. 권한 밖 주소

- 멤버가 아닌 조직·없는 slug: 404 화면(`web/app/not-found.tsx`). 두 경우를 구분하지 않는다 — 조직이 있는지 알려 주지 않는다. 내보내진 사람이 옛 주소를 열어도 같다.
- 옛 주소 `/dashboard`·`/memos`·`/settings`: 개인 조직의 같은 화면으로 보낸다(스펙 4.3).
- 로그인 전: 앱 틀 경로는 지금처럼 앱 틀이 "로그인이 필요합니다"를 그린다. `/teams/new`·`/invitations` 는 화면이 같은 안내를 그린다(4.4·4.5).

## 3. 화면별 명세

### 3.1 조직 전환기 (앱 틀, `web/components/app-shell.tsx`)

#### 목적
지금 어느 조직에서 일하는지 늘 보이고, 한 번에 다른 조직·새 팀·받은 초대로 간다.

#### 레이아웃

로고 자리(`SidebarHeader`)를 전환기가 차지한다(스펙 4.3). 제품 로고는 앱 틀에서 빠진다(열린 질문 Q10).

```
SidebarHeader (p-2, gap-2)
├─ 전환기 단추  SidebarMenuButton size="lg" (48px) ─ DropdownMenuTrigger
│   [조직 표시 32px] [이름 ─ 말줄임      ] [⇕]
│                    [개인 | 팀 · 소유자  ]
└─ (받은 초대가 있을 때만) SidebarMenuButton 기본(32px) → /invitations
    [✉] 받은 초대                          [2]   ← SidebarMenuBadge
```

- **조직 표시**(화면 안 보조 요소 `OrgMark`, 이 파일 안에서만 쓴다): `flex size-8 shrink-0 items-center justify-center rounded-lg bg-sidebar-primary text-sidebar-primary-foreground type-label font-semibold`. 조직 이름의 첫 글자(기존 `initialOf` 재사용). 사람(동그란 `Avatar`)과 구분되게 모서리를 둥근 사각형으로 둔다. `aria-hidden`.
- **이름 줄**: `truncate font-medium text-sidebar-accent-foreground`. **둘째 줄**: `truncate type-caption text-muted-foreground`, 글자는 개인이면 "개인", 팀이면 "팀 · 소유자" / "팀 · 멤버". 내 역할을 여기서 보여 줘서 멤버 화면에서 버튼이 안 보이는 이유를 미리 알 수 있게 한다.
- 단추 안 끝에 `ChevronsUpDownIcon`(`text-muted-foreground`). 구성은 아래 사용자 메뉴 단추와 같다.
- **받은 초대 줄**: 전환기 아래, 같은 `SidebarHeader` 안. `MailIcon` + "받은 초대" + `SidebarMenuBadge`(숫자, `tabular-nums`). 개수가 0이면 줄을 그리지 않는다(동작하지 않는 항목을 두지 않는다). 만료되지 않은 초대만 센다.

#### 메뉴 (`DropdownMenuContent side="bottom" align="start"`)

```
개인                       ← DropdownMenuLabel
  [표] 홍길동           ✓  ← DropdownMenuLinkItem → /<slug>/dashboard
팀                         ← 팀이 없으면 이 묶음째 없다
  [표] 디자인팀
  [표] 마케팅
────────────               ← DropdownMenuSeparator
  ✉ 받은 초대           2  ← 개수가 0이면 없다
  + 새 팀 만들기           ← /teams/new
```

- 조직 항목은 `DropdownMenuLinkItem`(링크라서 Enter·새 탭 열기가 된다). 앞에 작은 조직 표시(`size-5 rounded-md type-caption`), 이름은 `min-w-0 flex-1 truncate`, 지금 조직은 끝에 `CheckIcon`(`aria-hidden`) + 항목에 `aria-current="true"`.
- 순서: 개인 조직이 먼저, 팀은 이름 가나다순.
- 받은 초대 개수: `ml-auto type-caption tabular-nums text-muted-foreground`, 읽는 글자는 "2개"(`<span class="sr-only">개</span>`).
- 모든 링크 항목은 누르면 메뉴와 서랍을 같이 닫는다(`onClick={closeDrawer}`, 기존 메뉴와 같다).

#### 위 막대 (같은 파일의 `AppTopBar`)

서랍 폭(768px 미만)과 사이드바를 접은 넓은 폭에서는 사이드바가 안 보여 지금 조직을 알 수 없다. 이때 위 막대가 `조직 이름 / 화면 이름` 으로 보여 준다 — 팀에 메모를 잘못 쓰는 일을 막는다.

- 조직 이름: `min-w-0 truncate type-label text-muted-foreground`, 뒤에 `/`(`aria-hidden`, `text-muted-foreground`), 화면 이름은 지금처럼 `shrink-0 type-label font-medium text-foreground`.
- 보이는 조건: 사이드바가 펼쳐져 있으면 `md:hidden`(좁은 폭만), 접혀 있으면(`useSidebar().state === "collapsed"`) 늘. 두 값 모두 서버에서 알 수 있어(쿠키) 첫 렌더에 깜박이지 않는다.

#### 데이터 (앱 틀이 서버에서 읽어 넘긴다)

`currentOrg { slug, name, isPersonal, myRole }`, `orgs[] { slug, name, isPersonal }`, `pendingInvitationCount`(만료 전만). 사용자 메뉴의 "설정" 링크와 `NAV` 의 주소는 `/<slug>/…` 가 된다.

#### 상태표

| 상태 | 언제 | 보이는 것 | 사용자가 할 수 있는 것 |
|---|---|---|---|
| 개인 조직 | 개인 조직 화면 | 머리글자, 조직 이름, "개인" | 메뉴 열기 |
| 팀 조직 | 팀 화면 | 머리글자, 팀 이름, "팀 · 소유자" 또는 "팀 · 멤버" | 메뉴 열기 |

#### 접근성

- 단추 이름: `<span class="sr-only">조직 전환</span>` 을 앞에 둔다(사용자 메뉴의 "사용자 메뉴"와 같은 방식). 읽히는 이름은 "조직 전환 디자인팀 팀 · 소유자".
- Tab 순서: 건너뛰기 링크 → 전환기 → 받은 초대 줄 → 주요 메뉴 → 사용자 메뉴 → 위 막대 → 본문.
- 초점 표시: 사이드바 항목과 같은 `ring-sidebar-ring outline-hidden focus-visible:ring-2`(부품 기본).
- 메뉴를 닫으면 초점이 단추로 돌아온다(부품 기본). 다른 조직으로 이동하면 새 화면의 처음부터 시작한다.

### 3.2 `/[slug]/settings` — 계정 설정 + 하위 메뉴

#### 목적
지금의 설정 화면(프로필·비밀번호·세션)을 그대로 옮기고, 멤버 화면으로 가는 길을 둔다.

#### 멤버 화면으로 가는 길: 설정 안 하위 메뉴 `SettingsNav`

- 설정 두 화면(계정·멤버)의 제목 아래에 같은 링크 줄을 둔다. 사이드바 `NAV` 에는 더하지 않는다(설정의 한 부분이다).
- 경로 이동이라 ARIA 탭(`role="tablist"`)이 아니라 **링크 + `aria-current="page"`** 다. 그래서 Tabs 부품을 쓰지 않는다(5.2).
- 파일: `web/app/(app)/[slug]/settings/settings-nav.tsx`(설정 두 화면이 쓰는 화면 전용 부품).

```
설정                                   ← h1 (AppPage, 두 화면 같음)
프로필과 로그인 정보를 관리합니다.         ← 설명 (화면마다 다름)
 계정    멤버                           ← nav aria-label="설정 메뉴"
━━━━─────────────────────────────────   ← border-b, 지금 화면 아래에 2px 막대
```

| 요소 | 클래스 |
|---|---|
| `nav` | `border-b border-border` |
| `ul` | `-mb-px flex gap-6` (막대가 아래 선 위에 겹친다) |
| 링크 | `relative inline-flex h-10 items-center rounded-md type-label font-medium text-muted-foreground outline-none hover:text-foreground focus-visible:ring-3 focus-visible:ring-ring/50 aria-[current=page]:text-foreground` |
| 지금 화면 막대 | 링크의 `after:absolute after:inset-x-0 after:bottom-0 after:h-0.5 after:rounded-full aria-[current=page]:after:bg-foreground` |

- 막대 색은 `foreground` 다. 사이드바의 선택 표시도 회색 단계라서 맞춘다(`brand` 를 쓰지 않는다).
- 링크 글자: "계정" → `/<slug>/settings`, "멤버" → `/<slug>/settings/members`. 둘뿐이라 320px 에서도 넘치지 않는다. 늘어나 넘치게 되면 그때 가로 스크롤을 더한다.

#### 레이아웃 (계정 화면)

- `AppPage title="설정" description="프로필과 로그인 정보를 관리합니다."` — 지금과 같다.
- 본문 첫 자식은 `SettingsNav` 와 그 아래 내용을 **한 묶음**으로 넣는다(`AppPage` 의 `gap-6` 이 끼지 않게). 지금 구역 묶음의 `border-t` 는 지운다 — 하위 메뉴의 아래 선이 그 자리를 맡는다. 결과: 제목 → 24px → 하위 메뉴(선) → 32px(`py-8`) → 첫 구역.
- 구역(프로필·비밀번호·세션)과 `SettingsSection` 은 그대로. `SettingsSection` 을 멤버 화면이 쓰지 않으므로 지금 파일에 둔다.
- 문서 제목(`metadata.title`): "설정".

### 3.3 `/[slug]/settings/members` — 멤버·초대

#### 목적
팀: 누가 멤버인지 보고, owner 는 초대·역할 변경·내보내기를 하고, 누구나 팀에서 나간다. 개인: 팀을 만들라고 안내한다.

#### 공통 머리

- `AppPage title="설정"`, 설명은 아래 표. 본문 첫 자식은 `SettingsNav`("멤버" 선택) + 그 아래 카드 묶음(`flex flex-col gap-6 pt-6`)을 한 묶음으로.
- 문서 제목: "멤버".

| 보는 사람 | 설명(초안) |
|---|---|
| 팀 owner | "<팀 이름>의 멤버를 초대하고 역할을 관리합니다." |
| 팀 member | "<팀 이름>의 멤버입니다. 초대와 역할 변경은 소유자만 합니다." |
| 개인 조직 | "멤버 초대는 팀에서 합니다." |

역할 표기(초안): `owner` → "소유자", `member` → "멤버". 화면 어디서나 같은 글자를 쓴다.

#### 3.3.1 팀 · owner 가 보는 모양

```

  이메일 [______________]  역할 [멤버 ▾]  [초대]      ← @lg 이상 한 줄, 그 아래는 세로
  메일은 보내지 않습니다. 초대받은 사람에게 이 이메일로 가입한 뒤 ‘받은 초대’에서 수락하라고 알려 주세요.
[카드] 멤버                                    3명
  멤버                          역할       (관리)
  (홍) 홍길동 (나)              소유자      [⋯]
       hong@example.com
  (김) 김철수                   멤버        [⋯]

  나가면 이 팀의 메모를 볼 수 없습니다. …        [팀 나가기]
```

**초대하기 카드** (`Card` > `CardHeader`(제목 `h2` "초대하기") > `CardContent className="@container"`)

| 칸 | 부품 | 규칙 |
|---|---|---|
| 이메일 | `Field` + `FieldLabel htmlFor="invite-email"` + `Input type="email" autoComplete="off"` | 필수, 이메일 형식. 자동 완성을 끈다(`email` 이면 내 이메일이 채워진다) |
| 역할 | `Field` + `FieldLabel` + **Select**(제안 5.1) | 선택지 "멤버"(기본)·"소유자". 기본을 멤버로 두는 이유는 가장 작은 권한부터 주기 위해서다 |
| 초대 | `Button type="submit"` 기본(남색) | 이 화면의 유일한 주요 버튼. 제출 중 "초대 중…" |
| 안내 | `FieldDescription`(폼 아래) | 위 그림의 문장. 메일 발송이 비목표라서 늘 보인다 |

- 배치: `grid gap-4 @lg:grid-cols-[minmax(0,1fr)_10rem_auto] @lg:items-start`, 버튼은 `w-full @lg:mt-7 @lg:w-auto`(라벨 20px + 간격 8px 만큼 내려 입력칸과 줄을 맞춘다).
- 제출 중에는 입력칸을 `readOnly`(메모 폼과 같다 — 초점을 지킨다).
- 성공: 이메일 칸을 비우고 역할을 "멤버"로 되돌리고 초점을 이메일 칸으로. 대기 목록이 새로 그려진다.

**멤버 카드** (`Card` > `CardHeader`(제목 `h2` "멤버", 설명 "역할을 바꾸거나 팀에서 내보냅니다.", `CardAction` 에 "3명" `type-label text-muted-foreground tabular-nums`) > 표)

표는 대시보드 견본처럼 카드 끝까지 닿는다(`CardContent className="-mb-4 px-0"`, `Table className="table-fixed"`, 첫 칸 `pl-6`, 끝 칸 `pr-6`).

| 칸 | 머리 | 폭 | 내용 |
|---|---|---|---|
| 멤버 | "멤버" | 나머지 | `Avatar`(32px, `AvatarFallback` 머리글자) + 두 줄: 이름(`truncate font-medium text-foreground`, 내 줄이면 뒤에 `shrink-0 text-muted-foreground` " (나)") / 이메일(`truncate type-caption text-muted-foreground`, `title`=전체) |
| 역할 | "역할" | `w-20` | "소유자"·"멤버", `text-foreground` |
| 관리 | `<span class="sr-only">관리</span>` | `w-14` | `Button variant="ghost" size="icon-sm"` + `MoreHorizontalIcon`, `aria-label="<이름> 관리"` |

- 이름이 없으면 이메일의 @ 앞부분(앱 틀과 같은 규칙).
- 정렬: 소유자 먼저, 그다음 이름 가나다순.
- 페이지 나눔은 없다(견본 규모). 전부 보여 준다.

**줄의 관리 메뉴** (`DropdownMenu`, `align="end"`)

```
역할                 ← DropdownMenuLabel
 ● 소유자            ← DropdownMenuRadioGroup / RadioItem
 ○ 멤버
───────
 내보내기             ← DropdownMenuItem variant="destructive", 내 줄에는 없다
```

| 고른 것 | 동작 |
|---|---|
| 다른 사람의 역할 바꾸기 | 바로 저장. 그 줄의 관리 버튼을 저장이 끝날 때까지 비활성. 성공 토스트 "<이름> 님의 역할을 소유자로 바꿨습니다". 실패 `toast.error` |
| 내 역할을 멤버로 | 확인 대화상자 A |
| 내 역할을 멤버로 — 내가 마지막 소유자 | "멤버" 항목 비활성 + 묶음 아래 `DropdownMenuLabel` "마지막 소유자는 멤버로 바꿀 수 없습니다" |
| 내보내기 | 확인 대화상자 B |

**대기 중인 초대 카드** (owner 만. 멤버 카드와 같은 머리 구성, 제목 "대기 중인 초대", `CardAction` "2개")

| 칸 | 머리 | 폭 | 내용 |
|---|---|---|---|
| 이메일 | "이메일" | 나머지 | `truncate text-foreground` + `title`. 단이 좁으면(`@lg` 미만) 아래 줄에 `type-caption text-muted-foreground` "멤버 · 10. 21.까지" |
| 역할 | "역할" | `w-20`, `hidden @lg:table-cell` | "소유자"·"멤버" |
| 기한 | "기한" | `w-32`, `hidden @lg:table-cell` | `<time>` "2026. 10. 21.까지"(서울 시간), 만료면 "만료됨" `text-muted-foreground` |
| 관리 | sr-only "관리" | `w-14` | `ghost icon-sm` `MoreHorizontalIcon`, `aria-label="<이메일> 초대 관리"` |

- 단 폭 판정을 위해 이 카드에 `@container` 를 둔다.
- 정렬: 기한이 늦은 순(= 최근에 초대한 순). 만료된 것은 자연히 아래로 간다. `invitations` 에 만든 시각 열이 없어 기한으로 정렬한다.
- 관리 메뉴: "다시 초대"(`RotateCwIcon`) → 기한을 7일로 갱신, 토스트 "<이메일>의 초대 기한을 2026. 10. 28.까지 늘렸습니다". "초대 취소"(`destructive`) → 바로 지우고 토스트 "<이메일> 초대를 취소했습니다".
- 초대 취소에는 확인 대화상자를 두지 않는다. 잃는 것이 없고 다시 초대하면 된다(확인 대화상자는 3.3.4 의 기준).
- 비었을 때: 표 대신 `CardContent` 에 `type-label text-muted-foreground` "대기 중인 초대가 없습니다."

**팀 나가기 카드** (`Card` > `CardHeader`(제목 `h2` "팀 나가기", 설명 "나가면 이 팀의 메모를 볼 수 없습니다. 쓴 메모는 팀에 남습니다. 다시 들어오려면 초대를 받아야 합니다.") > `CardContent`)

- `Button variant="destructive"` "팀 나가기", `self-start`(좁은 폭에서는 `w-full sm:w-auto`). → 확인 대화상자 C.
- 내가 마지막 소유자: 버튼 비활성 + 버튼 위 `type-label text-muted-foreground` 글자, 버튼에 `aria-describedby` 로 연결.
  - 다른 멤버가 있음: "마지막 소유자라 나갈 수 없습니다. 다른 멤버를 소유자로 바꾼 뒤 나가세요."
  - 나 혼자: "팀에 나 혼자라 나갈 수 없습니다. 팀 삭제는 아직 지원하지 않습니다."
- 비활성 버튼은 초점을 받지 않으므로 이유를 툴팁이 아니라 보이는 글자로 둔다.

#### 3.3.2 팀 · member 가 보는 모양 (읽기 전용)

- 초대하기 카드·대기 중인 초대 카드가 없다(Q4).
- 멤버 카드: 설명 "초대와 역할 변경은 소유자만 합니다.", 관리 칸이 없다(머리·칸 모두 그리지 않는다).
- 팀 나가기 카드: 있다(마지막 소유자 문제는 member 에게 생기지 않는다).
- 이 화면의 주요(남색) 버튼은 없다.

#### 3.3.3 개인 조직이 보는 모양

하위 메뉴 아래에 카드 하나(메모의 빈 상태 견본과 같은 모양):

```
[카드]       (👥 아이콘, size-10 rounded-lg bg-muted text-muted-foreground, aria-hidden)
        개인 조직에는 멤버를 초대할 수 없습니다       ← type-body font-semibold
     팀을 만들어 초대하세요. 팀의 메모는 멤버 모두가 함께 봅니다.  ← type-label text-muted-foreground
                  [새 팀 만들기]                  ← 기본 버튼 → /teams/new
```

- 아이콘 `UsersIcon`. 멤버 표·나가기 카드는 없다(개인 조직은 나갈 수 없다, 스펙 5).

#### 3.3.4 확인 대화상자 (메모 삭제 대화상자와 같은 모양: `showCloseButton={false}`, 진행 중 닫히지 않음, 오류는 `role="alert"`)

확인을 두는 기준: **잃는 것이 있고, 되돌리려면 다른 사람이 다시 해 줘야 하는 동작**. 내보내기·나가기·자기 강등이 해당하고, 초대 취소·초대 거절·다른 사람의 역할 변경은 해당하지 않는다.

이메일 대소문자는 서버가 소문자로 바꾼다. 화면은 입력 중에 글자를 바꾸지 않는다.

#### 3.3.6 상태표

| 상태 | 언제 | 보이는 것 | 사용자가 할 수 있는 것 |
|---|---|---|---|
| 로딩 | 화면을 읽는 중(`loading.tsx`) | 진짜 글자 제목 "설정" + 하위 메뉴 + 카드 3개 뼈대(머리 줄, 표 줄 3개), `role="status"` "멤버를 불러오는 중…", `motion-reduce:animate-none` | 기다리기, 하위 메뉴로 이동 |
| 팀 · owner | 내가 owner | 초대하기, 멤버(관리 칸), 대기 중인 초대, 팀 나가기 | 초대, 역할 변경, 내보내기, 다시 초대, 초대 취소, 나가기 |
| 팀 · member | 내가 member | 멤버(관리 칸 없음), 팀 나가기 | 나가기 |
| 개인 조직 | `isPersonal` | 빈 상태 카드, "새 팀 만들기" | `/teams/new` 로 이동 |
| 멤버 나 혼자 | 팀에 나(owner)만 | 멤버 표 1줄, 팀 나가기 비활성 + "팀에 나 혼자라…" | 초대 |
| 초대 제출 중 | "초대" 누름 | "초대 중…", 버튼 비활성, 입력칸 읽기 전용 | 기다리기 |
| 초대 성공 | 서버 성공 | 토스트, 이메일 칸 비움·초점, 대기 목록에 새 줄 | 다음 초대 |
| 초대 오류 | 3.3.5 | 칸 또는 폼 아래 오류 | 고치고 다시 |
| 대기 없음 | 초대 0개 | "대기 중인 초대가 없습니다." | — |
| 만료된 초대 | 기한 지남 | 기한 칸 "만료됨"(좁으면 아래 줄) | 다시 초대, 초대 취소 |
| 역할 저장 중 | 메뉴에서 고름 | 그 줄 관리 버튼 비활성 | 기다리기 |
| 역할 저장 실패 | 서버 거절 | `toast.error` 문구(3.3.4 표), 권한이 바뀌었으면 새로 그림 | 다시 |
| 마지막 소유자 | owner 가 나 하나 | 내 줄 "멤버" 항목 비활성 + 이유, 팀 나가기 비활성 + 이유 | 다른 멤버를 소유자로 바꾸기 |
| 확인 대화상자 | 내보내기·나가기·자기 강등 | 3.3.4 | 확인, 취소, Esc |
| 권한이 바뀜 | 보는 사이 member 로 강등 | 다음 동작이 실패 → 문구 + 화면 새로 그림 → member 모양 | — |
| 내보내짐 | 보는 사이 내보내짐 | 다음 동작이 실패 → 새로 그리면 404 | 처음 화면으로 |
| 로그인 전 | 세션 없음 | 앱 틀 안내(화면은 `/account` 로) | 로그인 |
| 권한 없음 | 멤버가 아닌 조직 | 404 | — |
| 긴 텍스트 | 긴 이름·이메일 | 표 칸에서 한 줄 말줄임 + `title`. 대화상자 안에서는 `wrap-anywhere` 로 끝까지 | — |
| 많은 데이터 | 멤버·초대 수십 명 | 표가 길어진다(페이지 나눔 없음) | 스크롤 |

#### 3.3.7 반응형

| 폭 | 단 폭 | 배치 |
|---|---|---|
| 375 | 343 | 초대 폼 세로(이메일 → 역할 → 전폭 버튼). 멤버 표: 멤버 칸 ≈ 343−80−56 = 207px(아바타 뺀 글자 ≈ 160px). 초대 표: 역할·기한 칸 숨김, 이메일 아래 줄에 "역할 · 기한". 나가기 버튼 전폭 |
| 768 | 464 | 초대 폼 세로(카드 안 416 < `@lg` 512). 초대 표 역할·기한 칸 숨김(카드 464 < 512) |
| 1280 | 960 | 초대 폼 한 줄. 초대 표 역할·기한 칸 보임 |

#### 3.3.8 접근성

- 제목 계층: `h1` 설정 → `h2` 초대하기·멤버·대기 중인 초대·팀 나가기(카드 제목). 표는 `aria-labelledby` 로 카드 제목을 가리킨다.
- 관리 버튼 이름에 대상을 넣는다("홍길동 관리", "lee@example.com 초대 관리").
- 역할 항목은 `menuitemradio` 라 지금 역할이 "선택됨"으로 읽힌다(부품 기본).
- 비활성 버튼과 이유 글자는 `aria-describedby` 로 잇는다.
- 성공·실패 알림은 sonner 토스트(읽어 준다). 폼·대화상자 오류는 `role="alert"`.
- 대화상자: 처음 초점은 "취소"(DOM 첫 버튼, 메모 견본과 같다). 닫히면 연 버튼으로 돌아가고, 줄이 사라진 경우만 카드 제목으로 보낸다.

### 3.4 `/teams/new` — 팀 만들기

#### 틀: 인증 틀 (추천)

#### 레이아웃

```
AuthFrame
  새 팀 만들기                                    ← AuthHeader title
  팀을 만들어 멤버를 초대하고 메모를 함께 씁니다. 개인 조직은 그대로 남습니다.
  팀 이름   [________________]
  주소 이름 [________________]
           소문자·숫자·하이픈 3~32자입니다. 팀 주소는 /design-team 이 됩니다. 만든 뒤에는 바꿀 수 없습니다.
  [            팀 만들기            ]            ← Button w-full
                 취소                            ← AccountLink → /dashboard, text-center type-label
```

| 칸 | 부품 | 규칙(화면 검증은 편의, 서버가 다시 본다) |
|---|---|---|
| 팀 이름 | `Input id="team-name" autoComplete="off"` | 앞뒤 공백 빼고 1자 이상. 최대 길이는 Q2 (정해지기 전 초안: 40자, 표시 이름과 같게) |
| 주소 이름 | `Input id="team-slug" autoComplete="off" autoCapitalize="none" autoCorrect="off" spellCheck={false}` | 소문자·숫자·하이픈 3~32자, 예약어 금지, 중복 금지(스펙 4.3·5) |
| 안내 | `FieldDescription id="team-slug-hint"`, 입력칸 `aria-describedby` | 입력한 slug 를 `<code className="font-mono">` 로 넣는다. 비었으면 "팀 주소는 /주소-이름 이 됩니다" 부분을 뺀다 |

- 주소 이름을 팀 이름에서 자동으로 채우지 않는다(가장 단순한 안. 한글 이름은 옮길 수 없다).
- 대문자·공백을 몰래 고치지 않는다. 오류로 알린다(메모 폼이 글을 몰래 자르지 않는 것과 같은 원칙).
- 제출 중 입력칸 `readOnly`, 버튼 "만드는 중…".

### 3.5 `/invitations` — 받은 초대

#### 틀: 인증 틀 (3.4 와 같은 이유). 파일 `web/app/invitations/page.tsx`.

#### 레이아웃

```
AuthFrame
  받은 초대                                         ← AuthHeader title
  me@example.com 으로 받은 초대입니다.                ← 설명: 지금 로그인한 이메일
  ──────────────────────────────────────          ← ul: border-y border-border divide-y divide-border
  디자인팀                                          ← h2 type-heading, wrap-anywhere
  홍길동 님이 멤버로 초대했습니다.                       ← type-label text-muted-foreground
  2026. 10. 21.까지                                 ← <time> type-caption text-muted-foreground
  [수락] [거절]                                      ← Button size="sm": outline / ghost
  ──────────────────────────────────────
  마케팅                                            ← 만료된 초대
  김철수 님이 소유자로 초대했습니다.
  만료됨 · 만료된 초대는 수락할 수 없습니다. 다시 초대해 달라고 하세요.
  [수락(비활성)] [거절]
  ──────────────────────────────────────
                대시보드로 돌아가기                    ← AccountLink → /dashboard
```

- 인증 틀은 카드를 쓰지 않으므로 목록은 가는 선(`border-y` + `divide-y`)으로만 나눈다. 줄 안쪽 여백 `py-4`, 줄 안 간격 `gap-1`, 버튼 줄 위 `mt-3 flex gap-2`.
- 버튼: "수락"은 `outline`, "거절"은 `ghost`, 둘 다 `sm`(32px). 줄마다 같은 버튼이 되풀이되므로 남색 주요 버튼을 쓰지 않는다(주요 버튼은 화면에 하나).
- 순서: 만료 전 초대(기한 가까운 순) → 만료된 초대.
- 초대한 사람: 표시 이름, 없으면 이메일. 읽을 수 없으면 "알 수 없는 사람"(Q3).

#### 동작

| 동작 | 진행 중 | 성공 | 실패 |
|---|---|---|---|
| 수락 | 그 줄 두 버튼 비활성, "수락 중…" | `/<slug>/dashboard` 로 이동, 토스트 "<팀 이름>에 들어왔습니다" | 줄 안 `role="alert"` `type-label text-destructive` 문구(아래) |
| 거절 | 그 줄 두 버튼 비활성, "거절 중…" | 줄이 사라진다. 토스트 "<팀 이름> 초대를 거절했습니다". 초점 → 다음 줄의 "수락", 없으면 빈 상태 문단(`tabIndex={-1}`) | 줄 안 오류 |

거절에는 확인 대화상자를 두지 않는다(잃는 것이 없다. 3.3.4 기준).

줄 안 오류 문구(초안): 만료 "초대가 만료됐습니다. 초대한 사람에게 다시 초대해 달라고 하세요." / 이미 멤버 — 실패로 보지 않고 그 조직으로 이동 / 로그인 풀림 "로그인이 풀렸습니다. 다시 로그인하세요." / 그 밖 "처리하지 못했습니다. 잠시 뒤 다시 시도해 주세요."

#### 상태표

| 상태 | 언제 | 보이는 것 | 사용자가 할 수 있는 것 |
|---|---|---|---|
| 로딩 | 읽는 중(`loading.tsx`) | 진짜 글자 제목 "받은 초대" + 줄 2개 뼈대, `role="status"` "받은 초대를 불러오는 중…" | 기다리기 |
| 목록 | 초대 1개 이상 | 줄마다 조직·초대한 사람·역할·기한·버튼 | 수락, 거절 |
| 만료 포함 | 기한 지난 초대 | "만료됨" + 안내, 수락 비활성(`aria-describedby` 로 안내와 연결) | 거절(목록에서 치우기) |
| 비어 있음 | 0개 | 선 없이 가운데 정렬: `MailIcon` 상자(메모 빈 상태 모양) + "받은 초대가 없습니다" / "초대는 me@example.com 으로 받아야 여기에 보입니다. 다른 이메일로 초대받았다면 그 계정으로 로그인하세요." | 대시보드로 돌아가기 |
| 수락 중·거절 중 | 버튼 누름 | 위 표 | 기다리기 |
| 오류 | 서버 거절 | 줄 안 오류 | 다시, 거절 |
| 로그인 전 | 세션 없음 | "로그인이 필요합니다" 안내(3.4 와 같다) | 로그인 |
| DB 없음·프로필 없음 | — | 3.4 와 같다 | — |
| 긴 텍스트 | 긴 조직 이름·이메일 | 핵심 정보라 말줄임하지 않고 `wrap-anywhere` 로 줄을 바꾼다 | — |

#### 반응형

세 폭 모두 400px 이하 한 단. 375 에서 줄 폭 343px, 버튼 둘(각 ~60px)이 한 줄에 든다.

#### 접근성

- `h1` "받은 초대", 줄마다 조직 이름 `h2`. 목록은 `ul`.
- 버튼 이름에 대상을 넣는다: "수락"·"거절" 뒤에 `<span class="sr-only"> 디자인팀 초대</span>`.
- 기한은 `<time dateTime>`.

### 3.6 대시보드·메모 (조직 단위)

#### 설명·제목 문구 (초안)

| 자리 | 개인 조직 | 팀 조직 |
|---|---|---|
| 대시보드 설명 | "내 메모가 얼마나 쌓였는지 한눈에 봅니다." (지금과 같다) | "<팀 이름>의 메모가 얼마나 쌓였는지 한눈에 봅니다." |
| 대시보드 빈 상태 둘째 줄 | "첫 메모를 쓰면 통계와 차트가 채워집니다." | "첫 메모를 쓰면 팀 멤버 모두에게 보입니다." |
| 메모 설명 | "나만 볼 수 있는 메모입니다. 최신순으로 50개까지 보여 줍니다." | "<팀 이름>의 멤버가 모두 보는 메모입니다. 최신순으로 50개까지 보여 줍니다." |
| 메모 목록 카드 제목 | "내 메모" | "팀 메모" |
| 메모 빈 상태 둘째 줄 | "새 메모 입력칸에 첫 메모를 적어 보세요." | "새 메모 입력칸에 첫 메모를 적어 보세요. 팀 멤버 모두에게 보입니다." |

`loading.tsx` 의 제목·설명도 같은 글자여야 하는데, 뼈대는 조직을 모른다. 뼈대에는 제목만 진짜 글자로 두고 설명은 뼈대(`Skeleton h-5.5 w-72 max-w-full`)로 바꾼다.

#### 작성자를 보여 줄지: 팀에서만 보인다 (추천)

여러 사람이 쓰는 목록에서 누가 썼는지 모르면 삭제 버튼이 왜 어떤 줄에만 있는지 알 수 없다. 개인 조직은 늘 나라서 보이지 않는다.

- 작성자 이름: 표시 이름, 없으면 이메일 @ 앞부분(앱 틀과 같은 규칙). 내 메모도 내 이름으로 보인다(따로 "나"로 바꾸지 않는다 — 가장 단순한 안).
- 작성자가 비었거나(계정 삭제, `on delete set null`) 읽을 수 없으면(팀을 떠난 사람): "떠난 멤버"(Q6).
- **메모 목록**: 시각 줄을 `작성자 · 시각 [삭제]` 로. 작성자 `min-w-0 truncate type-caption text-muted-foreground`, 가운뎃점 `aria-hidden`, 시각 `shrink-0`.
- **대시보드 최근 메모 표**: 칸을 더하지 않는다. 메모 칸 본문 아래 둘째 줄에 작성자를 적는다 — 640px 이상은 "작성자"(시각은 지금처럼 오른쪽 칸), 미만은 "작성자 · 시각". 칸을 더하면 768px(단 464px)에서 본문 칸이 100px 남짓으로 줄어서다.

#### 삭제 버튼: 작성자와 owner 에게만 보인다 (추천)

- 조건은 서버가 줄마다 계산해 넘긴다(예: `canDelete`). 화면은 판단하지 않는다.
- 권한 없는 줄은 버튼을 **숨긴다**(비활성으로 두지 않는다 — 이유를 말할 자리가 없는 비활성 아이콘은 혼란만 준다).
- 숨긴 것은 화면 요구일 뿐이고, 삭제 권한은 DB 정책이 강제한다(스펙 4.2).
- owner 가 남의 메모를 지울 때 대화상자 설명에 한 문장을 더한다: "삭제한 메모는 되돌릴 수 없습니다. <작성자> 님이 쓴 메모입니다."
- 서버가 거절한 경우(그새 권한이 바뀜): 대화상자 안 오류 "이 메모를 삭제할 권한이 없습니다. 화면을 새로 고칩니다." + 새로 그림. 지금 삭제 결과(`deleted`·`signed-out`)로는 이 경우를 알 수 없다(Q7).

#### 상태표 (바뀌는 것만)

| 상태 | 언제 | 보이는 것 | 사용자가 할 수 있는 것 |
|---|---|---|---|
| 개인 조직 | `isPersonal` | 지금 화면과 같다(작성자 없음, 삭제 버튼 모든 줄) | 지금과 같다 |
| 팀 · 내 메모 | 작성자가 나 | 작성자(내 이름)·시각·삭제 버튼 | 삭제 |
| 팀 · 남의 메모, 나는 member | — | 작성자·시각, 삭제 버튼 없음 | 읽기 |
| 팀 · 남의 메모, 나는 owner | — | 작성자·시각·삭제 버튼 | 삭제(대화상자에 작성자 문장) |
| 떠난 작성자 | 작성자 비었거나 읽을 수 없음 | "떠난 멤버" | owner 만 삭제 |
| 삭제 거절 | 서버 거절 | 대화상자 안 오류 + 새로 그림 | 닫기 |
| 긴 작성자 이름 | — | 한 줄 말줄임, 시각·버튼은 줄지 않는다 | — |
| 권한 없음 | 멤버가 아닌 조직 | 404 | — |

#### 반응형

지금과 같다. 375 에서 메모 줄의 메타 줄: 작성자(말줄임) · 시각 · 삭제 버튼(32px).

#### 접근성

- 메타 줄을 `작성자 <time>` 순으로 읽는다. 삭제 버튼 이름은 지금처럼 "삭제".
- 작성자 이름은 링크가 아니다(프로필 화면이 없다).

### 5.1 제안 — Select (승인 필요)

초대 폼의 역할 칸에 고르기 칸이 필요하다. 지금 부품에 없다.

1. **shadcn `select` 를 넣는다 (추천).** 설치된 `@base-ui/react` 에 select 가 있어 새 패키지가 붙지 않는다. 폼 칸이라 라벨 연결·키보드·react-hook-form 연결이 자연스럽다. 넣은 뒤 `design-system` 스킬의 다섯 가지 확인을 한다. 크기 기준: 트리거 40px(입력칸과 같다)·`rounded-lg`·글자는 좁은 폭 16px / `md` 14px(입력칸과 같다), 팝업 `rounded-lg`·항목 32px·`--available-height` 안에서 스크롤.
2. shadcn `radio-group` 을 넣는다. 둘뿐이라 한눈에 보이지만 한 줄 배치(1280)에서 폭을 더 쓴다.
3. 넣지 않고 `DropdownMenu` + `DropdownMenuRadioGroup` 을 폼 칸처럼 쓴다. 메뉴는 동작용이라 라벨 연결·값 제출을 손으로 이어야 한다(비추천).

두 번 이상 쓰이는가: 지금은 이 폼 하나다. 1번을 고르면 그 점을 감수하는 것이고, 감수하지 않으려면 3번이다.

### 5.2 제안 — 설정 하위 메뉴 모양 (승인 필요, 설치 없음)

- Tabs 부품은 넣지 않는다. 같은 화면 안에서 패널을 바꾸는 ARIA 탭이라 경로 이동에 맞지 않는다.
- 대신 화면 전용 `SettingsNav`(링크 줄 + 밑줄 막대, 3.2)를 설정 두 화면이 쓴다. 저장소에 없던 모양(밑줄 탭)이라 승인을 받고, 승인되면 `design-system` 스킬 "웹 틀" 절에 견본 경로를 한 줄 더한다.

### 5.3 넣지 않는 것

- Badge: 역할·개인/팀·만료를 모두 글자로 보인다(기본 디자인 스펙 4.3 에서 쓰는 화면이 없어 넣지 않기로 한 것과 같다).
- AlertDialog: 확인은 기존 `Dialog` 로 한다(메모 삭제 견본과 같다).
- 새 토큰: 없다.

### 5.4 구현 메모

- 새 경로는 `web/e2e/responsive.spec.ts` 의 목록에 더한다: `/teams/new`, `/invitations`, 그리고 로그인 없이 여는 `/<임의 slug>/dashboard` 등(앱 틀 안내를 잰다).
- `AppPage` 설명에 팀 이름이 들어간다. 공백 없는 긴 영문 이름이 넘치지 않게 설명 `p` 에 `wrap-anywhere` 를 더하거나 팀 이름 길이를 묶는다(Q2).

## 6. 열린 질문

스펙이 정하지 않았거나, 정한 것과 화면이 부딪히는 곳이다. 괄호 안은 이 문서가 임시로 둔 기본값이다.

1. **Q1 개인 조직의 `name`**: 전환기·메뉴에 그대로 나온다. 표시 이름? 이메일 앞부분? 표시 이름을 바꾸면 따라 바뀌나? (기본: `name` 을 그대로 보이고 둘째 줄에 "개인")
2. **Q2 팀 이름 규칙**: 스펙은 slug 규칙만 정했다. 최대 길이·공백 처리는? (기본: 앞뒤 공백 빼고 1~40자)
3. **Q3 수락 전에 조직 이름·초대한 사람을 읽을 수 있나**: 조직 밖 사람은 조직을 못 읽고(완료 정의 1), profiles 는 팀원끼리만 읽는다(4.2). `/invitations` 에 둘 다 보이려면 초대받은 사람용 정책이나 함수가 필요하다. (기본: 보인다고 보고 설계, 못 읽으면 "알 수 없는 사람")
4. **Q4 member 가 대기 중인 초대를 보나**: 스펙은 초대 "하기"만 owner 로 정했다. (기본: member 에게 숨긴다)
5. **Q5 거절 = 초대 행 삭제인가**: 초대받은 사람이 자기 초대 행을 지울 정책이 필요하다. 만료된 초대를 치우는 것도 같다.
6. **Q6 떠난 작성자 표시**: 계정이 지워졌거나 팀을 떠난 사람의 profiles 는 읽을 수 없다. (기본: "떠난 멤버")
7. **Q7 서버 결과 모양**: (a) 메모 삭제가 0행(권한 없음)이면 지금 결과로는 성공처럼 보인다 — `forbidden` 같은 상태가 필요하다. (b) slug 중복 `invalid` 에 어느 칸인지(`field`)를 둘까. (c) 다시 초대가 "새 초대"와 "기한 연장"을 구분해 주나. (d) 역할 변경·내보내기·나가기·초대가 "마지막 소유자"·"권한 없음"을 구분해 주나.
8. **Q8 `/teams/new`·`/invitations` 의 틀**: 인증 틀(추천, 3.4) 로 확정할지. "취소"·"돌아가기"는 `/dashboard`(개인 조직)로 가는데, 직전 조직으로 돌아가게 할지(`?from=<slug>` 등).
9. **Q9 `/[slug]` 만 친 주소**: 경로 표에 없다. (기본: `/[slug]/dashboard` 로 보낸다)
10. **Q10 앱 틀의 제품 로고**: 전환기가 로고 자리를 차지하면 앱 틀에서 로고가 빠진다. `design-system` 스킬의 "로고는 마케팅 틀과 앱 틀이 같이 쓴다" 문장을 고칠지, 로고 마크를 전환기 옆에 남길지. (기본: 빠진다)
11. **Q11 계정 탭의 "역할" 줄**: 그대로 옮기면 "역할: 회원/운영자"가 조직 역할(소유자/멤버)과 헷갈린다. 라벨을 "계정 종류"로 바꿀지.
12. **Q12 혼자 남은 팀**: 소유자 1명뿐인 팀은 나갈 수도 지울 수도 없다(조직 삭제는 비목표). 안내 문구만 둘지. (기본: "팀에 나 혼자라 나갈 수 없습니다. 팀 삭제는 아직 지원하지 않습니다.")
13. **Q13 초대 알림 수단**: 메일이 없으니 초대한 사람이 알려야 한다. 대기 목록에 `/invitations` 주소 복사 버튼을 둘지. (기본: 두지 않고 안내 문장만)
14. **Q14 역할 표기**: "소유자"·"멤버"로 확정할지(영어 `owner`·`member` 그대로 둘지).
