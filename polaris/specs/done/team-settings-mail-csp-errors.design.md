## 2. 흐름

### F1. 팀 이름 바꾸기 (팀 · owner)

1. 사이드바 "설정" → 하위 메뉴 "팀"(`/<slug>/settings/team`).
2. "팀 이름" 칸을 고치고 → "저장".
   - 성공: 토스트 "팀 이름을 저장했습니다". 화면이 다시 그려져 사이드바 조직 전환기·위 막대·설명 줄이 새 이름이 된다. 주소는 그대로다.
   - 입력 오류: 칸 아래 오류. 입력값은 남는다.
   - 권한 없음(그새 member 가 됨·정지됨): 오류 토스트, 화면을 새로 그리면 member 모양이 된다.

### F2. 팀 지우기 (팀 · owner)

1. 팀 탭 맨 아래 "팀 삭제" 구역 → "팀 삭제" 버튼 → 확인 대화상자.
2. 지워지는 것을 읽고, 팀 이름을 그대로 입력 → "팀 삭제".
   - 이름이 틀림: 칸 오류, 초점이 입력칸으로 돌아간다. 서버를 부르지 않는다.
   - 성공: 개인 조직 대시보드(`/<개인 slug>/dashboard`)로 간다. 토스트 "팀을 지웠습니다". 전환기 목록에서 팀이 빠진다.
   - 취소·Esc: 대화상자가 닫히고 초점이 "팀 삭제" 버튼으로 돌아온다. 아무것도 바뀌지 않는다.
3. 같은 팀의 다른 멤버는 다음 요청에서 404 화면을 본다(스펙 5, 내보내졌을 때와 같다).

### F3. member 가 팀 탭을 본다

하위 메뉴 "팀" → 팀 이름과 주소를 읽기만 한다. 고치는 칸·지우는 버튼이 없다.

### F4. 초대 → 메일 결과 알림 (팀 · owner)

멤버 탭의 초대 폼 "초대" 또는 대기 중인 초대 줄의 "다시 초대" → 서버가 초대를 저장하고 메일을 보낸다(최대 약 10초 기다림) → 결과(새 초대·다시 초대) × 메일(보냄·설정 없음·실패)에 맞는 토스트(3.4).
메일이 실패해도 초대는 저장돼 있다. 대기 중인 초대 목록에 줄이 생기거나 기한이 바뀐다.

### F5. 권한 밖 주소

- 개인 조직 주소의 `/<개인 slug>/settings/team`: 404 화면(`notFound()`). 개인 조직에는 이 탭이 없으므로 "없는 화면"으로 다룬다.
- 멤버가 아닌 조직·없는 slug·지워진 팀: 지금처럼 `requireWorkspace` 가 404.
- 로그인 전: 앱 틀의 "로그인이 필요합니다" 안내(지금과 같다).

## 3. 화면별 명세

### 3.1 설정 하위 메뉴(`SettingsNav`)에 "팀" 탭

```
설정
<설명>
 계정    멤버    팀                ← nav aria-label="설정 메뉴"
───────────────━━━━──────────────  ← 지금 화면 아래 2px 막대
```

| 항목 | 값 |
|---|---|
| 주소 | `/<slug>/settings/team` |
| 탭 이름 | "팀" |
| 순서 | 계정 · 멤버 · **팀** (맨 끝에 덧붙인다) |
| 보이는 조건 | 지금 조직이 팀일 때(`current.isPersonal === false`). owner·member 모두 보인다. 개인 조직에서는 링크를 그리지 않는다 |
| 모양 | 기존 링크와 같다. 새 클래스 없음 |

- 맨 끝에 두는 이유: 개인 조직(계정 · 멤버)과 팀(계정 · 멤버 · 팀)에서 "멤버" 탭의 자리가 같아진다. 팀 설정은 자주 쓰지 않는 동작이다.
- `SettingsNav` 에 prop 을 하나 더한다(제안: `isTeam: boolean`). 계정·멤버·팀 세 화면이 모두 `workspace.current.isPersonal` 로 넘긴다.
- 320px 에서 세 링크(약 115px)는 넘치지 않는다.
- 계정·멤버 화면의 `loading.tsx` 는 주소를 몰라 탭 뼈대를 둘로 둔다. 팀 조직에서 셋으로 바뀌는 것은 받아들인다(고치지 않는다).

### 3.2 `/[slug]/settings/team` — 팀 설정

#### 목적
owner: 팀 이름을 바꾸고 팀을 지운다. member: 팀 이름과 주소를 확인한다.

#### 공통 머리

- `AppPage title="설정"`, 설명은 아래 표. 문서 제목(`metadata.title`) "팀".
- 본문 첫 자식은 계정 화면과 같은 묶음이다: `<div>` 안에 `SettingsNav`("팀" 선택) + `<div className="@container"><div className="divide-y divide-border">` 구역들.
- 구역은 계정 화면의 `SettingsSection` 을 쓴다. 이제 두 화면이 쓰므로 `settings/page.tsx` 안의 함수를 `settings/settings-section.tsx` 로 옮겨 함께 쓴다(모양은 그대로, 디자인 시스템 부품이 아니라 설정 화면 전용).
- 데이터는 `requireWorkspace` 가 주는 `current { id, name, slug, myRole, isPersonal }` 와 `orgs`(개인 조직 slug)뿐이다. 새로 읽는 것은 없다. `current.isPersonal` 이면 `notFound()`.

| 보는 사람 | 설명(초안) |
|---|---|
| 팀 owner | "<팀 이름>의 이름을 바꾸거나 팀을 지웁니다." |
| 팀 member | "<팀 이름>의 정보입니다. 이름 바꾸기와 삭제는 소유자만 합니다." |

#### 3.2.1 owner 가 보는 모양

**구역 A "팀 이름"** — `SettingsSection id="settings-team-name" title="팀 이름" description="사이드바와 초대 메일에 보이는 이름입니다."`

| 요소 | 부품·속성 | 규칙 |
|---|---|---|
| 칸 | `Field` + `FieldLabel htmlFor="team-name"` "팀 이름" + `Input id="team-name" autoComplete="off"` | 기본값은 지금 팀 이름. 제출 중 `readOnly`(초점을 지킨다). `aria-invalid`, `aria-describedby="team-name-hint"` |
| 안내 | `FieldDescription id="team-name-hint"` | "40자까지 씁니다. 팀 주소(<code className="font-mono">/seed-team</code>)는 바뀌지 않습니다." — 주소는 지금 slug |
| 칸 오류 | `FieldError errors={[errors.name]}` | 아래 오류 표 |
| 폼 오류 | `<p role="alert" className="type-label text-destructive">` | 아래 오류 표 |
| 저장 | `Button type="submit"` 기본(남색), `self-start` | 이 화면의 유일한 주요 버튼. 제출 중 "저장 중…" + 비활성 |

- 검증은 팀 만들기와 같은 zod 규칙: `trim()` → 1자 이상 "팀 이름을 입력하세요", 40자 이하 "팀 이름은 40자 이하입니다". 공백을 몰래 고치지 않는다(앞뒤 공백만 떼고 보낸다).
- 이름을 바꾸지 않고 눌러도 그대로 저장한다(표시 이름 폼과 같다. "바뀐 것 없음" 상태를 따로 두지 않는다).
- 성공하면 `form.reset({ name: <저장한 이름> })` 으로 칸을 정리된 이름에 맞춘다. 서버 함수가 `refresh()` 해서 앱 틀과 설명 줄이 새 이름이 된다. 초점은 "저장" 버튼에 그대로 둔다.

**구역 B "팀 삭제"** — `SettingsSection id="settings-team-delete" title="팀 삭제" description="팀과 그 안의 작업·활동 기록·초대를 바로 지웁니다. 되돌릴 수 없습니다."`

- `Button variant="destructive"` "팀 삭제", `w-full sm:w-auto sm:self-start`("회원 탈퇴"와 같다). 누르면 확인 대화상자(3.2.3)가 열린다. 열 때마다 칸·오류를 비운다.
- 구역에 빨간 테두리·바탕을 따로 두지 않는다. 계정 화면의 "회원 탈퇴" 구역과 같은 모양으로, 위험은 맨 아래 자리·버튼 색·설명 글로 알린다.

#### 3.2.2 member 가 보는 모양 (읽기 전용)

```
팀 이름                      │ 팀 이름   시드 팀
팀 이름은 소유자만 바꿉니다.     │ 주소      /seed-team
```

- 구역 하나: `SettingsSection id="settings-team-name" title="팀 이름" description="팀 이름은 소유자만 바꿉니다."`.
- 내용은 계정 화면 프로필의 `dl` 격자와 같다: `grid grid-cols-[auto_minmax(0,1fr)] gap-x-4 gap-y-2 type-body`.
  - `dt` "팀 이름"(`text-muted-foreground`) / `dd`(`text-foreground wrap-anywhere`) — 40자 이름도 잘리지 않고 줄을 바꾼다.
  - `dt` "주소" / `dd` `<code className="font-mono">/seed-team</code>`.
- "팀 삭제" 구역·입력칸·버튼이 없다. 이 화면에 주요(남색) 버튼이 없다.

#### 3.2.3 팀 삭제 확인 대화상자

"회원 탈퇴" 대화상자와 같은 짜임이다: `DialogContent showCloseButton={false}`, 안에 `<form noValidate className="grid gap-4">`, 진행 중에는 닫히지 않는다(`onOpenChange` 에서 `isPending` 이면 무시).

```
팀을 지울까요?                                  ← DialogTitle
지우면 바로 사라지고 되돌릴 수 없습니다.             ← DialogDescription
 • 팀의 모든 작업과 활동 기록                      ← ul list-disc pl-5, type-body text-muted-foreground
 • 모든 멤버의 멤버십과 대기 중인 초대
멤버 모두 이 팀을 더 볼 수 없습니다. 멤버의 계정과 개인 공간은 그대로 남습니다.
┌──────────────────────────────┐
│ 시드 팀                       │                ← rounded-lg bg-muted px-4 py-3 type-label wrap-anywhere
│ /seed-team                   │                   이름 font-medium text-foreground, 주소 text-muted-foreground
└──────────────────────────────┘
확인하려면 위 팀 이름을 그대로 입력해 주세요          ← FieldLabel htmlFor="delete-team-confirm"
[__________________________]
(오류)                                          ← FieldError
(서버 오류)                                      ← p role="alert"
────────────────────────────────
                       [취소] [팀 삭제]          ← DialogFooter: outline / destructive
```

| 요소 | 규칙 |
|---|---|
| 이름 상자 | 멤버 내보내기 대화상자의 대상 상자와 같은 모양. 이름이 길어도 `wrap-anywhere` 로 끝까지 보인다. 같은 이름의 팀이 여럿이어도 주소로 가린다 |
| 입력칸 | `Input id="delete-team-confirm" name="confirm" autoComplete="off" autoCapitalize="off" autoCorrect="off" spellCheck={false}`, 진행 중 `readOnly`, `aria-invalid`. 붙여넣기를 막지 않는다 |
| 맞는지 보기 | 누를 때 `입력값.trim() === 지금 팀 이름`. 대소문자·가운데 공백은 그대로 비교한다. 휴대폰 자동 입력이 끝에 붙이는 공백 때문에 실패하지 않게 앞뒤 공백만 뗀다(열린 질문 Q2) |
| "팀 삭제" 버튼 | **꺼 두지 않는다**("회원 탈퇴"와 같다, 열린 질문 Q1). 틀리면 칸 오류 "팀 이름이 맞지 않습니다. 위 이름을 그대로 입력해 주세요" + 초점을 입력칸으로. 서버를 부르지 않는다 |
| 진행 중 | 버튼 "지우는 중…", 두 버튼 비활성, 입력칸 `readOnly`, Esc·바깥 누름으로 닫히지 않는다 |
| 처음 초점 | 입력칸(대화상자 안 첫 입력 요소, "회원 탈퇴"에서 확인한 동작). 내용이 넘치는 낮은 화면에서는 부품 기본대로 대화상자 자체 |

결과별 동작(서버 결과 이름은 도메인이 정한다. 아래는 뜻으로 맞춘다):

| 결과 | 화면 |
|---|---|
| 지움 | `toast.success("팀을 지웠습니다")` → `router.replace(<개인 대시보드>)` → `router.refresh()`. 이동할 때까지 대화상자는 진행 중 모양으로 둔다(회원 탈퇴와 같다) |
| 이름이 다름(서버 확인) | 칸 오류(위와 같은 문구) + 초점을 입력칸으로 + `router.refresh()`(그새 이름이 바뀌었으면 상자와 라벨이 새 이름이 된다) |
| 권한 없음(member 가 됨·정지·이미 지워짐) | 대화상자를 닫고 `toast.error("소유자만 팀을 지울 수 있습니다. 화면을 새로 고칩니다.")` + `router.refresh()`. 새로 그리면 이 구역이 사라지거나(member) 404 라서 대화상자 안 오류는 남지 않으므로 토스트로 알린다 |
| 로그인 풀림 | 대화상자 안 `role="alert"` "로그인이 풀렸습니다. 다시 로그인하세요." |
| 개인 조직(화면에서는 생기지 않음)·예외 | 대화상자 안 `role="alert"` "팀을 지우지 못했습니다. 잠시 뒤 다시 시도해 주세요." |

- 개인 대시보드 주소: `orgs.find((org) => org.isPersonal)` 의 `/<slug>/dashboard`. 없으면 `/dashboard`(옛 주소 — 개인 조직 대시보드로 보낸다).
- 지운 뒤 토스트에 팀 이름을 넣지 않는다. 이름 뒤 조사(을/를)가 이름에 따라 달라지고, 방금 이름을 직접 입력했다(열린 질문 Q3).

#### 3.2.7 접근성

- 제목 계층: `h1` "설정" → `h2` "팀 이름"·"팀 삭제"(구역 제목, `section aria-labelledby`). 대화상자 제목은 Base UI 가 `aria-labelledby` 로 잇는다.
- 하위 메뉴: `nav aria-label="설정 메뉴"`, 지금 링크 `aria-current="page"`.
- 입력칸마다 보이는 라벨(`FieldLabel htmlFor`). 안내는 `aria-describedby`, 오류는 `aria-invalid` + `FieldError`(`role="alert"`). 서버 오류도 `role="alert"`.
- 제출 중에는 `disabled` 대신 `readOnly` 로 칸의 초점을 지킨다. 버튼만 비활성.
- 키보드: Tab 순서는 하위 메뉴 → 팀 이름 칸 → 저장 → 팀 삭제. 대화상자 안은 입력칸 → 취소 → 팀 삭제. 입력칸에서 Enter 는 제출이다. Esc 는 닫기(진행 중 제외).
- 초점 이동: 대화상자를 닫으면 "팀 삭제" 버튼으로 돌아온다(부품 기본). 삭제 성공 뒤에는 새 화면의 처음부터. 이름 오류는 입력칸으로.
- 초점 표시: 버튼·입력칸·링크 모두 `focus-visible:ring-3 focus-visible:ring-ring/50`(부품 기본, 문장 속 링크도 같은 클래스).
- 알림: 성공·실패 토스트는 sonner 의 알림 영역이 읽어 준다. 경고 토스트(3.4)는 아이콘만이 아니라 글로 "보내지 못했습니다"라고 말한다.
- 명도 대비: 기존 토큰 짝만 쓴다(`foreground`·`muted-foreground`·`destructive` on `background`/`muted`/`popover`). 새 색 없음.
- 움직임: 뼈대 `motion-reduce:animate-none`. 대화상자 열고 닫기는 부품 기본(100ms 페이드).

### 3.4 초대 결과 토스트 (6가지)

서버 결과 `invited`(새 초대)·`renewed`(같은 이메일의 초대가 있어 기한을 7일 늘림)에 메일 결과(보냄·설정 없음·실패)가 붙는다(스펙 3.4). 화면은 두 값만 보고 아래 표대로 띄운다. 초대 폼과 대기 중인 초대의 "다시 초대"가 같은 함수를 쓴다(제안: `members/messages.ts` 의 `showInviteToast(email, result)`).

| 결과 | 메일 | 토스트 | 문구(초안) |
|---|---|---|---|
| 새 초대 | 보냄 | `toast.success` | "<이메일>을 초대하고 초대 메일을 보냈습니다" |
| 새 초대 | 설정 없음 | `toast.success` | "<이메일>을 초대했습니다. 초대받은 사람에게 직접 알려 주세요." (지금 문구 그대로) |
| 새 초대 | 실패 | `toast.warning`, `duration: 10000` | "<이메일>을 초대했지만 메일을 보내지 못했습니다. 초대받은 사람에게 직접 알려 주세요." |
| 다시 초대 | 보냄 | `toast.success` | "<이메일>의 초대 기한을 7일 늘리고 메일을 다시 보냈습니다" |
| 다시 초대 | 설정 없음 | `toast.success` | "<이메일>의 초대 기한을 7일 늘렸습니다. 초대받은 사람에게 직접 알려 주세요." |
| 다시 초대 | 실패 | `toast.warning`, `duration: 10000` | "<이메일>의 초대 기한을 7일 늘렸지만 메일을 보내지 못했습니다. 초대받은 사람에게 직접 알려 주세요." |

- `<이메일>` 은 서버가 저장한 소문자 글자다(폼은 지금처럼 `trim().toLowerCase()`, 표는 줄의 이메일).
- 마침표: 한 문장이면 붙이지 않고, 두 문장이면 붙인다(기존 토스트의 관례). 지금 폼과 표가 "기한을 7일 늘렸습니다" 뒤 마침표를 다르게 쓰던 것을 이 표로 맞춘다.
- 실패를 `warning` 으로 두는 이유: 초대는 됐으니 오류(`error`)가 아니고, 해야 할 일이 남았으니 성공과 구분한다. 아이콘은 `Toaster` 에 이미 있는 `TriangleAlertIcon` 이고 색은 다른 토스트와 같다(새 토큰 없음). 메일 실패는 이 토스트 말고 남는 곳이 없어 10초로 늘린다. 마우스를 올리거나 알림 영역에 초점을 두면 멈춘다(sonner 기본).
- 보내는 동안: 서버가 메일을 최대 약 10초 기다린다. 폼은 지금처럼 "초대 중…"(버튼 비활성, 칸 읽기 전용), 표는 그 줄의 관리 버튼이 비활성이다. 새 표시를 더하지 않는다.
- 실패한 초대(입력 오류·권한 없음·로그인 풀림)는 메일을 보내지 않으므로 지금 문구 그대로다.

## 4. 접근성 체크 항목 (QA 기준)

1. 팀 조직의 설정 세 화면에 "팀" 링크가 있고, 팀 화면에서 그 링크만 `aria-current="page"` 다. 개인 조직에는 "팀" 링크가 없다.
2. 팀 화면의 `h1` 은 "설정" 하나, 구역 제목은 `h2`.
3. "팀 이름" 칸은 라벨 이름 "팀 이름"으로 찾힌다. 오류가 나면 `aria-invalid="true"` 이고 오류 글이 `role="alert"` 로 읽힌다.
4. 저장 중 칸에 초점이 남아 있다(`readOnly`).
5. 대화상자를 열면 초점이 확인 입력칸에 있고(라벨 "확인하려면 위 팀 이름을 그대로 입력해 주세요"), 닫으면 "팀 삭제" 버튼으로 돌아온다.
6. 틀린 이름으로 제출하면 서버를 부르지 않고 칸 오류를 보이며 초점이 입력칸에 있다.
7. 진행 중에는 Esc·바깥 누름·"취소"로 닫히지 않는다.
8. 모든 버튼·링크·칸에 보이는 초점 링이 있다. 키보드만으로 이름 저장과 팀 삭제를 끝낼 수 있다.
9. 320·375·768·1280px 에서 가로 넘침이 없다. 40자 팀 이름에서도 같다.

## 6. 화면 요구와 서버 요구

| 화면 요구(보인다·숨긴다) | 서버 요구(못 한다) |
|---|---|
| 개인 조직에 "팀" 탭이 없고 주소를 열면 404 | 개인 조직 id 로 부르면 `personal-org` 로 거절 |
| member 에게 이름 칸·삭제 버튼이 없다 | member·조직 밖·운영자·정지된 사람의 이름 바꾸기·지우기는 0행 → `forbidden` (DB 정책) |
| 확인 칸에 팀 이름을 입력해야 지운다 | 서버도 입력한 이름이 지금 이름과 같은지 다시 본다 |
| 이름 칸의 1~40자 검사 | 도메인 zod + DB 제약이 다시 본다 |
| 메일 결과에 맞는 토스트 | 메일 실패가 초대를 되돌리지 않는다. 결과에 메일 결과가 붙는다 |

## 7. 열린 질문

> 2026-10-15 결론: Q1~Q5 는 모두 추천안으로 구현했다. Q6 의 이름은 도메인 타입(`renamed`·`deleted`·`invalid`·`forbidden`·`personal-org`·`signed-out`, 메일 `sent`·`not-configured`·`failed`)을 따른다. [작성자 판단]

- **Q1. 삭제 확인 버튼을 꺼 둘까?** 작업 지시는 "팀 이름을 입력해야 켜지는" 대화상자였다. 이 문서는 1번을 추천한다.
  1. (추천) 꺼 두지 않는다. 틀리면 칸 오류 + 초점 복귀. "회원 탈퇴"와 같은 규칙이라 이웃한 두 위험 동작이 같게 움직이고, 비활성 버튼이 초점을 못 받아 이유를 알 수 없는 문제가 없다.
  2. 이름이 맞을 때만 켠다(`disabled={입력값.trim() !== 팀 이름 || isPending}`). 칸 오류 경로가 빠지고, 라벨이 조건을 말해 준다. 고르면 "회원 탈퇴"도 같이 바꿀지 정한다.
- **Q2. 이름 비교에서 앞뒤 공백을 뗄까?** 스펙 3.2 는 "정확히 같을 때"다. 팀 이름은 앞뒤 공백 없이 저장되므로 입력값의 앞뒤 공백만 떼고 비교하자고 제안한다(휴대폰 자동 입력 대비). 서버도 같은 규칙이어야 화면과 어긋나지 않는다 → `backend-developer` 확인.
- **Q3. 지운 뒤 토스트에 팀 이름을 넣을까?** 넣으려면 이름 끝 글자에 따라 을/를을 고르는 처리가 필요하다. 추천은 넣지 않는 것("팀을 지웠습니다").
- **Q4. 초대 폼 안내.** 1. (추천) 3.3 의 중립 문구. 2. 화면이 서버에서 메일 설정 여부를 받아 "초대 메일을 함께 보냅니다"/지금 문구를 고른다(도메인에 공개 함수가 하나 늘어난다).
- **Q5. 메일 실패 토스트.** 1. (추천) `warning` + 10초. 2. 다른 성공과 같은 `success` + 기본 시간.
- **Q6. 결과 이름.** 이름 바꾸기·지우기·메일 결과의 상태 이름은 도메인이 정한다. 이 문서는 뜻(저장함·지움·이름 다름·권한 없음·개인 조직·로그인 풀림 / 보냄·설정 없음·실패)으로만 맞췄다. 정해지면 구현 담당이 표의 이름을 그대로 쓴다.
