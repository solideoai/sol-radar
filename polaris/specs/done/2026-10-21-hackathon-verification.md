# 해커톤 검증 실행 범위

사용자 승인: 2026-10-21, 검증 축소안을 우선순위대로 구현한다.

목적은 개발 중 반복되는 전체 검증과 리허설을 줄이는 것이다. 제품 범위·보안 정책·커밋 게이트의 필수 검사·CI는 유지한다.

사용자 추가 지시(2026-10-21): 실행 횟수뿐 아니라 과도한 시험도 실제 삭제한다. 웹 6,830개를 286개, AI 1,511개를 101개, 결정 서버 152개를 57개로 축소하고 DB는 핵심 21개를 남긴다. 중복 계층·전수 오류 조합·상수/목업 고정·템플릿 CRUD·확장 회귀는 제거한다. 핵심 보안·점수·모델 장애·데모 흐름은 보존하고 기존 명령이 남은 시험을 모두 발견하도록 한다. `skip`·탐색 제외로 숨기지 않는다. 삭제와 보존 정본은 `docs/evidence/verification/20261021-pruned-tests.json`이다.

- 개발 중 `pnpm verify:changed`로 HEAD 대비 작업 폴더 변경(스테이징·미스테이징·새 파일)을 검사한다. 커밋된 브랜치 변경은 `--base <기준 커밋>`으로 포함한다.
- 검사 범위는 `verify.config.json`의 `changedPaths` 정규식으로 정한다. 웹 변경은 웹 quick 검사, Python 변경은 해당 서비스 검사, DB·seed·루트 도구 변경은 공통 검사 중 관련 검사를 실행한다. 문서만 바뀌면 실행할 코드 검사가 없다고 보고한다.
- 분류되지 않은 코드 변경은 전체 quick 검사로 넓힌다. Git 조회·기준 커밋·설정 오류를 성공으로 취급하지 않는다. 이름 변경의 이전·새 경로와 삭제도 포함한다.
- `--dry-run`은 변경 경로와 실행할 명령을 JSON으로 출력한다. 실제 실행은 첫 실패에서 멈추고 검사별 시간을 보여 준다.
- 전체 `pnpm verify`는 통합 직전과 제출 전 최종 코드에서 한 번 실행한다. 같은 코드·검사 입력·환경의 성공 결과는 중복 실행하지 않는다. 변경된 입력에 의존하는 검사는 다시 실행한다.
- Compose 기동은 인프라·환경변수 계약·의존성·컨테이너 진입점 변경 때와 통합/제출 리허설에 실행한다. 일반 화면·문구 변경마다 기동하지 않는다.
- 개발 중 E2E는 변경한 흐름을 선택한다. `test:e2e`에 포함된 브라우저 검사를 별도로 반복하지 않는다. 기능 검사는 1440 중심, 1280은 변경 화면의 배치·넘침을 확인한다. 데모 전에는 두 폭의 대표 흐름을 확인한다.
- 작은 작업은 같은 에이전트가 구현·관련 검증한다. 독립 리뷰는 통합 단위로 모은다. 새 테스트는 계산·권한·저장·외부 입력 계약·실제 결함 회귀에 집중한다.
- RLS·조직 격리·골든 94/72/68·정보 부족 처리·모델 장애·DEMO 표시·사람 결정 저장 검증은 유지한다. 실행하지 않은 검사를 통과로 보고하지 않는다.

완료 기준: 범위 선택·Git 변경 수집·오류 처리·실패 즉시 중단 시험, 기존 게이트 자기 보호 시험과 전체 verify가 통과하고 운영 지침이 위 정책과 일치한다.
